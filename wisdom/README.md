# wisdom · 智慧之书知识库

条件论知识图谱的集成仓库。灵枢（白箱智能）的知识之书——学科识别卡、理论、验证记录都在这。

## 目录结构

```
wisdom/
├── engine/                    # 智慧之书引擎（随包分发/运行）
│   ├── wisdom_book.py         # 条件论图谱核心（26+ 学科识别卡）
│   ├── wisdom_cloud.py        # 云端 REST 服务（POST /dex/query）
│   └── wisdom_ui.html         # 网页界面
└── knowledge/                 # 知识库（子智能体验证后落这里）
    ├── 识别卡/                # 每学科一个 md（识别卡 2.0 格式）
    │   ├── 自我增强回路.md     # 例：学科识别卡（pending/verified）
    │   └── ...               # 每学科一个文件，几十 KB 级
    ├── 理论/                  # 学科理论文档（智能论3.2 等完整理论）
    └── 验证记录/              # 子智能体验证轨迹（P37 双子管线）
        ├── 写手草稿/          # 写手子智能体产出的草稿
        ├── 验证者判定/        # 验证者独立复核结果
        └── 编排者修正/        # 修正后定稿
```

## 知识如何进库（P37 双子管线 · 规模化）

大量子智能体并行验证知识，每个学科的产出是一个文本 md：

```
写手子智能体 → 生成识别卡 2.0 草稿（JSON → md）
    → 验证者子智能体 → 独立复核（三闸门 + 格式 + 协议一致性 + 边界诚实）
    → 编排者 → 修正后定稿
    → 落库：wisdom/knowledge/识别卡/<学科名>.md
    → 状态：pending（设计者终裁后 → verified）
```

**关键原则**：
- 子智能体的产出是**文本 md**（几十 KB/学科），不是数据库 dump——验证轨迹留在 GitHub（可审计）
- 识别卡状态：`pending`（验证通过待终裁）→ `verified`（设计者终裁）
- 每次验证有记录（写手草稿/验证者判定/编排者修正全留档）

## 存储分层（10GB 就绪）

| 层 | 位置 | 放什么 |
|---|---|---|
| 权威源 | 本仓库 `wisdom/knowledge/` | 文本级知识（md，<100MB 健康线） |
| 分发源 | GitHub Releases / 对象存储 | 大体积快照（10GB 打包，将来） |
| 运行态 | 灵枢本地 SQLite | 播种后的检索态（离线可用） |

- 知识按学科分文件（天然可增量）
- 验证产出是文本（天然可审计）
- 大块二进制/非文本才走 Releases/对象存储

## 子智能体协作规范

- 每个学科识别卡 = 一个独立 md 文件 = 一个验证单元
- 验证标准：三闸门（①唯一机制 ②可观测判据 ③测试用例）+ 格式合法性 + 条件空间完整 + 协议一致性 + 边界诚实
- 条件论铁律：只声明条件化有效性，不声称真理性
- 贡献：验证通过的知识 → 提交本仓库 → 可审计可追溯
