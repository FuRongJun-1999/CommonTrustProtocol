# protocol-compiler 调用缺陷四例 · 实测报告（2026-08-28）

> 来源：T9-2b 编译器域 token 对照实验（灵枢 × dsh 双端）压力测试发现。
> 定位方法：最小形态对比法——逐变体 dump 字节码，每条附最小复现程序
> 与编译输出证据。已按 dsh 端先例（「当循环」bug）在实验任务中规避，
> 本报告供 protocol-compiler 修复反哺。

## 缺陷一 · 多参数函数调用被字符串化

**复现**：
```
定义 加（甲，乙）：返回 甲 加 乙；结果 = 加（2，3）；止。
```
**现象**：编译 ok=True，但 `结果 = 加（2，3）` 编译为
`PUSH_CONST '加（2'` ——调用被当成**字符串常量**，`，3）` 部分丢失。
**对照**：单参数调用 `阶乘（5）` 正常编译为 `CALL (1, ['n'])`。
**影响**：任何多参数函数调用（`，` 分隔）静默产出错误字节码。
**疑点**：词法/解析层对「名（参数1，参数2）」的调用形态未实现
（定义侧 `parser.py:523` 支持多参数——定义与调用不对称）。

## 缺陷二 · 嵌套调用被字符串化

**复现**：
```
定义 加一（甲）：返回 甲 加 1；定义 倍（甲）：返回 甲 加 甲；
结果 = 加一（倍（3））；止。
```
**现象**：`加一（倍（3））` 编译为 `PUSH_CONST '加一（倍（3））'`
（整串字符串化），函数体本身编译正常。
**影响**：调用作为另一调用的参数（函数组合）静默产出错误字节码。

## 缺陷三 · 若则体 + 非递归调用 → 参数未声明

**复现**：
```
定义 加一（甲）：若 甲 小于 0，则 返回 甲，否则 返回 甲 加 1；
中间 = 加一（3）；结果 = 中间；止。
```
**现象**：编译 ok，VM 运行 `NameError: 名实不符：'甲' 未声明`。
**对照（关键）**：同形态但函数体含**递归自调用**的程序
（阶乘/汉诺）参数绑定正常。
**疑点**：主程序→函数的 CALL 参数绑定路径，与函数体内自调用
的绑定路径行为不一致（疑与函数收集顺序/作用域快照时机有关）。

## 缺陷四 · 多函数定义执行错乱

**复现**：缺陷三程序同款（两个连续 `定义`）。
**现象**：字节码 dump 显示第一个函数定义的 `JUMP` 跳转目标与
函数体边界错位（多函数时函数体区间计算异常），执行流在函数
定义区与主程序区间之间错乱。
**影响**：多函数程序（即使每个函数单独正确）整体执行失败。

## 汇总

| # | 缺陷 | 静默/显式 | 规避方式 |
|---|---|---|---|
| 1 | 多参数调用字符串化 | **静默**（编译 ok 字节码错）| 单参数化 |
| 2 | 嵌套调用字符串化 | **静默** | 中间变量展开 |
| 3 | 若则体非递归调用参数丢失 | 显式（VM NameError）| 递归自调用形态 |
| 4 | 多函数定义执行错乱 | 显式（执行错乱）| 单函数程序 |

**最危险的是缺陷 1/2 的静默性**：编译 ok=True 但字节码已是错的——
违背白箱「编译通过=结构正确」的承诺。建议在编译期对「名字（」形态
做调用解析，解析失败即编译错误（显式失败优于静默错误）。

## 已验证可用的形态（实验任务据此设计）

- 纯算术主程序（优先级正确：`3 加 4 乘 2` = 11 ✓）
- 单参数函数 + 若则条件 + 递归自调用（阶乘 120 / 汉诺 7 / 斐波那契 8 ✓）
- 直接返回体单函数 + 中间变量调用 ✓
