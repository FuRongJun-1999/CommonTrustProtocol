# CodeGraph 定位与内部审查计划（2026-08-17）

> 爸爸定调：codegraph 作为**身体（工具）的一部分**接入灵枢，
> **但不依赖它**（D-005 降级原则：不可用返回空，系统照常工作）；
> 且需要**对它的代码进行内部审查、优化、验证、总结**——
> 它既是工具（身体延伸），也是被审查对象（外部知识）。

## 一、定位：身体工具

```
灵枢（大脑/认知）
  ├── 智慧之书（知识图谱·脊椎）
  ├── 记忆/预测/盲区（海马体等）
  └── 身体工具层（MCP 工具）
        ├── CodeGraph（代码显微镜·可选）
        └── 其他工具（弹幕/OCR/搜索…）
```

- **身体**：工具是能力的延伸（像手/眼），codegraph 给灵枢「看代码结构」的能力
- **不依赖**：D-005——codegraph 不可用时降级（返回空/走其他路径），
  不阻塞核心功能；知识图谱（智慧之书）永远不把 codegraph 当唯一依据
- **工具进不了知识核心**：codegraph 输出的是「结构事实」（输入），
  要成为知识必须过我们的管线（校验/终裁）——和任何外部输入一样

## 二、为什么审查它（内部审查/优化/验证/总结）

codegraph 是外部代码，不是可信基底。按条件论，对它：
1. **审查**：架构/实现是否符合声明的能力；有无盲区/错误
2. **优化**：识别可借鉴的模式（四件套已做过）；识别我们可增强的点
3. **验证**：它的输出（结构事实）用我们的方式核验（测试用例执行）
4. **总结**：把它的架构规律提炼成我们的知识（模式卡），
   不复制代码，复制「规律」（现象规律性即知识）

## 三、审查框架（条件论视角）

| 审查维度 | 问什么 |
|---|---|
| 架构规律 | 它的核心机制是什么（tree-sitter→图→MCP）？在什么条件下成立？|
| 条件边界 | 它的图/工具在什么场景失效？（大仓库/动态语言/构建期代码）|
| 可借鉴模式 | 哪些模式值得知识卡化（已做四件套）；哪些是我们独有的 |
| 风险点 | 语法层 vs 语义层的盲区；静态索引的腐坏 |
| 校准接口 | 如何作为物理基底校准源（测试用例执行器）|

## 四、审查范围（分批）

- **第一批（架构层）**：codegraph-core（图模型）、codegraph-server（MCP）、
  codegraph-memory（持久记忆）、codegraph-harness（集成）——提取机制规律
- **第二批（语言层抽查）**：python/rust/typescript 三个 crate——验证解析能力
- **第三批（总结）**：可借鉴模式清单 + 独特优势确认 + 接入设计

## 五、产出

- 审查报告（codegraph 架构规律/条件边界/风险/可借鉴）
- 模式卡（条件化知识：codegraph 的机制在什么条件下成立）
- 接入设计（测试用例执行器消费 codegraph MCP，物理基底校准代码侧）
- 降级保障（不依赖：D-005）
