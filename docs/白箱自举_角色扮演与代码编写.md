## 一、理论：角色扮演与代码编写都是「条件化知识问答」

第一阶段用户洞察：「角色扮演=带条件的知识问答，条件=当前角色」——已验证（v1.29 角色条件路由 6/6）。
**第二阶段延伸：代码编写同样是条件化知识问答**——条件=编程任务需求，知识=编程规律片段。

| 场景 | 条件 | 知识单元 | 生成 |
|---|---|---|---|
| 角色扮演 | 角色×场景×情绪 | 角色条件单元（身份/住处/性格…） | 角色化回答 |
| 代码编写 | 任务需求×语言×算法 | 代码条件单元（排序/遍历/分支…） | 代码片段 |

两条主线共用第一阶段沉淀的同一套机制：**条件化单元 + 方向推理 + 组合生成 + 自校验 + 固化 + LLM 外部对照**。

## 二、角色扮演主线（条件=角色）

### 2.1 角色条件单元（ROLE_UNITS，类比 CONDITION_UNITS）

```python
ROLE_UNITS = {
  "鲸鱼娘": {
    "conditions": ["身份", "住处", "食物", "特征", "性格", "习惯"],
    "units": {
      "身份": {"rule": "鲸鱼娘——一条住在深海的会说话的鲸鱼", "direction": "身份"},
      "住处": {"rule": "深海，大海是家，从海面到海沟都是地盘", "direction": "住处"},
      "食物": {"rule": "磷虾和小鱼、浮游生物", "direction": "食物"},
      ...
    },
  },
}
```

### 2.2 角色×场景组合生成（第二阶段核心）

- 现有（v1.29）：ROLE_CLUSTERS 触发词查表直答——「你是谁」→ 角色直答
- 升级：**组合引擎接入角色**——角色条件单元 × 场景事实（今天天气/心情/用户状态）→ 组合生成角色化回答
  - 「今天天气不错」→ 场景(天气)×角色(鲸鱼娘性格) → 「海面亮晶晶的，我浮上去晒太阳」
  - 「你心情好吗」→ 情绪(心情)×角色 → 角色化心情回答
- 逆转操作 → **OOC 检测**：生成与角色设定矛盾 → 标记 OOC（如「我是人类」vs 角色=鲸鱼 → 逆转检测）
- 固化：角色化回答生成→自校验（角色一致性）→固化→直答（多角色扩展时复用）

### 2.3 多角色扩展

- 角色卡 → 角色条件单元（build_role_clusters 模式扩展）
- 新增角色：鲸鱼娘之外（如 猫娘/学者/小丑）——角色条件单元独立，防污染（v1.29 纪律保持）

## 三、代码编写主线（条件=编程任务）

### 3.1 代码条件单元（CODE_UNITS：编程规律片段）

```python
CODE_UNITS = {
  "冒泡排序": {
    "conditions": ["数组", "升序"],
    "pattern": "def bubble_sort(arr):\n    n = len(arr)\n    for i in range(n):\n        for j in range(n-1-i):\n            if arr[j] > arr[j+1]:\n                arr[j], arr[j+1] = arr[j+1], arr[j]\n    return arr",
    "direction": "排序",
    "verify": "语法检查 + 样例运行",   # 自校验：py_compile + 断言
  },
  "数组去重": {"direction": "去重", "pattern": "...", "verify": "..."},
  "计数":     {"direction": "计数", "pattern": "...", "verify": "..."},
  ...
}
```

### 3.2 组合生成代码（枚举→验证→生成 范式扩展到代码）

- 第一阶段 ARC 原型已有：枚举原语 → 训练样例验证 → 生成规律（5/5）
- 升级：**代码组合生成**——任务需求（排序/去重/计数/查找）→ 匹配代码单元 → 组合参数（数组名/升降序/语言）→ 生成代码 + 自校验
- **自校验（自举核心）**：语法检查（py_compile/ast.parse）+ 样例测试运行（输入→期望输出断言）→ 白箱自己发现代码错误
- 生成泛化：同一代码单元 × 不同参数 → 不同实例（冒泡排序×[3,1,2] / [5,4,3]）
- 固化：验证通过的代码 → 固化 → 下次同任务直接直出

### 3.3 代码自校验层次

| 层次 | 检查 | 自发现 |
|---|---|---|
| L1 语法 | py_compile / ast.parse | 语法错误 |
| L2 样例 | 输入→期望输出断言运行 | 逻辑错误 |
| L3 边界 | 空数组/单元素/重复元素 | 边界 bug |

## 四、判定标准（第二阶段）

| 主线 | 指标 | 目标 |
|---|---|---|
| 角色扮演 | 白箱命中率（零 LLM 角色化） | ≥80% |
| 代码编写 | 组合生成代码测试通过率 | ≥80% |
| 代码编写 | 自校验发现错误率（含故意 bug 代码） | 100% |
| 双主线 | 固化闭环（生成→自校验→固化→直答/直出） | 成立 |

## 五、闭环（⑤）

- 角色扮演：角色单元组合生成 → 角色一致性自校验 → 角色语录固化 → 直答（零 LLM）
- 代码编写：代码单元组合生成 → 语法/测试自校验 → 代码固化 → 直出（零 LLM）
- 两条主线均达成白箱自举闭环，LLM 仅外部对照（偶尔抽检）

## 六、实施顺序（迭代路线）

1. **角色扮演原型**：组合引擎接入角色（ROLE_UNITS + 角色×场景组合生成 + 角色一致性自校验）
2. **角色固化+多角色**：鲸鱼娘语录固化 → 新增第二角色（验证防污染）
3. **代码原型**：CODE_UNITS（排序/去重/计数）+ 组合生成 + 语法/样例自校验
4. **代码固化**：验证通过代码固化 → 同任务直出
5. **判定+闭环**：双主线达标 → LLM 降级外部对照
