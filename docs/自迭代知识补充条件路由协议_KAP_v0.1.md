# 自迭代知识补充条件路由协议（KAP v0.1 · Knowledge Auto-Patch Protocol）

> 状态：设计稿（荣 2026-08-26：自迭代的知识补充过程也要加上条件路由图的规范）
> 背景：v1.39 F-SPEC 暴露 25 题 F6 失败 → 手工补知识。此后**补知识这个动作本身
> 必须走条件路由图**——不再是「发现缺什么就写什么」，而是按四要素协议化：
> 条件分析 → 路由 → 补知识（四要素注释）→ 验证 → 回归。

## 0. 问题：补知识为什么也要条件路由图

- 补知识是**对知识库的修改**——错误补充 = 新的错误知识（如「变质」kp 抢答
  「冰箱保鲜」——补了错误的生效条件导致跨题误配）
- 手工补知识不可审计（补了什么/为什么补/验证了吗）
- 自迭代（LLM/自动补卡）更需要闸门——否则自主进化覆盖 REVERSE_DAILY 成
  整卡的退化会重演（559 键污染教训）

## 1. 补知识协议（对齐条件路由图五步）

```
知识缺口（F-SPEC 失败 / 对话 miss / 验证拒绝）
  → ① 条件分析：缺什么知识（keys 未命中）→ 学科域 → 问题类型
  → ② 路由：目标位置（现有 kp 补 / 新建 kp / 翻译键）
  → ③ 补知识：写四要素注释（生效条件/子功能/执行/不适用条件）
  → ④ 验证：graph_retrieve 命中正确卡 + chat 回答含 keys
  → ⑤ 回归：F-SPEC 全量重评（不误伤其他题）+ 提交
```

### 1.1 每个补充的知识必须带四要素注释（KCCS）

```json
{
  "name": "饭后不宜剧烈运动（小学科学）",
  "生效条件": ["问饭后运动", "问消化"],
  "子功能": ["消化需血液", "剧烈运动抢血"],
  "执行": "饭后血液集中消化系统，剧烈运动导致消化不良",
  "不适用条件": ["问运动补水", "问饭前洗手"]
}
```

**不适用条件尤其关键**——补知识时若不给负路由，新 kp 会抢答相邻问题
（「变质」kp 无负路由 → 抢答「冰箱保鲜」）。对齐 CCG 能力级互斥。

### 1.2 验证闸门（补完必须过）

| 闸门 | 检查 | 失败处理 |
|---|---|---|
| 命中闸 | graph_retrieve(问题) top1 = 新 kp | 修正生效条件 |
| 内容闸 | chat(问题) reply 含全部 keys | 补 content 表述 |
| 负路由闸 | 相邻题不被新 kp 抢答 | 补不适用条件 |
| 回归闸 | F-SPEC 全量无新增失败 | 回滚/修正 |

## 2. 分类处理（v1.40 实例）

| 类 | 判定 | 处理 | 实例 |
|---|---|---|---|
| A 表述差异 | 答对但 keys 字面未命中 | 补 content 含 keys 表述 | 细胞补「基本单位」、分数补「分子分母」、加减法补「1+1=2」 |
| B 知识缺口 | 无对应知识 | 新建 kp（四要素注释） | 饭后运动、开水、GIL、信任、记忆 |
| C 路由误配 | 有知识但答错卡 | 补不适用条件/修正生效条件 | 变质 kp 抢答冰箱保鲜 → 补冰箱生效条件到正确位置 |

## 3. 防退化（对齐 consolidate 教训）

- 补知识写入 **state_attributes.comment**（KCCS 结构化），不覆盖 REVERSE_DAILY
  字面量（整卡污染根因——559 键被自主进化覆盖）
- 新建 kp 一律带 `status:verified` + 四要素注释
- 每次补充记 **knowledge_patch 日志**（时间/缺口/补了什么/验证结果）
- F-SPEC 回归是硬闸门：全量不过 → 回滚

## 4. 工具落地

- `gen_kp_comments.py`：批量生成器（v1.39 已用）
- `knowledge_fix_A.py` / `knowledge_fix_B.py`：A/B 类补全脚本（v1.40）
- `verify_full_comments.py`：13 题端到端验证
- F-SPEC 全量：回归闸门
