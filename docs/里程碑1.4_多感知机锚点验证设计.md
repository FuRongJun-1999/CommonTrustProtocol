# 里程碑 1.4 设计：多感知机锚点验证

> 状态：设计 v1.0（2026-08-29）· 用户洞察扩展
> 核心（荣）：**一个事物不能只有视觉一个层面的信息**——还有交互（触觉）、
> 声音（听觉）、其他交互来实现感知。3D 锚点验证 = **多感知机协同验证**。

---

## 〇、为什么不止视觉

> **单一通道 = 自证陷阱**（v3.4 理论）：视觉证据完美自洽（蜡苹果看起来完全像），
> 但内部一致性 ≠ 外部真实性。3D 锚点若只靠视觉多视角确认，永远无法区分
> "像椅子"与"是椅子"——需要**独立于视觉的通道**打破自证闭环。

**对应 v3.4**：这是「多重一致性（Multi-Consistency）」的落地——候选在证据/概率/
导数/图四维一致 + 多通道独立证据一致才确认。

---

## 一、多感知机通道（已具备的基础）

| 通道 | 设备 | 感知层面 | 3D 锚点验证作用 |
|---|---|---|---|
| visual（视觉）| screen/see | 形状/颜色/位置 | 多视角几何一致（弱验证）|
| tactile（触觉）| control/交互 | 硬度/温度/重量 | 接触确认（强验证：摸到就是真的）|
| audio（听觉）| audio | 声音/材质回声 | 敲击声/环境声（独立证据）|
| action（行动）| device_call/run_command | 操作反馈 | 物理裁决（强验证：推/拿/移动）|
| prediction（预测）| predict_routes | 未来状态 | 预测验证（预期 vs 实际）|

> 通道可信度注册表（channel_credibility.py）已定义这 6 通道——
> 每个通道有独立的历史命中率（Beta 后验）。

## 二、锚点验证的通道协同

### 2.1 验证流程（多通道证据 → 锚点确认）

```
3D 锚点（视觉三角化产出）
  │
  ├─ 视觉多视角一致（弱验证·visual）→ 锚点置信度 ↑
  ├─ 触觉接触确认（强验证·tactile）→ 锚点确认度 ↑↑（"摸到就是真的"）
  ├─ 听觉证据（独立·audio）→ 锚点确认度 ↑（"敲击声符合椅子材质"）
  ├─ 行动验证（强验证·action）→ 锚点确认度 ↑↑（"推了一下，纹丝不动=固定"）
  ├─ 预测验证（prediction）→ 锚点确认度 ↑（"预测它在，确实在"）
  └─ 关系验证（图·相邻/支撑）→ 矛盾检测（"杯子悬浮无支撑=可疑"）
      │
      ▼
Confirmed(锚点) ⟺ 多通道一致 ∧ 强验证命中 ∧ 稳定 ∧ 无矛盾
```

### 2.2 锚定分级（多通道的强弱区分）

| 级别 | 通道组合 | 3D 锚点例子 | 更新速率 |
|---|---|---|---|
| 弱验证 | visual 多视角 / 图关系 | 多视角投影一致 | α=0.95 慢 |
| 强验证 | tactile 接触 / action 行动 / audio 物理声 | 摸到/推到/敲到 | α=0.7 快 |

## 三、实现设计

### 3.1 锚点验证记录（provenance 扩展）

```python
锚点 = {
  category, center, size,
  provenance: ["visual@view1", "tactile@contact", "action@push"],  # 多通道来源
  channel_evidence: {"visual": 0.9, "tactile": 0.8, "action": 0.7},  # 各通道证据
  confirmation: "ACCEPT_weak" | "ACCEPT_strong" | "ACCEPT_stable",
  verified_at, TTL,  # stable 租约
}
```

### 3.2 新增能力

1. **add_channel_evidence(anchor_id, channel, evidence)**：记录某通道对锚点的验证
2. **verify_anchor(anchor_id)**：聚合多通道证据 → 确认度判定（复用 confirmation.py）
3. **channel_conflict_detect()**：多通道矛盾检测（视觉说椅子，触觉说箱子 → 冲突降级）
4. **MCP world3d 新增 verify 动作**：查询锚点确认状态 + 提交通道证据

### 3.3 与既有组件复用

| 组件 | 复用点 |
|---|---|
| channel_credibility.py | 6 通道可信度（visual/tactile/audio/action/prediction/search）|
| anchored_verification.py | 弱/强分级（tactile/action → 强）|
| confirmation.py | 完全确认四条件 + ACCEPT 分层 |
| stable_lease.py | 锚点 TTL 租约（过期降级）|
| semantic_anchor_graph.py | 锚点节点 + 关系边（矛盾检测）|

## 四、验证示例（椅子锚点）

```
1. 视觉：2 视角三角化 → 位置 (0,1,5) conf=0.6 → ACCEPT_weak（疑似）
2. 触觉：device_call 接触该点 → "有实体" → tactile 证据 0.8 → 升级
3. 行动：run_command 推 → 纹丝不动 → action 证据 0.9 → ACCEPT_strong
4. 听觉：敲击 → "木质声" → audio 证据 0.7 → 多通道一致
5. 稳定：多次观测一致 → stable_rounds ≥ 5 → ACCEPT_stable（确认）
6. 三个月后：TTL 过期 → 降级 weak 重新验证（防"门把手松动"）
```
