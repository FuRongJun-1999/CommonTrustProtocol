# 灵枢 · 信息分层处理方案（v1.16）

## 一、背景

当前灵枢的 `wisdom_chat` 是所有消息直接走智慧之书（chat_engine）：
- 能处理的（情感/闲聊/知识/诚实）→ 自回答
- 处理不了的（诚实边界）→ 说「没把握」就结束

问题：智慧之书是 5.71MB 结构图谱，覆盖有限。复杂推理、开放问题、
图谱外知识（如「帮我规划一次旅行」「解释一下相对论和量子力学的争论」）
接不住——但这些不该是「没把握」的终点，而应该交给更强的 LLM。

爸爸指示：**信息分层处理**——
1. 入口先做语义识别（判断类型：简单知识查询/判断/情感/复杂/无法判断）
2. 简单知识查询/判断/情感 → 智慧之书优先自处理
3. 无法完成的 → 走 LLM
4. 无法判断的内容 → 智慧之书先给出自身回答，把回答放入上下文给 LLM 续答

## 二、架构

```
输入 message
   │
   ▼
① 语义识别分流（chat_engine.chat 已内建）
   ├─ 情感检测（emotion）        ─┐
   ├─ 闲聊（chitchat）            │
   ├─ 记忆询问（memory_reply）    ├─→ 智慧之书自处理（route=self）
   ├─ 自省（self_reflexive）      │
   ├─ 转折（turn）                ─┘
   ├─ 知识检索（hits 高置信）     ─→ 智慧之书自处理（route=self）
   ├─ 诚实边界（honest 无命中）   ─┐
   └─ 知识检索（hits 低置信）     ─┴→ LLM 兜底（route=llm）
                                      智慧之书回答放入上下文
   │
   ▼
② 路由决策（_decide_route）
   route=self  → 直接返回智慧之书回答（快/透明/可溯源）
   route=llm   → 调 DeepSeek API 续答
                 上下文 = 原问题 + 智慧之书初步回答
                 返回 LLM 回答（标注 route=llm, wisdom_reply 保留）
   │
   ▼
③ 返回结构化结果
   {reply, route, wisdom_reply, hits, emotion, honest, ...}
   调用方（MCP 工具/网页端）按 route 消费
```

## 三、路由判定规则

| chat() 返回特征 | route | 说明 |
|---|---|---|
| blocked | self | 内容安全拦截（不转 LLM） |
| emotion 命中 | self | 情感已共情处理 |
| chitchat / memory_reply / self_reflexive / turn | self | 闲聊/记忆/自省/转折已答 |
| hits 且 top.score ≥ 0.30 | self | 知识检索高置信命中 |
| honest=True 且无 hits | llm | 智慧之书没把握 → LLM 续答 |
| hits 但 top.score < 0.30 | llm | 低置信命中 → LLM 完善 |
| LLM 不可用（无 key/网络） | self(fallback) | 回退智慧之书回答 |

阈值 0.30 依据：实测命中分数 饿 0.72 / 串联 0.64 / 1+1 0.64 / 熵 0.38 均 ≥0.30；
低置信噪声（旧 0.009 类）远低于 0.30。

## 四、LLM 接入

- 客户端：openai 1.40.0（已装）
- API：DeepSeek（base_url=https://api.deepseek.com，model=deepseek-chat）
- Key：环境变量 DEEPSEEK_API_KEY（User 级已配置）
- 调用方式：系统提示说明「灵枢=记忆/知识图谱大脑，智慧之书已给出初步回答，
  请基于它续答/完善/纠正」，用户消息 = 原问题 + 智慧之书回答
- 失败降级：无 key / 网络错误 / 超时 → 返回智慧之书原回答（route=self_fallback）
- 成本控制：仅 route=llm 才调用；temperature=0.3；max_tokens≈300

## 五、实现位置

1. `aeis/api.py`：Agent 增加 `chat()`（分层入口）——内部调 wisdom_chat 得
   智慧之书回答 → _decide_route → 需要时 llm_complete → 返回带 route 的结构
2. 新模块 `aeis/layered.py`：`_decide_route(result)` + `llm_complete(question, wisdom_reply)`
   （独立模块，api.py 不膨胀；LLM 失败降级逻辑集中在此）
3. `aeis/mcp/server.py`：wisdom_chat 工具改为走 `agent.chat()`（分层）——
   MCP 调用方（DSH 主模型）拿到 route 字段，route=llm 时主模型可继续加工
4. 同步：site-packages（热路径）+ 2_ai\knowledge-base + CommonTrustProtocol + 1_ai/3_ai

## 八、联合判断（白箱后验校验 · 回应 Kimi 架构评审）

Kimi 评审点出：白箱应给 LLM 的回答戴条件论缰绳（LLM 生成 → 白箱校验条件合法性）。
实测验证 `dex_auto_verify` 直接校验不够——错误主张「量子纠缠可超光速通信」被
误采纳为「物理学·知识综述」工作假设（词面重叠误导 D_norm 判定）。
改用 **graph_retrieve 主张锚定**（LLM 回答在图谱的一致性检测）更可靠：

| LLM 回答 | 锚定检测 | 标注 |
|---|---|---|
| 生锈正确回答（图谱内）| anchored 初中化学 0.789 | ✓ 图谱锚定：初中化学，在E2条件下成立 |
| 旅行规划（图谱外）| unverified（0.006 噪声）| 图谱外补充：未在图谱锚定，基于通用知识 |
| 超光速错误主张 | unverified + warning | ⚠️ 条件偏差警告：与诚实边界可能冲突 |

实现：`layered.whitebox_check(dex, llm_reply)`（强锚定=score≥0.30+翻译命中；
诚实边界词命中→warning）；`route_reply` 在 LLM 续答后自动校验并在回答尾部标注，
结果附 `llm_verify` 字段。提交 cf7b170。

### 主张级升级（19f79f6 · 回应 Kimi「实体级事实核查」）
Kimi 二轮评审指出：整段打分会被词面包裹骗过（「量子纠缠可超光速」混在物理词面里）。
升级：LLM 回答**按句切分 → 逐句图谱锚定**——每句独立判定：

```
回答级: partial | warning
  [图谱外] 量子纠缠是量子力学中的一种现象
  [图谱外] ⚠️诚实边界词 它允许超光速通信，这推翻了爱因斯坦的相对论
  [✓锚定] -> 初中化学 0.656  铁生锈是铁与氧气和水发生化学反应
  [图谱外] 北京适合旅游
```

回答级汇总：全锚定→anchored / 部分→partial / 全无→unverified。
误判代价分析：正确句漏标（量子纠缠现象→图谱外）宁缺毋滥——图谱诚实原则
（无强证据不强行锚定）；越界句（超光速）必标 ⚠️。

### 诚实边界 2.0（727dc65 / d6f18fd · 回应 Kimi「词表 vs 克制条款」）
Kimi 三问「诚实边界词是硬编码词表还是识别卡动态匹配」——诚实回答：原本是
硬编码词表；Kimi 的问题催生了升级为**双通道**：

| 通道 | 机制 | 实例 |
|---|---|---|
| ① 硬编码边界词 | 已知边界快路径（超光速/外星人/能保证/你懂吗/长什么样）| 「量子纠缠允许超光速通信」→ ⚠️诚实边界词 |
| ② 识别卡 counters 动态 | 137 卡 counters 克制条款（格式不统一：克制『X』/以X替代Y/把X当作Y…），句子 vs counters 二元组交集≥4 触发 | 「信息论就是语义理论」→ ⚠️触发克制条款：把信息论当作语义理论或本体论的越界主张 |

检测候选卡 = 检索命中的卡 ∪ 句子中直接提到的知识卡名（「信息论就是…」
检索可能命中语言学而非信息论，但句子含卡名 → 仍查信息论卡 counters）。

现场演示（四句混合）：
```
[✓锚定] -> 初中化学 0.656 (E2)  铁生锈是铁与氧气和水发生化学反应
[图谱外]                         北京适合旅游，有很多景点
[图谱外] ⚠️触发克制条款          信息论就是语义理论，能解释语言的意义
[图谱外] ⚠️诚实边界词            量子纠缠允许超光速通信
```
