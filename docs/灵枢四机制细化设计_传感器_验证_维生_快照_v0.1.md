> 设计者指令 2026-08-27：这四点「得做细化设计」。
> 定位：把零散机制（验证单元/维生系统/手工备份）升级为**成体系的自修改安全闭环**。

## 〇、四机制总览（一句话）

```
信息差传感器（感知自身质量差）
  → 验证单元（交叉审问每处自修改）
  → 维生系统显示化（存活状态可视化，自修改不破坏自身）
  → 自修改自动快照纪律（改前快照，撤销永远一条命令）
```

四者构成「**自修改的安全闭环**」：感知 → 验证 → 维生 → 可回滚。

## 一、信息差传感器（借鉴 sentrux「结构健康传感器」）

### 1.1 问题

sentrux 洞见：**「没有传感器，agent 不知道自己该改进什么」**——能力 6772 不是因为做不好，是没有信号告诉它哪里差。
灵枢现状：repro_gate（正确性基准）+ 三层自校验（正确性），**缺「结构质量信号」**（非正确性，是自身结构健康度）。

### 1.2 设计

**传感器输出 = 多维结构质量信号（可量化、可对比基线）**：

| 信号 | 度量 | 数据源 |
|---|---|---|
| **路由健康度** | KCCS 注释覆盖率 / 负路由命中率 / 检索确定性（指纹稳定性）| semantic_translate + 指纹化 |
| **知识健康度** | kp 孤立率 / 卡-kp 覆盖 / 矛盾键冲突数 | lingshu.db 图统计 |
| **代码健康度** | 单元自校验通过率 / 固化成功率 / 测试回归 | code_compose + repro_gate |
| **认知健康度** | 自我认知评分 / 失调检测 / 价值迭代候选数 | cognition 管线 |
| **信息差收敛度** | D_norm 趋势 / gap_trend 斜率 | 已有 gap_trend 工具 |

**闭环**（对齐 sentrux scan→score→improve→rescan）：
```
sensor scan（全维度打分）→ save 基线（gate --save）
→ 自修改（知识/代码/锚点）
→ sensor rescan → 对比基线
→ 退化：拦截（触发维生系统）；改善：固化
```

### 1.3 关键设计点
- **基线快照**：每次自修改前保存传感器基线（`gate --save` 语义）
- **退化判据**：任何维度下降 → 该次自修改不得固化（对齐「自修改必须验证」）
- **暴露为工具**：`lingshu_sensor_report`（MCP 工具，agent 可主动查）

## 二、验证单元强化（借鉴 gbase「多臂评审」）

### 2.1 现状
- 三层自校验（L1 语法/L2 样例/L3 边界）——单臂
- 互维 mutual.js（白箱+LLM 双通道）——双臂，但未成体系

### 2.2 设计：三臂交叉审问（build / audit / judge）

```
Build（构建臂）：产生自修改（知识固化/代码单元/规则）
Audit（审计臂）：独立复核——合法性/条件一致性/不越界
Judge（裁决臂）：对照目标判通过/修订/拒绝（终裁权保留设计者）
```

- **双臂→三臂**：现有「白箱+LLM」升级为「构建+审计+裁决」三职责分离
- **交叉审问**：审计臂与构建臂**独立**（不共享中间产物），防「自己审自己」
- **证据链**：三臂各留验证轨迹 → 可审计（对齐护栏宪章）

## 三、维生系统显示化（survival 从后台到前台）

### 3.1 现状
- `survival.py`（swarm）存在，但**后台运行、不可见**
- 维生判定（自修改不破坏自身）无显式界面/报告

### 3.2 设计：维生状态可视化

```
维生系统显示化 = 把「自身存活状态」变为可观测信号：
  ├─ 心跳（heartbeat）：引擎/知识库/桥 存活状态
  ├─ 自修改影响面（impact）：一次自修改动了哪些层（知识/代码/锚点）
  ├─ 回滚能力（rollback）：快照可用性 + 撤销路径可达性
  └─ 维生判定（vitality）：自修改是否威胁自身（阻断 or 放行）
```

- **显示载体**：`lingshu_vitality_report`（MCP 工具）+ GUI 面板（对接 archify 认知图）
- **中断权序**：维生系统 > 验证单元 > 用户 > 实例（已有协议，显示化落实）
- **与传感器联动**：传感器检测到退化 → 维生系统显示「威胁自身」→ 阻断 + 建议回滚

## 四、自修改自动快照纪律（借鉴 gbase「Lifeline 预快照」）

### 4.1 现状
- 手工 `bak_20260819` 文件备份——零散、易漏、无纪律
- 固化前有部分备份（bak-整卡），但非系统性

### 4.2 设计：任何自修改前自动快照

```
自修改（知识/代码/锚点/翻译表/固化单元）前置动作：
  1. 自动快照：当前状态序列化到快照区（snapshots/<ts>/）
  2. 记录修改意图（改什么/为什么/影响面）
  3. 执行修改
  4. 验证（三臂评审）
  5. 通过 → 标记快照为「已验证」；失败 → 一键回滚到快照
```

- **快照粒度**：知识库（db/json）+ 代码（.py）+ 固化单元（code_solidified.json）+ 锚点/价值观
- **回滚命令**：`lingshu_rollback <snapshot_id>`（撤销永远一条命令）
- **与 git 结合**：代码层走 git（已有）；数据层（db/json）走快照区
- **对齐指纹化**：快照附指纹 → 回滚后指纹校验一致性

## 五、四机制闭环（完整流程）

```
一次自修改（agent 决定改进知识/代码）：
  1. 【快照】自动快照当前状态（附指纹）
  2. 【传感器】扫描基线（gate --save）
  3. 【执行】修改
  4. 【验证】三臂评审（build/audit/judge）
     ├─ 通过 → 继续
     ├─ 需修订 → 按审计意见改 → 重验
     └─ 拒绝 → 回滚快照
  5. 【传感器】rescan 对比基线 → 退化？→ 维生系统阻断 + 回滚
  6. 【维生显示】更新存活状态报告（影响面/回滚能力/心跳）
  7. 【固化】验证全过 + 无退化 → 固化（对齐自举纪律）
```

## 七、验证标准

- 传感器：自修改前后基线对比，退化可检出（构造退化样例）
- 三臂：同一修改，build/audit/judge 独立判据可追溯
- 维生显示：自修改威胁自身时正确阻断
- 快照：任意自修改可回滚（快照→修改→回滚→状态一致 + 指纹一致）
