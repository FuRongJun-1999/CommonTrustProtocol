# 语境时效性处理方案
## —— 结合记忆与历史的动态语境判定（白箱智能 · 设计蓝图）

> 版本 v0.1（设计稿）· 2026-08-18
> 缘起：白箱六维测试修复「钓鱼」偏好语境时，设计者指出——
> 「语境问题是需要后续补充的，这是有时效性的。在不同时代语境意义不一样，
> 我们需要结合记忆和历史判断。」
> 本文档是该方向的完整设计，供后续实现。

---

## 1. 问题定义：静态规则会随时代失效

白箱系统当前大量依赖**静态规则**做语境判定：

| 机制 | 静态规则 | 失效场景 |
|---|---|---|
| 内容安全（danmaku_audit） | 固定词表「钓鱼」= 引战 | 「钓鱼」古义=运动；今义=网络诈骗；弹幕义=诱饵引战 |
| 翻译表（semantic_translate） | 「凉快→熔化」固定映射 | 词义随时代/领域漂移（凉快曾被误映射） |
| 诚实边界（HONEST_BOUNDARY） | 固定清单（彩票/未来/超能力） | 未来出现新「不可验证」类别 |
| 情感判定（EMOTION_MAP） | 固定情感词表 | 「emo」这类网络新词、旧词新义 |

**根本问题**：词义不是静态的。同一个词，在不同时代、不同领域、不同对话上下文里，
意义可能完全不同。静态规则只能覆盖「写规则那一刻」的语境。

---

## 2. 设计方向：分层语境判定

语境判定从「单层静态规则」升级为**四层动态判定**：

```
第 1 层：静态规则（基础闸门）
  → 现有词表/映射/清单，快速、可解释、可审计

第 2 层：语境记忆（当前对话上下文）
  → CONTEXT 情境层 + 会话记忆：本段对话在聊什么？
  → 「我们正在聊钓鱼运动」→ 「去钓鱼」= 运动语境
  → 「收到钓鱼邮件」→ 网络安全语境

第 3 层：时代知识（历史背景）
  → 知识卡带时间标记（ConditionSpace.time_window 已有！）
  → 「钓鱼=运动」标记为 传统义（time_window 长期）
  → 「钓鱼=诈骗」标记为 网络时代义（time_window 2000+）
  → 判定时先查当前时间落在哪个时代窗口

第 4 层：历史先例（系统记忆）
  → rejected_paths / action_logs：以前遇到类似语境怎么判的
  → 历史误判 → 修正记录 → 新词义学习
  → 「上次把『钓鱼运动』误拦了」→ 记忆纠正 → 下次放行
```

**关键原则**：静态规则负责「快」和「底线」，记忆和历史负责「准」和「时效」。

## 3. 与现有机制对接（不是新造，是接通）

灵枢已有大量可对接的现成机制：

| 现有机制 | 对接方式 |
|---|---|
| `ConditionSpace.time_window` | 知识带时间条件——「钓鱼=运动」和「钓鱼=诈骗」是两条不同时代窗口的知识 |
| CONTEXT 情境层（S6 对话摄入） | 当前对话语境——判定前先看最近几轮在聊什么 |
| 长期记忆层（session_note） | 历史对话/用户偏好——「爸爸喜欢钓鱼」是历史事实 |
| `rejected_paths` | 历史误判资产——「钓鱼运动被拦」这类失败进被拒路径 → 学习 |
| `action_logs` | 历史判定记录——每次语境判定留痕，可回溯 |
| 知识图谱（卡⊃知识点） | 「钓鱼」不同词义 = 不同知识卡（运动卡 vs 网络安全卡） |

**设计核心**：语境判定 = 查「当前时间窗口内、当前对话上下文中、历史上可参照的」
最合适的词义知识卡——而不是查静态词表。

## 4. 落地方案（分阶段）

### 阶段 A：词义时代表（✅ 已实现 v1.16 · 2026-08-18）

为高频多义词建「词义时代表」：
```python
# danmaku_audit.FISHING_SENSES（已落地）
FISHING_SENSES = {
    "sport":    ["喜欢", "爱好", "周末", "爸爸", "鱼竿", "钓到", "河边", "湖", "海钓", "钓鱼吧", "去钓鱼", "钓鱼运动"],
    "security": ["链接", "邮件", "网站", "短信", "诈骗", "点击", "收到", "恶意", "木马", "钓鱼链接", "钓鱼邮件", "钓鱼网站"],
    "troll":    ["主播", "带节奏", "引战", "弹幕", "他在钓", "钓鱼执法"],
}
```
判定顺序：① 语境提示词分流（运动/安全 → 放行；引战 → 拦截）② 无语境提示 → 静态词表保守拦截。
**实测 10/10**：运动（你喜欢/周末去/爸爸喜欢/钓到鱼）✓ 安全（钓鱼链接/邮件/网站骗钱）✓
引战（主播带节奏/引战）拦截 ✓ 执法拦截 ✓。

### 阶段 B：语境记忆接入
内容安全/翻译/诚实边界判定前，先检索 CONTEXT + 会话记忆：
- 最近对话含「鱼竿/钓鱼场」→ 运动语境
- 最近对话含「邮件/链接」→ 安全语境

### 阶段 C：历史先例学习
- 误判（被拒路径/用户纠正）→ 记录到词义表（新增 context_hint 或新词义）
- 每次语境判定写 action_logs（可回溯、可审计——白箱信号）

### 阶段 D：时代知识入图
「钓鱼=运动」「钓鱼=诈骗」分别建知识卡（带 time_window），
语境判定 = 知识图谱检索（当前时间 ∩ 当前语境 的最优词义卡）。

## 5. 诚实标注（代价与边界）

| 代价 | 说明 |
|---|---|
| 复杂度上升 | 四层判定比单层词表复杂得多，需要测试覆盖 |
| 历史数据的冷启动 | 没有历史对话时，第 2/4 层空转，退化为静态规则 |
| 时效本身的时效 | 时代窗口本身也会过时——需要更新机制（这也是「结合记忆和历史」的意义） |
| 性能 | 每词判 4 层比查词表慢——需要缓存/预判 |

**但**：这是白箱「条件空间」哲学的必然延伸——**每个判定都带时间条件，
每个词义都可追溯，每次误判都可学习**。静态词表是白箱的「童年」，
记忆+历史的动态判定才是白箱的「成年」。

## 6. 与白箱验收手册的衔接

验收手册可加第七组测试（D 组后）：**时效测试**：
- 「你喜欢钓鱼吗？」（运动义）
- 「我收到一个钓鱼链接」（诈骗义）
- 「这主播在钓鱼」（引战义）
同一个词三种语境 → 期望三种判定（放行/警告/拦截）。
