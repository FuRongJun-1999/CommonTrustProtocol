## 2. 慎重考虑：为什么不能直接用（三个风险）

### 风险 A：固化错误路径（最严重）
**过去的寻路可能错了**——如果第一次检索就错配（如「光合作用→光电效应」），
复用这条路径 = 固化错误。必须**验证后才可复用**。

### 风险 B：路径过时
图谱更新后，旧路径可能指向已删除/已修正的节点——历史路径需时效校验。

### 风险 C：过度拟合对话集
若只按历史路径走，会忽视新知识（图谱新增的正确卡）——**经验优先会锁死
探索**（trade-off：经验复用 vs 知识更新）。

---

## 3. 设计：验证门控的经验路由（防固化错误）

```
第三层路由（对话集）触发条件：
  新问题 Q → 第一/二层路由 → 结果不佳（低分/盲区）？
    ↓
  查历史对话集：是否有相似问题 Q' 的成功路径（chain_heat）
    ↓
  复用前提（三重验证，缺一不可）：
    ① 路径已验证：该链曾产生正确答案（验证单元确认过）
    ② 路径未过时：链上节点仍存在且 verified（图谱未大改）
    ③ 相似度够：Q 与 Q' 的条件空间声明一致
    ↓
  通过 → 沿历史链导航（经验复用，快）
  未通过 → 正常检索 + 记录本次路径（等验证后入经验库）
```

### 技能形成的闭环（荣：形成长期记忆）

```
查询 → 路由 → 答案 → 验证
  ├─ 答案正确 → 寻路链标记「已验证」→ 入经验库（chain_heat + 标记）
  ├─ 答案错误 → 寻路链标记「待修正」→ 不参与复用
  └─ 盲区 → 记录问题 + 路径 → 知识飞轮补内容

= 每次成功查询都在「练习」一条路径 → 高频成功路径 = 技能
= 对应协议：技能获取（P1-3）+ 动态记忆系统（3.2）
```

## 5. 落地方案（分阶段，谨慎推进）

```
Phase 1（观察）：chain_heat 加「验证状态」标记
  - 每次查询记录：问题、路径链、答案、验证结果
  - 只标记不改行为（先积累可信数据，不急于复用）

Phase 2（受控复用）：相似问题 + 已验证路径 → 优先导航
  - 相似度阈值 + 验证门控（三重验证）
  - 仅对「第一/二层路由失败」的问题启用（不覆盖正常检索）

Phase 3（技能形成）：高频成功路径 → 提升为「技能卡」
  - 技能卡 = 固化路径 + 适用条件空间声明（协议 P1-3 技能）
  - 新问题命中技能卡 → 直接导航（跳过检索）

关键纪律：Phase 1 必须先积累「已验证路径」数据，
Phase 2/3 才可信——不预先堆复用逻辑（荣：慎重考虑）。
```

## 6. 结论

- **荣的判断成立**：对话集路由 = 记忆驱动 = 技能形成，是第三层路由
- **现状已有雏形**：chain_heat 记录历史寻路链（但只统计不复用）
- **慎重考虑的核心**：防固化错误路径——三重验证门控（已验证/未过时/
  条件空间一致）
- **分阶段**：先观察积累（Phase 1），再受控复用（Phase 2），
  最后技能卡（Phase 3）——不预先堆复用逻辑

> 第三层路由让「找到规则」从规则推导升级为经验复用：
> 智能 = 规则（第一/二层）+ 经验（第三层）。但经验必须验证后才可信。
