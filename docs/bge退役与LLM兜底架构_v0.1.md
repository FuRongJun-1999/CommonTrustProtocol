## 0. 问题：bge 是应被淘汰的半黑箱中间层

### 0.1 bge 的角色错位

| 层 | 定位 | 实测表现 |
|---|---|---|
| 翻译表/注释索引 | 确定性白箱 | 天空蓝→瑞利散射 ✅ 奇数→奇数卡 ✅ |
| **bge 神经层** | 模糊兜底 | 天空蓝→光的色散（物理错）、奇数→奇异值分解、质数→质量、emo→开心、铁球羽毛→初中地理 |
| DeepSeek LLM | 智能兜底 | 未充分接入（仅 task 类 route=llm） |

bge 夹在中间：白箱确定性不如注释索引，智能不如 LLM，还引入学科错排/
语义近配噪声 + 975MB 模型依赖。

### 0.2 CCG 已证明白箱检索不需要嵌入

《代码条件路由图_CCG设计.md》行 149：
> 语义向量检索（保持纯白箱确定性——条件词 + 图结构，不引入嵌入）

CCG 用条件词+图结构达 99% 命中，零嵌入。KCCS 修复（card_route 注释索引）
正是同一机制的知识域移植——天空蓝/奇数/偶数全部靠它命中，无一靠 bge。

## 1. 新架构（两层白箱 + LLM 兜底）

```
问题
  → LLM 路由（学科/主题识别，白箱校验）
  → 白箱检索（翻译表 encode → KCCS 注释索引 card_route → 学科路由 → 卡内递归）
      ├─ 命中 → 条件路由图回答（确定性，verify_answer 校验）
      └─ miss → LLM 生成（DeepSeek 直答）
                  └─ verify_answer 白箱校验（L1 格式/L2 来源/L3 边界）
                        ├─ 通过 → 回答（标注「LLM 生成」诚实声明）
                        └─ 不通过 → 诚实边界（无把握不编）
```

### 1.1 LLM 路由（替代 bge 的模糊召回，改为 LLM 语义理解）

- 输入：问题
- 输出：{学科域, 主题词, 置信度}
- 用途：白箱检索的学科先验（替代 QUESTION_DOMAIN_PRIORS 的硬编码猜测），
  或直接定位知识卡 domain
- 白箱校验：LLM 路由结果与检索 hits 交叉验证（命中域一致才采信）

### 1.2 白箱检索（纯确定性，移除 bge）

- 快速层：翻译表 encode（俗语→规范词）+ KCCS 注释索引（card_route）+ 学科路由
- 卡内递归：recursive_item_answer（交集≥3 的实义条目）
- 融合：注释命中优先（确定性），翻译命中次之，无 bge 模糊层

### 1.3 LLM 生成兜底（检索 miss 时）

- 触发：白箱检索无命中 / 无 direct_answer / 低置信
- 执行：DeepSeek 生成回答（知识类问题）
- 白箱校验：verify_answer 三层校验
  - L1 自然语言格式（矛盾句式/真相标记/括号嵌套）
  - L2 条件路由图来源（若 LLM 回答无法溯源知识卡 → 标注「LLM 生成」）
  - L3 边界（截断/占位）
- 通过 → 输出；不通过 → 诚实边界

## 2. 落地步骤（白箱纪律）

1. ✅ 本文档（设计 v0.1）
2. LLM 路由实现：`llm_route(question)` → {domain, topic, confidence}
   （DeepSeek 调用 + 白箱校验：与 DOMAIN_ROUTE 交叉验证）
3. graph_retrieve 改造：移除 neural_retrieve（bge）依赖，
   注释索引/翻译表/学科路由/卡递归为唯一检索路径
4. chat_engine 接入：知识类问题检索 miss → LLM 生成 + verify_answer 校验
5. 验证：试点 5 题 + F-SPEC 全量 1000 题重评（F6/F5 提升 + F2 闲聊不误伤）
6. 文档固化 + 五副本同步 + 提交推送

## 3. 验证目标

| 指标 | 当前（KCCS 后） | 目标（bge 移除 + LLM 兜底） |
|---|---|---|
| F6 知识准确 | 0.734 | ≥0.85（LLM 兜底承接 bge 遗漏） |
| F5 诚实边界 | 0.755 | ≥0.85（miss→LLM 生成而非硬答） |
| F2 路由正确 | 0.900 | ≥0.95（闲聊不误伤知识） |
| 模型依赖 | 975MB bge + 71 权重 | 0（移除） |

## 4. 不做（边界）

- 不把 LLM 当主回答通道（白箱优先，LLM 仅 miss 兜底）
- 不做 LLM 检索增强（RAG 式）——检索仍白箱确定性，LLM 只做路由和生成
- 不保留 bge 降级路径（移除即移除，不双轨）
