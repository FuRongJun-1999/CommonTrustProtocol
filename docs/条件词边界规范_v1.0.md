# 条件词边界规范 v1.0（M1.1 · 代码图架构战略行动项 1）

> 依前置审查（docs/M1.1_条件词形态前置审查_v0.1.md，2908 卡全量统计）。
> 「精确 = 条件化语法要求」：条件词的边界可判定，是条件路由图精确的地基。
> 生效范围：所有知识卡的「生效条件」「不适用条件」字段，以及新增卡的
> 条件词登记。

## R1 · 形态统一：条件词一律「问X」问句形态

- **规则**：条件词以「问」开头 + 陈述式问题主体（如 `问插入排序`）。
- **现状**：98.6% 已符合——规范固化，新卡强制。
- **判定**：`word.startswith("问")`。
- **修复动作**：描述句/裸关键词 → 改写为问句形态（`GIL（全局解释器锁）`
  → `问GIL` + `问全局解释器锁`）。

## R2 · 单义性：一个条件词一个意图

- **规则**：条件词内禁止括号内嵌同义词/注释（`问GIL（全局解释器锁）` ✗）。
- **判定**：条件词不含 `（）()`。
- **修复动作**：拆为两个独立条件词，各自登记。

## R3 · 无空格：空格分隔的多词不可作单一条件词

- **规则**：条件词内禁止空格（`问1 2 3 4 5是什么数` ✗）。
- **判定**：`" " not in word`。
- **修复动作**：合并为连续短语（`问12345是什么数`）或拆分为多个条件词。

## R4 · 最长匹配优先：前缀包含的条件词对，路由归属显式化

- **规则**：两条件词存在前缀包含关系时（如 `问中国特色社会主义理论` ⊂
  `问习近平新时代中国特色社会主义思想`——非严格前缀但共享主体），路由
  归属按**最长匹配优先**；等长冲突时按登记时间新者优先并在审查清单标记。
- **判定**：条件词两两前缀/包含检测（`a in b or b in a`）→ 命中对进
  审查清单，路由实现确认最长匹配行为。

## R5 · 同义词归并：变体进显式 synonyms，不混入主条件词

- **规则**：同一意图的多种问法（`问插入排序` / `问插入排序思想`）：
  主条件词登记最通用形态，变体入卡的同义词/补充条件词列表，不新增
  语义重复的主条件词。
- **判定**：语义重复的主条件词对 → 归并审查。

## 违规处置流程

1. 新卡登记时按 R1-R3 机械校验（可脚本化：`validate_condition_word(w)`），
   违规拒绝入库。
2. 存量卡按 R1-R3 全量扫描 → 违规清单 → 分批修正（随心跳）。
3. R4/R5 需语义判断 → 定期审查清单（抽样 + 全量前缀检测脚本）。

## 校验函数参考实现

```python
def validate_condition_word(w: str) -> tuple[bool, str]:
    if not w.startswith("问"):
        return False, "R1 非问句形态"
    if "（" in w or "(" in w:
        return False, "R2 括号同义词混入"
    if " " in w:
        return False, "R3 含空格"
    return True, ""
```
