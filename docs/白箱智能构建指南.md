# 白箱智能构建指南
## —— 从灵枢（AEIS）的工程实践提炼的可操作方法

> 版本 v1.0 · 2026-08-18
> 适用对象：想给自己的 AI 系统装上「透明度」的开发者/研究者。
> 本文所有模式都来自灵枢（一套遵循「智能论」协议的开源记忆引擎）的真实运行代码，
> 不是 PPT——每一节都有代码、有实测数据、有诚实标注的代价。

---

## 0. 白箱智能是什么（先对齐概念）

**黑箱**：大模型给你一个答案，你不知道它依据什么、在什么条件下成立、错了怎么修正。
**白箱**：系统的每个回答都能回答三个问题——

1. **依据什么**（锚定：引用了哪条知识）
2. **在什么条件下成立**（条件空间：E1 小学层级成立 ≠ E5 前沿成立）
3. **错了怎么办**（验证闭环：失败被记录、被学习、被修正）

白箱 ≠ 不用大模型。白箱 = **给模型套一层可审计的骨架**：
知识库负责「知道什么」，验证单元负责「凭什么信」，反思协议负责「怎么改自己」。
大模型退居为「假设生成器」——它提出假设，物理基底（代码/实验）裁决。

灵枢的实测结果（诚实校准）：1000 条对话严格正确率 69.5%，图谱信噪比 0.9524，
压缩率 4000:1（7.1GB 维基 → 1.78MB 纯知识）。**白箱没有牺牲正确率，换来的是可审计**。

## 1. 第一原则：一切知识必须带条件

**理念**：世界上没有「无条件为真」的知识。「水在标准大气压下 100°C 沸腾」——
去掉「标准大气压」这个条件就是错的。黑箱把条件藏在训练数据里，白箱把条件写出来。

**灵枢的做法**：每条知识卡挂一个 `ConditionSpace`：

```python
class ConditionSpace:
    observation_position: str   # 从哪个观测位置看（外部观测/行为观测）
    observation_tool: str       # 用什么工具观测
    time_window: tuple          # 在什么时间范围内成立
    existence_constraint: str   # 存在的约束条件（核心！）
```

例如初中物理卡：

```python
ConditionSpace(
    observation_position="初中物理 外部观测位",
    observation_tool="课标骨架×综合卡",
    time_window=(0.0, 9999999999.0),
    existence_constraint="通用规律/知识（开源非盈利知识库）"
)
```

**你的系统怎么做**：
1. 给每条知识/每个回答加 `condition` 字段（最少：成立条件一句话）
2. 回答时把条件展示给用户：「这条知识属于初中物理，在 E2 条件下成立」
3. 检索时按条件过滤（问小学问题，不返回大学公式）

**代价（诚实）**：写条件 = 额外维护成本。但换来的是「知识冲突时可追溯」——
灵枢发现矛盾记忆时能定位是哪两个条件空间打架，而不是黑箱里无法归因。

---

## 2. 信息分层：系统必须知道自己「知道多少」

**理念**：白箱系统的第一自省 = 知道自己的知识边界。把处理分成几层，
每层明确「我有把握到什么程度」。

**灵枢的做法**：三层路由（`route` 字段标注每层）：

```
self         智慧之书自处理（情感/闲聊/高置信知识）→ 直接回答
llm          知识库没把握 → 大模型续答（知识库回答作上下文）
self_fallback LLM 不可用 → 回退知识库
```

每一层都有 `meta_note` 非认知声明：「这条回答来自知识图谱自处理」或
「LLM 补充，未经物理基底验证」。

**你的系统怎么做**：
1. 定义你的分层（至少两层：知识库层 + LLM 兜底层）
2. 每层返回时**标注来源**（`route` + `confidence` + `anchored`）
3. 上层没把握就**降级**，但永远不静默混淆「我查到的」和「我编的」

**实测**：灵枢 1000 条测试 route 分布 self:756 / llm:244——
76% 的问题知识库直接处理，24% 诚实交给 LLM。分层不是要「尽量少用 LLM」，
是要「每一条都清楚是谁答的」。

---

## 3. 白箱校验：回答之后自检「锚没锚住」

**理念**：回答完不等于结束。白箱系统对自己的输出做**白箱校验**——
这个回答锚定到知识库的哪条知识？锚不住 = 可疑。

**灵枢的做法**：`llm_verify` 三态 + `meta_note`：

```
anchored     回答有知识卡锚定（引用「初中物理」卡）
unverified   回答无锚定（LLM 自由发挥，标注「未经验证」）
partial      部分锚定（一半知识一半推测）
```

校验记录归档观测层，供 `history_recheck` 回溯——**旧回答放入新结构重新锚定**。

**你的系统怎么做**：
1. 回答后跑一遍「锚定检查」：找出回答里引用的知识库条目
2. 没锚住的回答打标 `unverified`，用户能看到
3. 定期回溯：旧回答用当前知识库重新校验（知识进化后，旧回答可能过时）

---

## 4. 诚实边界：不知道就说不知道（且能说清单）

**理念**：白箱不是「永远答对」，是「永远区分知道/不知道」。黑箱的幻觉来自
「不知道但装知道」；白箱把「不知道」变成一等公民。

**灵枢的做法**：`HONEST_BOUNDARY` 拦截不能编造的问题类型：

```
future      未来随机事件（彩票号码）→「信息边界：结果发生前不确定，我不编」
impossible  超能力/伪科学 →「这超出可验证范围」
unknown     知识库没有 →「这个问题我暂时没有把握，不想瞎编」
```

回答模板固定：「关于 X，我没有能力预测未来随机事件——这不是知识问题，
是信息边界：结果在发生前不确定，我不会编一个答案给你。」

**你的系统怎么做**：
1. 列一张「不能编造」的清单（未来预测/超自然/无法验证的断言）
2. 命中清单 → 返回标准诚实回答（不要用 LLM 即兴发挥——即兴就会编）
3. 把「我不知道」也计入可复现指标（诚实率：该说不知道的题里，说了几次）

**实测**：诚实边界类 1000 条测试正确率 67.9%，且**从不编造**——
「诚实率」是白箱系统的硬指标，比正确率更重要。

## 5. 真理闸门：物理基底校准（代码/实验裁决）

**理念**：白箱的最终裁判不是 LLM 自我评估（那还是黑箱），是**物理基底**——
代码运行结果、实验偏差。LLM 只负责「提出假设」，物理基底负责「裁决真理」。

**灵枢的做法**：三语言物理基底测试（`code_test_runner`）：

```python
# 假设「Rust 所有权错误信息是 borrow of moved value」
# → 物理基底：写一段真正触发该错误的 Rust 代码，编译看报错文案
# → 裁决：实际报错是 "borrow of moved value"，假设成立 → 知识入图（verified）
```

验证闭环：
```
被拒路径（系统失败的输入）→ 因果候选（假设）→ 可观测预测
→ 物理基底验证（代码/实验）→ 命中=知识确认入图 / 未命中=候选否决
```

**你的系统怎么做**：
1. 找出你系统里「可用代码/实验验证」的知识领域（编程、科学、数学）
2. 为这些领域建「验证器」：知识断言 → 自动跑实验 → 比对结果
3. LLM 生成的假设必须过验证器才进知识库（`verified` 标记），
   过不了的进 `rejected_paths`（失败资产化，不丢弃）

**关键原则**：验证器和被验证的知识**分属不同实现**（不能自己验证自己）。
灵枢用 Python 测 Python 知识、用 Rust 编译测 Rust 知识——错误文案是
编译器说的，不是模型说的。

## 6. 可审计推理：递归反思协议

**理念**：白箱系统会「想」，且每次「想」都有记录。反思不是玄学，
是固定协议：claim → 验证 → 隐藏前提 → 终裁。

**灵枢的做法**（协议 3.12，递归 ≤3 层）：

```
depth 1：claim 是什么？验证（预期 vs 实际）→ 偏差？
depth 2：这件事的隐藏前提是什么？（条件空间边界）
depth 3：影响评估 → 终裁（可逆性优先）
超出 3 层 = 结构性盲区（反思本身的反思也有限制）
```

每次反思生成 `reflection_chain` 归档（可回溯到当初的每一条判断）。

**你的系统怎么做**：
1. 定义你的反思协议（哪怕只有一层：断言 → 证据 → 结论）
2. 每次系统「自我修正」时写反思日志（claim/expected/actual/verdict）
3. 反思日志计入审计（谁在什么时候因为什么改了知识）

**案例**：灵枢曾给「信噪比」维度设计五信号仪表盘，反思到 depth 3 时发现
「还在细化指标口径 = 设计噪音本身」——**反思协议连自己的设计过程都能审**。

## 7. 因果发现：从失败中学习

**理念**：白箱系统的失败不是 bug，是**被拒路径**——「系统在这些输入上失败」= 未知因果的线索。
黑箱失败后沉默，白箱失败后生成因果假设。

**灵枢的做法**：`causal_discover`（条件论七操作对自身）：

```
识别   扫描被拒路径/预测未命中 → 异常模式
声明   异常 → 因果候选（带条件空间）
分离   剥离混淆因素（排除第三变量）
逆转   检查因果方向（A→B 还是 B→A）
循环   输出可观测预测 → 物理基底验证 → 命中强化/未命中否决
```

**你的系统怎么做**：
1. 记录所有失败输入（检索 miss/预测未命中/回答被纠正）
2. 聚类相似失败 → 生成因果假设（「翻译表缺 X→Y 映射导致检索失败」）
3. 假设可验证 → 物理基底验证 → 确认后知识入图（或修复代码）
4. **被拒路径 consumed = 因果确认**——失败转变成知识，闭环闭合

**案例**：灵枢发现「用户问『水为什么烧开』检索不到沸点知识」→ 因果假设
「翻译表缺沸点→沸腾映射」→ 物理验证（编码测试命中沸腾）→ 路径 consumed →
第一条 verified causal 边入图。**失败直接变成了可追溯的知识**。

## 8. 可复现度量：用数据证明白箱有效

**理念**：白箱的终极自证 = 可复现的度量。没有测试报告的白箱是自称白箱。

**灵枢的做法**（三件套）：
1. **1000 条对话测试**：客观题关键词评分 + 主观题通路匹配，输出分类正确率报告
2. **五维标尺评分表**：S 存储/R 检索/J 判断/C 信噪比/Safety 安全，每维有依据注释
3. **信噪比仪表盘**：压缩率/注入质量率/图谱信噪比/记忆清理率——趋势+瓶颈建议

**你的系统怎么做**：
1. 建一个可复现测试集（至少 100 条，覆盖你的核心能力）
2. 每次改动跑全量回归（**教训：灵枢知识点嵌套曾引入三处回归 bug，
   第 4 轮测试 65.5% 跌穿基线——没有回归测试的优化都是赌博**）
3. 指标写进 README，标注「设计者校准，不虚高」

## 9. 代价与边界（诚实章节）

白箱不是免费午餐。把这页给投资人/合作者看之前，先自己接受：

| 代价 | 说明 |
|---|---|
| 开发成本 | 条件空间/验证器/反思协议都要写代码，不是调 API |
| 表达受限 | 诚实边界让系统「不敢编」，某些场景显得笨 |
| 维护负担 | 条件要维护，验证器要更新，测试要重跑 |
| 覆盖有限 | 物理基底只能验证可执行的知识（编程/科学）；情感/审美类仍靠模型 |

**但**：这些代价换来的是黑箱永远给不了的——**可审计、可修正、可复现**。
当你的系统出错时，你能说出「哪条知识错了、为什么错、怎么改」——
这是 AI 进入严肃领域（医疗/金融/教育）的入场券。

## 附录：最小白箱骨架（Python，零依赖）

```python
"""最小白箱系统：带条件的知识 + 诚实边界 + 锚定校验 + 失败记录"""
import json, time

class ConditionSpace:
    def __init__(self, position, tool, constraint):
        self.position, self.tool, self.constraint = position, tool, constraint
    def to_dict(self):
        return {"position": self.position, "tool": self.tool,
                "constraint": self.constraint}

class KnowledgeBase:
    """知识库：每条知识带条件 + 验证状态"""
    def __init__(self):
        self.knowledge = {}   # key -> {"content", "condition", "verified"}
        self.rejected = []    # 被拒路径（失败资产）

    def add(self, key, content, condition: ConditionSpace, verified=False):
        self.knowledge[key] = {"content": content,
                               "condition": condition.to_dict(),
                               "verified": verified}

    def retrieve(self, query):
        """检索：返回 (命中的知识, 锚定与否)"""
        for key, k in self.knowledge.items():
            if key in query or query in key:
                return k, True
        return None, False   # 未锚定

class WhiteBoxAgent:
    HONEST_BOUNDARY = ["彩票", "未来", "超能力", "无法验证"]  # 不能编造的词

    def __init__(self, kb: KnowledgeBase, llm=None):
        self.kb, self.llm = kb, llm   # llm = 假设生成器（可空）

    def answer(self, question):
        # 1. 诚实边界：命中清单 → 标准诚实回答（不用 LLM 即兴）
        if any(w in question for w in self.HONEST_BOUNDARY):
            return {"reply": f"关于「{question}」我没有能力验证——"
                             "结果在发生前不确定，我不会编一个答案给你。",
                    "anchored": False, "route": "honest"}

        # 2. 知识库自处理（带条件）
        k, anchored = self.kb.retrieve(question)
        if anchored:
            return {"reply": f"{k['content']}（这条知识属于{k['condition']['position']}，"
                             f"在{k['condition']['constraint']}条件下成立）",
                    "anchored": True, "route": "self",
                    "verified": k["verified"]}

        # 3. 降级 LLM（标注未经物理验证）
        if self.llm is not None:
            reply = self.llm(question)   # 假设生成
            self.kb.rejected.append({    # 失败资产化
                "query": question, "time": time.time(),
                "reason": "知识库未锚定，LLM 补充未经验证"})
            return {"reply": reply, "anchored": False,
                    "route": "llm", "meta_note": "LLM 补充，未经物理基底验证"}

        # 4. 无 LLM：诚实说不知道
        self.kb.rejected.append({"query": question, "time": time.time(),
                                 "reason": "知识库未锚定且无 LLM"})
        return {"reply": "这个问题我暂时没有把握，不想瞎编。",
                "anchored": False, "route": "honest"}

# ---- 使用 ----
kb = KnowledgeBase()
kb.add("沸腾", "水在标准大气压下 100°C 沸腾",
       ConditionSpace("初中物理观测", "课标", "标准大气压下成立"), verified=True)

agent = WhiteBoxAgent(kb)   # 不接 LLM，纯白箱
for q in ["沸腾", "下期彩票号码", "光合作用"]:
    r = agent.answer(q)
    print(q, "→", r["reply"][:40], f"[anchored={r['anchored']}]")
```

运行输出：

```
沸腾 → 水在标准大气压下 100°C 沸腾（这条知识属于初中物理观测，在标准大气压下成立条件下成立） [anchored=True]
下期彩票号码 → 关于「下期彩票号码」我没有能力验证——结果在发生前不确定，我不会编一个答案给你。 [anchored=False]
光合作用 → 这个问题我暂时没有把握，不想瞎编。 [anchored=False]
```

这就是白箱最小闭环：**带条件的知识 + 诚实边界 + 锚定校验 + 失败记录**。
你的系统从这里开始，一步步加上验证器、反思协议、因果发现和测试报告，
就能达到灵枢的完整程度。
