# CSPMN GPU 接入设计 · 规模感知 + 信息差驱动（2026-08-20）

> 决策依据：GPU 矩阵乘验证成功（3030→7x，10^6→2.1ms），但量化显示
> 当前 3030 规模下 search_index 全链路仅 0.9ms，矩阵乘只占 18%——
> GPU 在当前规模收益 <5%。GPU 的价值在百万级（荣确认的主线）。

---

## 0. 核心设计原则（荣：信息差足够小就不需要更深的调用）

**「百万级子实例」不是每次调用都触发——由信息差收敛判据（gap_trend）
决定调用深度**。这正是 3.10 自迭代 + 3.12 递归验证在 CSPMN 上的落地：

```
信息差 D_norm 大（新问题/盲区）→ 深调用（更多子实例，甚至 GPU 全量）
信息差 D_norm 小（已知问题/常规）→ 浅调用（少量子实例，CPU 足够）
信息差收敛（gap_trend → 0）→ 停止扩展（自维持）
```

---

## 1. 规模感知的检索层（分层决策）

```
search_index(query, scale="auto"):
  scale = "auto" 由信息差/图谱规模决定：
    N ≤ 10^4  → CPU（numpy BLAS，~0.9ms 全链路，当前 3030 用这个）
    N ≤ 10^6  → GPU（torch cu118，2.1ms，4.11GB 显存）
    N > 10^6  → GPU 分块/稀疏（远期）

当前 3030 → CPU 足够（0.9ms 毫秒级，GPU 收益 <5%）
未来 10^5+ → GPU 切换（矩阵乘占比主导，7x 加速显效）
```

**为什么现在不换 torch**：主环境 torch 2.13.0+cpu + pytorch-lightning 2.6.5
全家桶，装 cu118 会破坏版本匹配（torch/cpu→cuda 全家要一起换）。GPU 验证
用 SD python 做（独立环境，不冲突），接入主环境等规模到了 10^5 再动。

---

## 2. 信息差驱动的调用深度（CSPMN 自维持）

```
深度决策（复用现有 gap_trend / D_norm）：
  D_norm > 0.6（大信息差）→ 深度 3（全量子实例 + 盲区检测）
  0.3 < D_norm ≤ 0.6 → 深度 2（相关子空间，CSPRE domain 分块）
  D_norm ≤ 0.3（小信息差）→ 深度 1（浅层匹配，缓存优先）
  gap_trend 收敛 → 不再扩展（3.10 自迭代停止条件）

= 荣说的「信息差足够小就不需要更深的调用」
= CNN 论证里「收敛判据驱动结构增长」的工程化
```

---

## 3. 当前落点（不做大改，加一层决策）

```
1. search_index 保持 CPU（3030 规模毫秒级，够用）
2. 新增 cspmn_depth(query) → 返回建议深度（复用 D_norm/gap_trend）
3. 深度 3 时触发盲区检测（现有 BS-QUERY-WEAK 机制）
4. GPU 后端预留接口（Backend 抽象，规模到 10^5 再启用）
```

**诚实边界**：当前不换 torch（破坏依赖），不强制 GPU（收益 <5%）。
GPU 已验证可行（SD python 独立跑通），等规模增长启用。

---

## 4. 未来路径（荣的主线：百万级）

```
阶段1（现在）：3030 规模，CPU 检索 + 信息差驱动深度决策
阶段2（图谱扩到 10^5）：GPU 切换（SD python 或主环境装 cu118）
阶段3（10^6+）：GPU 分块/稀疏 + 冷热缓存（高频子实例常驻显存）
```

---

## 5. 结论

- **荣的判断正确**：信息差收敛判据决定调用深度，不是所有任务都触发百万级
- **当前不换 torch**：3030 规模 CPU 已毫秒级，GPU 收益 <5%，且换 torch
  破坏主环境依赖
- **GPU 已验证可行**（SD python 独立跑通 10^6 2.1ms），规模到 10^5 启用
- **新增**：cspmn_depth 深度决策层（复用 D_norm/gap_trend）+ Backend 抽象
