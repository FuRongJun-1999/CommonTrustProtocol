# 为什么有记忆/规范/锚点，执行依然会犯错（架构反思 · 2026-08-26）【架构反思·有效】

> **【版本确认 · 2026-08-29】** 本文档的反思结论（规范/锚点需验证闭环）与智能论 v3.4
> 一致（验证是信任基底）。

> 背景：1000 对话集退化（99%→79%）暴露的根本问题。灵枢有长期记忆
> （REVERSE_DAILY 649 条）、有规范（条件路由图）、有锚点（设计原则），
> 但执行依然被 REVERSE_DAILY 整卡直出带偏。

## 一、四层脱节（这次失败的解剖）

| 层 | 有什么 | 怎么失守的 |
|---|---|---|
| 记忆 | REVERSE_DAILY 649 条知识 | 自主进化把 70 字人话覆盖成 1010 字整卡——**写无校验** |
| 规范 | 条件路由图（_cond_analysis → 子功能） | v1.27 预检绕过规范——新代码路径插队，规范是注释不是硬约束 |
| 锚点 | 「回答走条件路由图」「诚实边界」 | 锚点是理念文档，没有变成 invariant——绕过时无人拦截 |
| 执行 | 实际代码路径 | 走了 REVERSE_DAILY 直出整卡——与规范/锚点脱节 |

## 二、三个机制缺陷

### 1. 规范与执行是两条平行线
- 规范写在注释里，代码可悄悄新增绕过路径——没有机制把规范变成拦截器
- 类比：交通规则写在墙上，但没人设卡口

### 2. 记忆「可写」但「写无校验」
- 自主进化直接 REVERSE_DAILY[key] = 整卡，无校验「是否适合作为回答输出」
- 记忆系统只保证「能存」，不保证「存对」——写入正确性无 gate
- 基线被破坏时无回归报警，直到人工测试发现

### 3. 锚点是「理念」不是「机制」
- 设计原则只在人脑里生效，未变成代码层断言（invariant）

## 三、根因：知识表示与用户输出不分层

- REVERSE_DAILY 存知识卡内部格式（整卡），被直接当回答输出
- 缺少「表示→人话」的强制转换边界——内部格式泄漏到用户界面

## 四、正解：规范 → 机制（四道硬约束）

1. **规范 → invariant**：回答出口断言「必须来自条件路由图结果」，绕过路径被机制拒绝
2. **记忆写 gate**：自主进化升级簇时校验新值格式（人话 ≤300 或入 FULL 库），写错拒绝
3. **进化带回归**：每次 evolve 升级自动跑 1000 集，命中率下降即回滚
4. **分层强制**：知识表示（整卡 FULL）与输出表示（人话 DAILY）物理分离，输出层只认人话

## 五、结论

> 灵枢的问题不是「没有记忆/规范/锚点」，而是「记忆可写坏、规范可绕过、
> 锚点不设卡」——三层都是「建议」而非「约束」。白箱的下一步不是加更多
> 知识，而是把已有规范变成**不可绕过的机制**：写错会被拒绝、绕过会被
> 拦截、退化会被报警——成为系统属性。
