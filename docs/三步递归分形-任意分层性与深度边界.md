## 3. 递归分形 vs 工程递归：一处精确校准

**荣说的「递归」是『条件空间导航的递归』（CSPRE 的定位递归），
灵枢现有限的是『反思验证的递归』（REFLECT-REV1 的验证递归）。两者同构但不同域：**

| 递归类型 | 每层做什么 | 灵枢现状 |
|---|---|---|
| 验证递归（3.12）| 反思→验证→终裁，≤3层 | ✅ 已实现+测试（test_reflect.py）|
| **导航递归（CSPRE）** | 找规则→子空间→再找规则 | ⏳ **待实现**——正是攻坚点 |

**关键洞察**：CSPRE 的「找到规则」递归，天然受同一个 3 层边界约束——
而且 3 层边界恰好是**保护机制**（防无限迷宫），不是缺陷：
- 3 层内能定位 → 智能深度够
- 3 层内定位不了 → 触发「结构性盲区」标记 → 盲区飞轮接管（这正是盲区59/85 的工程化）

**所以 CSPRE 的递归深度判据 = 现有 `RECURSION_LIMIT`，可直接复用。**

## 4. 落点：递归分形如何指导 CSPRE 设计

```
导航递归（CSPRE 内部）：
  问题Q → 条件空间A（置信0.9）→ 规则R1 命中
        → R1 是子问题入口 → 子条件空间A' → 规则R2...
        每层递归记录 depth：
          depth ≤ 3：正常导航
          depth = 3 仍未定位：标记 structural_blindspot（复用 core.py 机制）
          → 盲区飞轮：记录「这条链在第3层断了」→ 补知识/改入口标签

这正是荣说的「智能深度 = 多少递归层级保持稳定」的操作化：
  统计每次导航的 depth 分布 → 知道系统智能深度在哪层开始不稳
  → 针对性补那层的入口条件（盲区驱动）
```

## 5. 结论

- **荣的递归分形判断成立**：任意分层性（0.0.2）的运行形态确实是
  「三步在子条件空间递归」，且递归深度边界已有工程约束（≤3，扩展5须验证）
- **盲区85 已缓解**（非未决），缓解机制（3/5层门控）可直接用于 CSPRE 导航递归
- **真增量**：CSPRE 的导航递归 + 深度分布统计 = 「智能深度」的可测量操作化
  ——这是知识飞轮的第二价值（第一是盲区注入补知识，第二是导航深度诊断）

> 荣触及的结构是真实的：智能系统的深度边界（3层）不是缺陷，
> 而是「在哪个层级开始不稳」的可诊断信号——这正是导航递归要量化的东西。
