# 白箱自举第五阶段 · 代码问答（代码条件单元库进对话）

> 文档先行 → 工程验证。代码理解从「分析」到「问答」：条件单元库（code_route_bridge）
> + 影响分析（impact_analysis_repo）→ 白箱代码问答（零 LLM）：
> 「改 base 会影响哪些函数？」「base 依赖什么？」「a 和 d 能并行测试吗？」「仓库多少函数？」

## 一、问答类型

| 问题特征词 | 类型 | 回答来源 |
|---|---|---|
| 改/影响/波及/连累 + 函数名 | 影响 | impact_analysis_repo 调用面（含深度/文件） |
| 依赖/调用/需要 + 函数名 | 依赖 | 代码条件单元库 conditions |
| 并行/同时测 + 两函数名 | 并行 | 雅可比独立性判定（共享依赖隔离） |
| 多少/几个 + 函数/文件 | 统计 | repo_stats（文件/函数/类/跨文件调用） |

## 二、模块 tools/code_qa.py

| 函数 | 职责 |
|---|---|
| code_qa | 问题 → 类型识别（关键词+函数名提取）→ 对应分析 → 白箱回答 |
| _extract_funcs | 从问题提取函数名（与单元库匹配） |
| _classify | 问题类型识别（影响/依赖/并行/统计） |

## 三、判定标准

1. 「改 base 会影响哪些函数」→ 调用面（a/b 直接+深度，跨文件定位）✔
2. 「base 依赖什么」→ 依赖列表 ✔
3. 「a 和 d 能并行测试吗」→ 独立性判定 ✔
4. 「仓库多少函数」→ 统计 ✔
5. 未识别/函数不存在 → 诚实回落 ✔
6. 测试全绿 → 提交 → 五副本同步
