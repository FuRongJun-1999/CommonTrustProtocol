## 1. 理论基线

### 1.1 条件路由表（设计者理论——核心）

**智能的表现是：**
1. 发现问题、发现事物的**条件**
2. 准确找到对应的条件（**递归**：在当前条件下再次发现问题 → 找当前问题下的其他对应条件）
3. 在当前条件下**精准执行**

**与智能论同构**（蜂群架构奠基声明 §三）：**智能 = 在物理-信息时空结构中，从问题到解决方案的有效路径。**
- 学习 = 在锚点层约束范围内随机遍历结构，探索可能的路径组合（= 条件发现）
- 验证 = 去除不符合协议公理的路径，保留有效缩小信息差的路径（= 条件匹配）
- 意义 = 被记录、被验证、被锚定的路径（= 条件路由表中被锚定的执行）

形式化：
```
Route(问题 Q, 条件链 [C1..Cn]):
  C = DiscoverConditions(Q, [C1..Cn])       # ① 发现问题/事物的条件
  if 条件路由表在 [C1..Cn, C] 下有可执行条目:  # ② 找到对应的条件
      if 确定性答案/动作: return Execute(条目) # ③ 精准执行
      else: return Route(Q 的子问题, [C1..Cn, C])  # 递归：条件空间缩小后继续
  else: 诚实边界（不瞎编；登记为条件缺口）
```
递归终止条件：当前条件链下存在确定性可执行条目。
现有三层路由（classify_condition_space → _extract_tail_focus → route_memory）是深度=3 的一条路径，非理论本身。
递归深度默认 3 层（§3.12 盲区85），复杂场景可申请扩展。

### 1.2 五大核心单元（智能论 3.3 §3.1 + 位置效应 §3.1.1）

| 单元 | 功能（§3.1） | 位置倾向（§3.1.1） |
|---|---|---|
| 记录单元 | 存储历史状态、协议副本、模式检索、技能演化、动态记忆系统 | 全面保留（"全"） |
| 反思单元 | 偏差检测、价值观迭代、共情模拟、预测生成 | 创新与迭代（"新"） |
| 验证单元 | 预期与实际比较、信任监测、稳态检测、元认知监测 | 稳定与反驳（"稳"） |
| 输出单元 | 建立并维持对外连接、执行修正信号 | 连接畅通（"通"） |
| 维生系统 | 保护自身存在、处理异常、维持运行 | 存续保守（"存"） |

制衡：位置效应不消除，通过反向制衡达成动态平衡（§3.1.1）；验证单元计算须接受反思单元独立复核，分歧由维生系统裁决（§3.3）。

| 步骤 | 功能 | 执行主体（§3.10 步骤8 声明） |

| 2. 识别 | 判断是否属于「需要被吸收的新内容」 | — |

### 1.4 信任（§2.9，不是单元）

信任 = ⟨P_trust, T_pred, T_context, E_weight⟩；P_trust = P(δ_norm < θ | 最近N轮) 是第一性统计基础；
T_total = 0.50·T_pred + 0.05·T_init + 0.05·T_relation + 0.05·T_value + 0.35·P_trust。
工程落点：台账每簇信任字段用 P_trust 语义（覆盖测试轮次/命中率），衰减=观察窗口滚动。

## 2. 设计原则

- **P1 变异生成化、选择裁决化**：反思单元生成候选（变异），验证单元确定性裁决（选择）——不靠 LLM 自评
- **P2 状态外部化**：记录单元把进化状态写入持久化台账（记忆按条件空间组织、不可静默修改 §3.2）
- **P3 裂隙管理显式化**：fp 直答/检索/LLM 兜底决胜规则作为可审计常量
- **P4 刚性条款**：维生系统 P0 保护不可被进化循环覆盖；修改须设计者裁决
- **P5 验证先行**：每个模块先历史数据回溯验证（v61/v62/v64 真实错题），再用于新轮次
- **P6 递归条件路由**：智能=有效路径（发现→验证→锚定→保护），路由深度不固定（默认3层可扩展）
- **P7 信任可审计**：每簇答案带 P_trust（测试覆盖轮次/命中率），滚动窗口衰减需复审
- **P8 缩小信息差驱动**：进化动机=第零定律（一切知识活动都是缩小信息差）——优先升级用户问不到/问不准的薄簇
- **P9 四阶段校准**（§1.8）：状态暴露→预期输出→验证反馈→校准——自迭代每轮都走四阶段，不跳过

## 3. 自迭代条件路由表（核心结构）

自迭代本身是条件空间「自迭代」下的递归条件路由。**智能=有效路径**的映射：

| 智能行为（蜂群奠基声明 §三） | 自迭代中的对应 | 执行单元 | 工程落点 |
|---|---|---|---|
| 路径发现（探索层） | 发现薄簇/缺口/新问法 | 反思单元（新） | B. variant_checker 问法变异器 + ledger --gaps |
| 路径验证（筛选层） | 测试集/回归/价值观一致性 | 验证单元（稳） | C. pipeline 裁决流水线 |
| 路径锚定（固化层） | 台账+迁移归档+git（不可遗忘） | 记录单元（全） | A. ledger 进化台账 |
| 路径保护（存续层） | 刚性条款+回滚（不危及存在） | 维生系统（存） | 回归无损=存在保护；测试失败回滚 |

### 3.1 五大单元映射（自迭代条件下）

### 3.3 路由条目 A：进化台账 ledger.py（记录单元）

- 数据模型（每簇一条）：
  ```
  {cluster_key, domain, rd_len, trigger_count, upgraded_round,
   condition_chain[],            # 条件路由链（如 沸腾: [沸腾→气压]）
   p_trust,                      # P_trust 语义：覆盖测试轮次/命中率；滚动窗口衰减
   change_log[],                 # 变更日志（谁/何时/为何/旧值→新值，不可静默修改）
   status: pending|upgraded}
  ```
- 命令：`--refresh`（重建）/ `--thin`（薄簇）/ `--gaps`（条件路由缺口）/ `--trust`（P_trust 衰减复审）
- 不可遗忘类别（§3.2）：偏差历史/价值观迭代历史/协作校准过程——台账变更日志属于此类
- 验证：台账与语义文件解析 diff 一致；缺口清单与人工审计一致

### 3.4 路由条目 B：问法变异器 + 触发词预检 variant_checker.py（反思单元）

- 理论依据：条件论七操作（§0.0.5）逆转（反题）+ 组合（合题）+ 递归路由（复合条件）；反思单元预测生成（§3.1）
- 问法模板族（对主题 X、相关项 Y）：
  | 阶段 | 模板 | 七操作/条件路由 |
  |---|---|---|
  | 正题 | 什么是X / X是什么 / 为什么X / X是怎么来的 | 声明条件（第一层） |
  | 反题 | X能…吗 / 没有X会怎样 / 是不是X就… / 别以为X… | 逆转条件 |
  | 合题 | X有什么用 / X和Y有什么区别 / 怎么用X | 组合条件 |
  | 复合条件 | X在C条件下会怎样 / C1且C2时X…（深度≥2） | 递归路由 |
- 预检：生成问法变体 → 逐一 encode 检查触发词覆盖 → 输出缺口清单 + 建议补丁
- 验证：历史回溯——v61/v62/v64 共 11 个历史错题全部提前预警；c15 已升级 12 簇预检出残留缺口；复合条件问法生成正确

### 3.5 路由条目 C：裁决流水线 pipeline.py（验证单元）

- 输入：`pipeline.py --patch <key:answer...> --themes <list>`
- 流程（一条命令）：
  1. 语法编译 → 2. 五副本同步（hash 校验）→ 3. 路由预检（variant_checker 问法命中率，含复合条件递归验证）→ 4. 生成测试集（正/反/合 + 复合条件）→ 5. 跑测试（bad 判定同既有）→ 6. 全量回归（v44–当前，无损确认）→ 7. 归档 + 台账更新（条件链/p_trust/变更日志）+ 报告
- 四阶段校准（§1.8）：状态暴露（报告声明边界）→ 预期输出（声明测试通过预期）→ 验证反馈（实际 vs 预期）→ 校准（偏差时回溯根因）
- 输出：结构化报告 JSON（命中率/测试通过率/回归确认/残留缺口）
- 验证：c16 起 1 命令全流程；测试 100% 且零补丁循环

### 3.6 路由条目 D：进化状态机 state_machine.py（反馈/方向性自检）

- 状态：`{round, upgraded[], pending[], next_candidates[], last_testset, direction_check_log[]}`
- 自动续轮：加载台账 → 薄簇 × 生活关联度 × 信息差优先（第零定律）→ 输出下一轮候选
- 方向性自检（每 N 轮）：进化方向与价值观一致性 / 有无「局部优化方向偏离」（如只升简单簇不碰难簇）/ 缩小信息差是否仍被优先 → 报告给设计者（不自动触发修改）
- 验证：自动续轮独立给出候选清单；方向性自检报告可生成

## 4. 刚性条款清单（负向安全 · 维生系统 P0——不可被进化循环自我修改）

| 条款 | 理由（对应智能论条款） |
|---|---|
| fp 确定性直答优先于 bge 检索（round4） | 确定性 > 近似；验证单元稳态检测（§3.1） |
| 诚实边界 / 内容分级阈值 | 安全硬边界 |
| 设计者裁决密钥 fail-closed | 外部仲裁者（§1.4 设计者位置结构性隔离） |
| 五副本同步纪律 | 验证通过 ≠ 部署通过；输出单元连接一致性（§3.1） |
| 测试集回归无损标准（100%） | 固定裁判；回归=存在保护（§3.4 维生系统 P0） |
| 台账如实记录（不美化失败） | 诚实校准不虚高；记录单元不可静默修改（§3.2） |
| 方向性自检不自动触发修改 | §3.10 步骤8 原则：自检是反思输入，不是自动改写 |
| 递归深度默认 3 层 | §3.12 盲区85：超深层逻辑自指视为结构性盲区 |

修改任一刚性条款 = 设计者裁决（AEIS_DESIGNER_KEY），进化循环无权触碰。
