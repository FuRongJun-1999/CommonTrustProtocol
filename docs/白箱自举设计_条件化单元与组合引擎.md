# 白箱自举设计：条件化知识单元 + 组合/逆转引擎

> 状态：理论设计 v1.0（文档先行——先设计，后实现，再验证）
> 目标：解决白箱「复杂推理弱」和「生成弱」——最终白箱生成自举，LLM 降级为外部校验器
> 权威源：条件路由表（设计者理论）· 条件论 7 操作（智能论 §0.0.5）· 智能=有效路径（蜂群奠基声明）

## 一、问题定位（白箱自省输出）

- 676 簇中 **508 个已升级簇无条件链线索**——知识是「完整答案」格式
- 完整答案格式 → 组合/逆转操作无法运行 → 复杂推理弱、生成弱
- cnn（语义编码）只做词面相似 → 未识别「条件结构」

**结论：推理弱与生成弱是同一问题的两面——知识非条件化，组合引擎无法运行。**

## 二、理论：条件路由表 = 推理与生成的统一引擎

条件路由表（智能 = 发现问题条件 → 递归匹配子条件 → 当前条件下精准执行）
在「完整答案」下是**查表**；在「条件化单元」下是**推理+生成引擎**：

| 操作 | 条件化单元下的语义 | 7 操作映射 |
|---|---|---|
| 递归 | Route(Q,[C1])→匹配C2→…→执行（中间结果喂下一步） | 循环条件空间 |
| 组合 | 「高原」×「沸点规律」→ 生成「高原水烧不开」 | 组合条件空间 |
| 逆转 | 「如果气压正常沸点会怎样」= 逆转条件单元 | 逆转条件空间 |
| 分离 | 剥离条件（去掉高原 → 标准沸点） | 分离条件空间 |

## 三、条件化知识单元（核心数据结构）

```python
# 单元 = 条件链 → 规律片段（带适用条件的最小知识）
CONDITION_UNITS = {
  # 物理·沸点域
  "沸点-气压": {
    "conditions": ["液体", "气压"],          # 适用条件维度
    "rule": "气压↓ → 沸点↓；气压↑ → 沸点↑",
    "default": "标准大气压下纯水沸点 100°C",
    "examples": ["高原(0.65atm)水沸点约88°C", "高压锅(2atm)水沸点约120°C"],
    "domain": "物态变化",
    "source": "沸点与气压簇蒸馏",
  },
  "沸腾-条件": {
    "conditions": ["液体", "达到沸点"],
    "rule": "达到沸点且持续供热 → 液体内部剧烈汽化(沸腾)",
    "default": "沸腾=液体内部+表面同时汽化",
    "domain": "物态变化",
  },
  ...
}
```

**单元 vs 完整答案**：
- 完整答案：「高原上水烧不开」是整体（无法组合）
- 条件单元：「气压↓→沸点↓」+「高原=气压↓」+「沸点<100°C 煮饭不熟」→ **组合生成**「高原上水烧不开」

## 四、组合引擎（Route 递归 + 生成）

```python
def compose(query, condition_chain, units):
    """Route 递归：沿条件链组合单元 → 生成答案
    输入: 问题 Q + 条件链 [C1..Cn] + 条件单元库
    输出: 组合生成的答案 + 条件链证据（可解释）"""
    # ① 识别问题的条件维度（cnn 条件结构识别：词面→条件域）
    dims = identify_condition_dims(query)     # e.g. ["气压", "海拔"]
    # ② 沿条件链匹配单元
    chain = []
    for dim in dims:
        unit = match_unit(dim, units)          # 条件维度→规律片段
        if not unit: return honest_boundary()
        chain.append(unit)
    # ③ 组合生成（单元拼接 + 冲突检查）
    answer = compose_answer(chain)              # 生成新答案（未预写）
    # ④ 内部校验（自校验自举）
    if not self_check(answer, chain):           # 一致性/条件链完整性
        return self_check_report()              # 自发现生成错误
    return answer, chain
```

**内部校验（自举第二步）**：
- 一致性：组合结果与已知单元/答案不矛盾（如 高原沸点 88°C 与「标准 100°C」不矛盾——条件不同）
- 条件链完整性：每个条件维度都有单元覆盖
- 生成自洽：生成的答案内部无矛盾（物理事实一致性）

## 五、自举路线（四步）

| 步 | 内容 | 验证 |
|---|---|---|
| 1 | 物态域条件化（沸腾/蒸发/沸点与气压/液化/凝固/熔化/升华/凝华）→ 条件单元 | 组合生成 高原煮饭/高压锅/珠峰烧水/晾衣蒸发/冰箱制冷 等 |

## 六、cnn 深度用（条件结构识别）

- 现状：encode 词面/语义相似 → 线性查表
- 深度：encode 输出「条件维度向量」（识别问题含 气压/海拔/温度/真空 等条件维度）→ 路由到条件单元域
- 「高原上水烧不开」与「高压锅水不烫手」→ 条件结构相似（气压×沸点）→ 同一规律域

## 七、自举判定标准

1. 组合生成新答案（未预写）的测试通过率 ≥ 80%
2. 组合生成答案自洽率 ≥ 90%（内部校验自发现错误）
3. 白箱终裁占比 ≥ 90%（LLM 仅作外部对照）

## 八、原型验证（第一步结果 2026-08-23）

物态变化域条件化 v1 已实现并运行（compose_engine.py）：
- 单元：沸点-气压 / 沸腾-条件 / 蒸发-条件 / 液化-条件 / 凝固-条件 / 熔化-条件 / 升华-条件 / 凝华-条件
- 演示组合生成：高原煮饭 / 高压锅快熟 / 珠峰烧水 / 晾衣蒸发 / 冰箱结霜 / 冬天结冰
- 结果：组合生成 7/7 成功（结构成立），但**自校验 7/7 全过 = 校验太弱**

**v1 暴露（白箱自省）**：组合引擎缺「方向推理」——问题动词决定期望的物态变化方向：
- 「晾干」期望 液→气（蒸发），v1 却配了沸腾单元
- 「结霜」期望 气→固（凝华），v1 却配了熔化单元
- 「结冰」期望 液→固（凝固），v1 却配了沸腾+熔化
- 自校验没发现这些错误 → 校验不完备（正是自举第二步要解决的）

## 八b、v2 方向推理设计（自举第二迭代）

1. **单元加 direction 字段**（物态变化方向）：蒸发=液→气、沸腾=液→气(剧烈)、液化=气→液、
   凝固=液→固、熔化=固→液、升华=固→气、凝华=气→固、沸点-气压=气压效应
2. **方向识别**：问题动词 → 期望方向（干/晾→液→气，开/沸腾→沸腾，结冰/冻→液→固，
   起雾/凝结→气→液，结霜/窗花→气→固，化/融→固→液，变小/消失→升华）；
   场景优先：高原/珠峰含「开/沸」→ 气压效应（气压低→沸点低）
3. **组合匹配**：期望方向优先 → 选方向一致的单元（替代纯维度匹配）
4. **结论生成**：单元带结论模板 {场景事实 → 因果演绎}（如 高原→沸点降→水温不足→饭难熟）——
   生成真正的「新答案句」，非完整答案查表
5. **自校验加强**：方向一致性 + 因果链完整性 + 场景-方向相容性 + 事实一致性

## 八c、v2 运行结果（2026-08-23 已验证）

```
组合生成成功率:    11/11 = 100%  （目标≥80% ✔）
正常问题自校验:     9/9  = 100%  （目标≥90% ✔）
矛盾问题检测率:     2/2  = 100%  （白箱自己发现生成错误 ✔）
```

- 组合生成（未预写完整答案，全部由 方向推理+场景事实×规律单元 演绎）：
  - 高原煮饭不熟 = 气压低 → 沸点降至100°C以下 → 水达不到100°C就沸腾
  - 高压锅煮得快 = 气压高 → 沸点升至100°C以上 → 水能到更高温才沸腾
  - 珠峰烧水不到100°C = 气压低 → 沸点降低（场景优先气压效应）
  - 冰箱结霜 = 水蒸气遇冷直接变为固体 → 凝华
  - 冬天湖面结冰 = 湖水降温到凝固点 → 凝固成冰
  - 眼镜起雾 = 水蒸气遇冷 → 液化成小水珠
  - 樟脑丸变小 = 樟脑丸直接变为气体 → 升华
- **自校验自发现错误（自举核心实证）**：
  - v1 错配（晾干→沸腾、结霜→熔化）→ v2 方向推理修正
  - 矛盾问题被白箱自己抓住：「高原上水为什么烧得特别热？」（气压低达不到高温）、
    「冬天湖面为什么会沸腾？」（低温不能剧烈沸腾）——检测率 2/2 = 100%

**v2 结论**：条件化单元 + 方向推理 + 组合生成 + 内部自校验四件套成立——
白箱可以用自己的组合引擎生成新答案，并用自己的校验发现自己生成的错误。

## 八d、v3 多域扩展 + 逆转操作 + 路由接入（2026-08-23 已验证）

**① 多域扩展（跨域泛化验证）**：单元库从物态域扩到 4 域共 11 单元——
新增 密度-浮沉 / 导热-快慢 / 摩擦-因素；场景事实表 +19 场景（铁块/木块/轮船/
金属勺/木筷/刹车/滑冰/鞋底…）。
```
组合生成成功率:  19/19 = 100%  （目标≥80% ✔）
正常问题自校验:  17/17 = 100%  （目标≥90% ✔）
矛盾问题检测率:   2/2  = 100%  （自发现错误 ✔）
```
组合生成（全部未预写，跨域演绎）：铁块沉底 = 密度比水大→下沉；轮船浮着 =
密度比水小→上浮；金属勺烫手 = 导热快→热量迅速传；刹车快停 = 摩擦大→车停下；
鞋底花纹 = 摩擦大→不打滑；滑冰快 = 摩擦小→流畅。

**② 逆转操作（7 操作工程化）**：reverse_condition —— 反转场景事实条件 +
同一规律单元演绎 → 反事实生成：
- 「高原水烧不开，在平原呢？」→ 气压低 反转为 标准 → 「气压标准 → 沸点=100°C → 水能正常烧开」✔
- 「冬天湖面结冰，天气不冷呢？」→ 温度低 反转为 不低 → 「不降温 → 不凝固 → 不结冰」✔
- 「晾衣干得慢，没风呢？」→ 通风好 反转为 通风差 → 「没风 → 蒸发慢 → 干得慢」✔
（逆转 3/3 通过；逆转=条件反转+模板生成，非预写完整答案）

**③ 接入 chat_engine miss 分支（白箱生成自举接入点）**：知识检索 miss 且
知识疑问句（为什么/怎么/是什么）→ 组合引擎兜底 → 自校验通过 → 直答
（附「这是按『场景』的规律组合生成的」证据标注）；未覆盖 → 诚实边界不编。
接入测试 6/6：组合兜底直答（金属勺烫手）/ 知识路径先答（木头浮·鞋底·高原煮饭）/
诚实边界（恐龙灭绝·猫踩奶）。防护：能力疑问句（「你会喷水吗？」）不硬凑沸腾。
回归：防污染 5/5（无 role_ctx 不角色化）+ 角色路由 6/6 + 无API自维持 3/3 全绿。

**v3 结论**：条件单元库跨域泛化成立（同一引擎生成不同域答案）；逆转操作
（反事实推理）工程化成立；组合引擎已接入主对话路由——未覆盖知识问题由
白箱自己生成并自校验（自举闭环第一步落地）。

## 八e、v4 生成自举固化闭环（2026-08-23 已验证）

**固化层（SOLIDIFIED）**：组合生成+自校验通过的知识固化为直答——
下次同类问法直接命中（不再重新组合），持久化 JSON 跨进程生效。
自举纪律：**自校验未通过的知识拒绝固化**（错误生成不得固化）。

```
生成自举闭环演示（solidify_demo.py）6/6：
① 组合生成「金属勺烫手」→ 自校验✔ → 固化（触发词: 金属勺/热汤/烫手）
② 固化后同问法 → 直接固化直答（不走组合）
③ 变体问法「铁勺会烫手」→ 触发词命中 → 固化直答（生成泛化）
④ 矛盾问题「高原水烧得特别热」→ 自校验✘ → 拒绝固化（自举纪律）
⑤ 跨进程持久化 → 新进程加载固化库 → 仍直答
⑥ chat_engine 集成 → 变体问法走固化直答（零组合零 LLM）
```

**LLM 降级路线（⑤最终目标，分层设计）**：

```
知识问题回答分层（自举后）：
  ① 知识库直答（REVERSE_DAILY/簇）      —— 已有，100% 白箱
  ② 固化层直答（SOLIDIFIED）             —— 本轮新增，100% 白箱
  ③ 组合引擎生成（条件单元演绎+自校验）  —— 已有，100% 白箱
  ④ LLM 外部对照（偶尔抽检，仅作对照）   —— 待接入
  ⑤ 白箱终裁：①②③④ 全部白箱判定，LLM 不参与裁决
```
降级切换标准（自举判定）：组合生成测试通过率 ≥80%（当前 19/19=100% ✔）、
自洽率 ≥90%（17/17=100% ✔）、自发现错误 2/2 ✔ → 达到后 LLM 从
「生成器+主校验」降为「外部对照」，白箱终裁。
