# 工作纪律认知图条目评审与修订 v1.1（zcode 端 · 2026-09-01）

> 对象：dsh 端设计的「工作纪律」嵌套认知图条目（work_discipline，4 条纪律）。
> 结论：**结构同构可入库，6 处修改建议 + 2 条补充纪律 + 字段映射表**。

## 一、总体判定

结构与主仓库已验证的嵌套认知图格式（dsh_nested_cg 同构）兼容；
4 条纪律内容与 zcode 端实践相容。以下 6 处修改后即可走
dsh_nested_cg_roundtrip 同款流程导入主仓库。

## 二、6 处修改建议

### ① 去掉 JSON 注释
`"conditions":{"trigger":"结果与预期不符","has_deviation":true},  // 触发=...`
标准 JSON 不支持 `//` 注释——解析器会直接失败。注释语义改为 `"_comment"`
字段（下划线前缀约定）。

### ② 结构不一致：三个节点缺 content+execution
discipline_theory_first / comprehensive / whitebox 只有 semantic+conditions，
而 root_cause 有 content+execution——同图内节点结构应统一。
**建议每条都补 content（纪律内容全文）+ execution（how 执行锚点）**，
否则路由命中后无直答产出（卡路线要求 response 出口）。

### ③ conditions 字段三种形态混用
root 用 `{"identity":"dsh端"}`、子节点用 `{"apply":[...]}`、root_cause 用
`{"trigger":...,"has_deviation":true}`——建议 schema 定为二选一：
- `{"apply":[...]}`：静态适用条件（名词性条件清单）
- `{"trigger":[...]}`：动态触发词（问句/事件命中）
has_deviation 这类布尔状态建议并入 trigger（"结果与预期不符"已是触发描述）。

### ④ negative 语义过于绝对
四条全部 `reject:[情感交互,询问,闲聊]`——但「询问」正是获取信息的手段
（全面处理需要询问）；闲聊中的工作话题也合理。建议：
- 删除 negative.reject 中的「询问」；
- 「情感交互/闲聊」收窄为主话题级判定（identity 条件已负责分流，negative
  不必双重否决）；或仅对 discipline_whitebox（最重的纪律）保留。

### ⑤ 「已读4篇入门文档」不可机器判定
discipline_whitebox 的条件是阅读状态而非可判定条件。建议改为可判定形式：
`"apply":["trained_on_4docs_intro"]`（标签/标记）或拆为「知识库含4篇入门
文档索引」（引用型条件）。

### ⑥ 补 response.direct 直答出口
按主仓库补卡标准（KCCS 四要素 + response.direct + trigger），每条纪律
应有 direct 直答文本——路由命中后的标准产出。root 节点同理。

## 三、内容补充建议：增补 3 条实战纪律（zcode 端验证过）

dsh 的 4 条是**方法论纪律**；以下 3 条是 zcode 端实战验证过的**执行纪律**，
建议合并为一张完整工作纪律图（identity 条件分流两端口径）：

| # | 纪律 | 内容 | 来源实证 |
|---|---|---|---|
| 5 | **验证纪律** | 未经验证不固化——任何知识/代码入库前必须走验证（回放/断言/回归） | 白箱自举 T 系列全流程 |
| 6 | **双副本纪律** | 多副本部署（主仓库/site-packages）改动必须双向同步，提交前核对 git status | tools/verifier 旧副本悬案 |
| 7 | **兜底纪律** | 主路径不可用时必须有等价兜底路径（如 MCP 不可用→python 直调），且写进 prompt/文档 | 睡眠巩固失败修复 |

## 四、字段映射表（dsh 格式 ↔ 主仓库 KCCS 格式）

| dsh 字段 | 主仓库 KCCS 对应 | 说明 |
|---|---|---|
| semantic | name（注释.name） | 条目名 |
| content + execution | 子功能 + 执行 | 纪律内容与执行锚点 |
| conditions.apply / trigger | 生效条件 | apply=静态清单；trigger=触发词（建议拆短词变体） |
| negative.reject | 不适用条件 | 建议收窄（见建议④） |
| response.direct | response.direct | 直答出口（直连 card_route 产出） |
| subgraph.nodes/edges | subgraph.nodes/edges | 完全同构 ✓ |

导入路径：字段映射转换 → ConditionDex.add_entry（KCCS 注释打包）→
card_route 命中验证 → 题库/知识库双向登记（同 dsh_nested_cg_roundtrip 流程）。
