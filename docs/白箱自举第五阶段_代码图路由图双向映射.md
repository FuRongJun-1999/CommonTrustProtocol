# 白箱自举第五阶段 · 代码图↔条件路由图双向映射

> 文档先行 → 工程验证。codegraph 调用图与白箱条件路由图同构：
> **函数 = 条件单元**（参数=条件，被调函数=条件依赖），**Calls 边 = 条件链**。
> 落地价值：代码库 → 条件单元库 → 条件代数雅可比独立性判定 → **并行测试分组**
> （独立函数可并行测试——把 compose_parallel 的并行化能力应用到代码测试）。

## 一、同构映射

| 代码图（codegraph） | 条件路由图（白箱） |
|---|---|
| Function 节点 | 条件单元（{条件→规律}） |
| 函数参数 | 条件维度 |
| Calls 边（A→B） | 条件链（A 依赖 B 成立） |
| 调用面（改 B 影响谁） | 条件影响（B 变化影响哪些规律） |
| 函数独立性 | 条件独立性（雅可比混合偏导=0） |

## 二、模块 tools/code_route_bridge.py

| 函数 | 职责 |
|---|---|
| build_code_route_units | 仓库 IR → 代码条件单元库（{name, conditions:[被调函数], domain:file}） |
| code_jacobian_independence | 单元库 → 雅可比独立性（复用 condition_algebra 判定）→ 独立函数对 |
| parallel_test_groups | 独立性 → 可并行测试分组（贪心并组，同 compose_parallel） |

## 三、判定标准

1. 仓库 IR → 代码条件单元库（函数=单元，被调=条件）✔
2. 雅可比独立性：无共享依赖的函数独立（可并行测试）✔
3. 共享依赖的函数不并组（依赖同一函数 → 测试串行防冲突）✔
4. 并行测试分组：独立函数并组、依赖函数隔离 ✔
5. 测试全绿 → 提交 → 五副本同步
