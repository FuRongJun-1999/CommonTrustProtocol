|---|---|---|

## 1. 逐层对照：CSPRE vs 现有实现

| CSPRE 层 | 现有对应 | 判定 |
|---|---|---|
| 条件空间识别器 | `condition_frame.parse_conditions`（emotion/self/knowledge）| **半有**——缺学科级识别 |
| 脉冲生成器 | 无（graph_retrieve 无脉冲概念）| **真增量**（但可简化） |
| 同步搜索窗口 | graph_retrieve 全库扫描（dex_respond 遍历）+ 神经索引 | **真增量**——当前 O(n) 全库扫，无「先导航再激活」 |
| 结果聚合+白箱校验 | chat_engine._assemble + 诚实边界 | **已有**（诚实边界/导航降级 v1.17 已做） |
| 盲区发现 | blindspot 注册表（D-001）+ 蒸馏飞轮 | **已有**——CSPRE 的「警告」应接现有盲区注册表 |
| 节律/心跳 | SurvivalArbiter HEARTBEAT（存活）| **非增量**——搜索节律与存活心跳不同域，不建议混 |

**精确定位**：CSPRE 的真增量 = **① 学科级条件空间识别** + **② 定向检索（跳过无关 domain）**。
脉冲/同步窗口/节律是性能层增强，**先做①+②验证价值，再决定是否引入**。

---

## 2. MVP（第一步）：学科级硬分类 + 定向检索

### 2.1 学科级条件空间识别器（新增，挂 semantic_translate）

**复用已有**：
- `DOMAIN_ROUTE`（规范词→学科域映射，已有 31+ 规范词）
- 学科卡 `domain` 字段（编程语言/物理/数学/语文/英语…）
- `QUESTION_DOMAIN_PRIORS`（问题关键词→学科域先验，v1.17 已加编程域）

**新增**：`classify_condition_space(question) -> {domain, confidence}`
```
1. 用 DOMAIN_ROUTE 编码问题 → 命中规范词 → 学科域
2. QUESTION_DOMAIN_PRIORS 关键词匹配 → 补充学科域
3. 无命中 → "未分类"（走现有全库检索 + 诚实边界）
```

### 2.2 定向检索（graph_retrieve 加 domain 过滤参数）

```
graph_retrieve(dex, q, limit, domain_filter="物理学")
  → dex_respond 只遍历 domain=物理学 的节点（SQL 预过滤）
  → 神经索引只检索该 domain 子集
  → 预期：扫描量 34199 → 数百，耗时降 1-2 个数量级
```

### 2.3 验证实验（关键——先证明价值）

```
用 T2 1000 题 + 三类 294 题：
1. 现状基线：graph_retrieve 全库（已有数据：T2 75.8%）
2. 定向版：classify_condition_space → domain_filter 检索
3. 对比：准确率（keys 评分）+ 耗时
判定：准确率不降 + 耗时降 ≥50% → MVP 成立，继续脉冲层
      准确率降 → 分类器需调（阈值/召回）
```

## 3. 后续层（验证 MVP 后再做）

---

## 4. 诚实边界（不做的部分）

- **节律/心跳进搜索**：存活心跳是探活，搜索节律是路由——混用会引入无意义复杂度，不做
- **节点激活状态机**：MVP 阶段 SQL 过滤已足够，状态机留到节点数再涨时
- **跨实例搜索脉冲（蜂群）**：当前单实例运行，蜂群查询走 MCP 已够

---

## 5. 结论

CSPRE 方向正确，**第一步（学科级硬分类+定向检索）是真实增量且数据已就绪**
（domain 字段 + DOMAIN_ROUTE + QUESTION_DOMAIN_PRIORS 全部存在）。
建议：先写 `classify_condition_space`（~50 行），跑 T2 定向 vs 全库对比，
有数据再谈脉冲/同步层。不预先堆机制。
