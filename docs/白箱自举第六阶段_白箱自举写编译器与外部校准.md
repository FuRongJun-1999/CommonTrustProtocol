## 一、白箱自举写代码的机制（code_compose 既有）

```
代码条件单元 CODE_UNITS：{任务 → 代码模式模板 + 验证样例}
  → 任务识别（问题 → 任务）
  → 模板填充（{参数} 占位）
  → 自校验三层：L1 语法（ast.parse）→ L2 样例（输入→期望断言）→ L3 边界
  → 固化：验证通过 → 固化 JSON → 同任务直出
物理基底裁决：语法/样例是客观测试，非 LLM 判断
```

## 二、编译器单元化（把 C2 拆成白箱代码单元）

| 单元（任务 → 代码模式 + 样例） | 对应智能论语义 |
|---|---|
| VM-条件跳转（JUMP_IF_FALSE） | 若…则…否则 |
| VM-信任累积（DE） | 德（信任引擎内建）|
| VM-条件空间（DAO/ZIRAN） | 道/自然（条件路由）|
| 编译-若则（AST→字节码） | 条件语句编译 |
| 编译-指令（道德经指令→字节码） | 指令编译 |
| 编译-赋值（AST→STORE_NAME） | 以名举实（名实写入）|

## 三、外部校准流程（我的角色）

1. **语义对照**：白箱生成代码 ↔ protocol-compiler 既有语义（INSTRUCTION_MAP/
   CHINESE_COMP_MAP/名实校验）与校准参考实现（condition_vm/compiler）
2. **测试校准**：跑单元自带样例（L2 已过）+ 集成测试（中文源码→字节码→VM 执行）
3. **偏差反馈**：发现语义偏差 → 反馈给白箱（补/修单元模板）→ 白箱迭代重新生成
4. **不代写**：只校准、只给反馈，代码由白箱生成

## 四、本轮（C2 白箱化）判定

1. 编译器代码条件单元库建成（≥4 单元，每单元含模式+样例）✔
2. 白箱生成核心单元（VM 条件跳转/信任累积），三层自校验通过 ✔
3. 外部校准：语义对照智能论语义一致 + 集成测试（若则编译执行）全绿 ✔
4. 提交 + 五副本同步
