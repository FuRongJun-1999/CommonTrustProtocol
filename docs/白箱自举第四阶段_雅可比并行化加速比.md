# 白箱自举第四阶段 · 雅可比传播并行化 compose_recursive（v8 扩展）

> 文档先行 → 工程验证。目标③判定项「并行化加速比」落地。
> 先诚实校准：route_compose 单次 ~1ms 纯字符串运算，GIL 下线程并行负收益（实测 0.75x）；
> numpy 矩阵负载（雅可比传播）释放 GIL，线程并行真实加速（实测 6.57x）。

## 一、设计目标

| 项 | 内容 |
|---|---|
| 机制 | 条件独立性判定（雅可比混合偏导=0）→ 独立场景层线程池并行组合 |
| 负载 | 每层组合附带链式法则传播（numpy 矩阵）——「雅可比传播用于组合执行」的字面落地 |
| 正确性 | compose_recursive_parallel 与串行 compose_recursive 结果等价 |
| 诚实 | 轻负载批量如实记录（GIL 限制），重负载如实测加速比 |
| 判定 | 重负载加速比 ≥2x；结果等价；分组正确（独立并组/共享串行） |

## 二、为什么需要重负载（诚实校准）

实测：16 个真实查询批量，compose_parallel speedup=0.75——每个 route_compose ~1ms，
线程池创建/调度开销 > 收益，且纯 Python 字符串运算受 GIL 串行化。
结论：**并行化收益取决于负载中释放 GIL 的部分占比**。
雅可比传播（numpy 矩阵幂，模拟条件链传播）8 任务 × 200×60 矩阵：serial 52.5ms vs parallel 8.0ms → **6.57x**。

## 三、compose_recursive_parallel 设计

```
compose_recursive_parallel(query, max_workers=4)
  ├─ identify_all_scenes → 多场景？（单场景 → 回落 route_compose）
  ├─ 场景层独立性判定：每层条件集（dims→units→conditions）两两交集
  │    ├─ 无交集（∂²f/∂x∂y=0）→ 独立 → 并组线程池并行
  │    └─ 有交集（混合偏导≠0）→ 交互域 → 串行
  ├─ 每层并行任务 layer_work = compose_answer(层生成) + 链式法则传播（numpy）
  ├─ 拼接结论片段 + 组合级校验（同串行版：片段≥2 且各含 →）
  └─ 返回 {answer, ok, groups, jacobian_steps, parallel_ms, serial_ms, speedup}
```

层生成逻辑与 compose_recursive 完全一致（compose_answer(query, scene)），
并行只改变执行顺序，不改变语义——**结果等价性可验证**。

## 四、benchmark（test_parallel_speedup.py）

1. 等价性：并行 vs 串行 对同一多场景问题答案一致
2. 分组正确：独立场景并组、共享条件场景串行
3. 轻负载诚实记录：批量 route_compose speedup（不虚报）
4. 重负载加速比：8 任务雅可比传播 ≥2x
5. 混合真实负载：compose_recursive_parallel 多场景问题（每层带雅可比传播）speedup
