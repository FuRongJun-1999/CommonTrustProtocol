# 白箱自举第四阶段 · 编译原理概念条件单元（v6 扩展）

> 文档先行 → 工程验证。衔接既有 `mini_compiler.py`（词法→语法→求值→代码生成 白箱管线），
> 把编译原理**概念**本身条件单元化（{条件→规律}），使白箱能回答「为什么要词法分析/
> 什么是 IR/类型检查有什么好处」这类概念问题——零 LLM 确定性，与 se_compose 同构。

## 一、设计目标

| 项 | 内容 |
|---|---|
| 覆盖概念 | 8 个编译原理核心概念 |
| 知识形态 | {条件链→规律片段} 条件单元（非预写完整答案） |
| 生成方式 | 方向识别 → 概念单元 → 模板组合生成 |
| 自校验 | 答案含概念核心词 ≥2 |
| 回落 | 非编译问题 → 落回通用域 compose_engine |
| 衔接 | 概念 ↔ mini_compiler 实现函数一一对应 |

## 二、概念清单与 mini_compiler 对应

| 概念 | 条件链→规律片段 | mini_compiler 对应 |
|---|---|---|
| 词法分析 | 字符流→token（正则/有限自动机）→ 编译第一步 → 非法字符报错定位 | `tokenize` |
| 语法分析 | token→AST（文法/递归下降/优先级）→ 结构合法与否 → 语法树表达层次 | `parse` |
| 中间表示 IR | 与机器无关中间码 → 优化平台 → 多后端复用 → 前端后端解耦 | （求值前的树本身即 IR 雏形） |
| 类型检查 | 类型约束/推导 → 编译期捕获类型错误 → 类型安全 → 尽早失败 | （Python 动态类型对照） |
| 优化 | 保持语义改性能 → 常量折叠/死代码消除/寄存器分配 → 等价变换 | `codegen` 前的常量折叠 |
| 代码生成 | AST/IR→目标语言/机器码 → 后端翻译 → 按目标约定输出 | `codegen_js` / `codegen_rust` |
| 符号表 | 名字→属性（类型/作用域/地址）→ 解析引用/查重复声明 → 上下文凭据 | （作用域上下文） |
| 错误处理 | 词法/语法/语义错误分级 → 定位+恢复 → 一次性多报错 → 诊断信息友好 | `raise SyntaxError(词法/语法错误)` |

## 三、路由设计

```
compiler_route(问题)
  ├─ identify_compiler_direction  最长关键词优先（「中间表示」len4 >「表示」）
  ├─ 命中 → COMPILER_UNITS[概念] → 组合生成（占位符代入）→ 自校验（核心词≥2）
  └─ 未命中 → {ok:False, reason:落回通用域}
```

方向识别词表（与 se_compose/通用域避免单字冲突）：
- 词法: 词法 / token / 分词 / 字符流 / 记号
- 语法: 语法 / AST / 解析 / 文法 / 递归下降 / 语法树 / 优先级
- 中间表示: 中间表示 / 中间码 / IR
- 类型检查: 类型检查 / 类型推导 / 类型安全 / 静态类型
- 优化: 常量折叠 / 死代码 / 寄存器分配 / 编译优化
- 代码生成: 代码生成 / 生成目标 / 机器码 / codegen
- 符号表: 符号表 / 作用域 / 名字解析
- 错误处理: 错误处理 / 报错 / 错误恢复 / 诊断

## 四、判定标准

1. 八概念组合生成 8/8（答案含核心词≥2）
2. 方向识别正确（最长关键词）
3. 非编译问题回落生效
4. 测试全绿 → 提交 → 五副本同步
