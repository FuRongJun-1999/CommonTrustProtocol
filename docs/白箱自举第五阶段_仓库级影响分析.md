# 白箱自举第五阶段 · 仓库级影响分析（跨文件调用面）

> 文档先行 → 工程验证。单文件 impact_analysis（BFS 逆向调用面）升级到**仓库级**：
> 改 utils.py 的 parse → 算出受影响的文件集合（main.py）与调用链——
> codegraph impact_analysis 的完整价值（改前先算影响面），白箱零 LLM。

## 一、设计

```
仓库 IR（analyze_repository：函数带 file 归属）
  ├─ 合并仓库调用图：函数名 → 定义文件（跨文件函数名全局索引）
  ├─ 逆向 BFS：target → 所有调用者（含跨文件，带深度）
  └─ 输出：{target, target_file, callers[{name, file, depth}], files_affected[]}
```

## 二、模块扩展（codegraph_white.py）

| 函数 | 职责 |
|---|---|
| impact_analysis_repo | 仓库级影响分析：改函数 → 跨文件调用面（按文件分组） |

## 三、判定标准

1. 改 utils.parse → 调用面含 main.process（跨文件定位）✔
2. files_affected = [utils.py, main.py]（定义文件 + 受影响文件）✔
3. 深度正确（直接调用者 depth=1）✔
4. 无关函数（models.Item 无调用链）不在调用面 ✔
5. 测试全绿 → 提交 → 五副本同步

## 四、价值

单文件 → 仓库：影响分析升级为「改一个函数，算跨文件波及面」——
代码编写的工程闭环（改前影响评估，白箱确定性）。
