# 条件节点化设计（GPT 审查·第二优先级）

> 状态：理论设计 v1.0（文档先行——先设计，后实现，再验证）
> 来源：GPT 审查「知识 vs 条件」审查点 + GPT 优先级回复（第二优先级·GPT 最感兴趣项）
> 权威源：条件论（条件=知识适用性约束）· 白箱自举 compose_engine 条件化单元（已示范格式）

## 一、问题：条件现在是「属性」不是「对象」

现状：ConditionSpace（observation_position/tool/time_window/existence_constraint）
是**节点/边的属性**（内嵌）：

```
知识节点
 ├─ observation_position
 ├─ observation_tool
 ├─ time_window
 └─ existence_constraint
```

局限：
1. **条件不可被独立发现/组合/验证/继承**——只能是知识的 metadata
2. 条件之间无结构（无法表达「条件A+条件B→条件C→理论X适用」）
3. 白箱自举的 compose_engine 条件化单元 `{条件链→规律片段}` 已示范条件作为独立单元的格式，但未入主库

## 二、目标：条件成为「可学习的认知对象」

```
条件节点（condition）        ← 可发现/组合/验证/继承/修改
    ↓ applies_to（适用关系）
知识节点（knowledge）
    ↓ implies（推理规则）
结论/行动
```

- **条件节点**：独立节点类型（NodeType.CONDITION），content 为条件描述
  （如「气压低」「海拔高」「温度>100°C」），带 ConditionSpace 自身
- **applies_to 边**：条件 → 知识（适用关系，替代属性内嵌）
- **组合**：条件A+条件B → 条件C（条件空间组合操作，condition_space_operate 已有 compose）
- **发现**：预测误差自动条件化（已实施 v1.16）产生的 `condition_candidate` 节点
  → 经验证提升为正式条件节点（candidate → verified condition）

## 三、对接 compose_engine 条件化单元

compose_engine 已示范格式：

```python
CONDITION_UNITS = {
    "沸点-气压": {
        "conditions": ["气压", "液体"],        # 条件链
        "rule": {"低": "沸点降低", ...},        # 规律片段
        "conclusion": {"低": "气压低 → {液体}沸点降至100°C以下 → …"},
    }
}
```

条件节点化后，条件单元映射到主库：

```
条件节点「气压低」──applies_to──→ 知识节点「沸点-气压规律」
条件节点「液体」──applies_to──→ 知识节点「沸点-气压规律」
（多条件 → 同一知识 = 条件链）
```

组合演示（条件A+条件B→条件C）：
```
条件「高原(气压低)」+ 条件「高压锅(增压)」→ 组合条件「高原+高压锅」
    → 知识「沸点随气压变化」适用 → 结论「高压锅在高原能煮熟」
```

## 四、实施路径（分步）

1. **NodeType 加 CONDITION + applies_to 边类型**（core.py）
2. **条件节点注册**：`declare_condition(content, condition_space)`——
   condition_candidate 节点经验证提升（verify 后 candidate→condition）
3. **applies_to 边**：条件→知识（替代属性内嵌；旧节点条件空间保留兼容）
4. **条件组合**：复用 condition_space_operate（compose 操作）+ 组合引擎递归
5. **验证**：条件节点可发现（预测误差自动条件化已产出 candidate）→
   提升 → 组合生成（compose_engine 对接主库条件节点）

## 五、与白箱自举第三阶段的关系

- 条件节点化 = 把 compose_engine 的**条件化单元格式引入主库**——两个体系合一：
  - compose_engine（组合引擎）：条件单元 → 组合生成 → 自校验 → 固化
  - 主库（语义时空图）：条件节点 → 适用关系 → 知识节点 → 推理规则
- 预测误差自动条件化（已实施）是条件节点发现的**入口**：
  `误差 → 缺失条件 → condition_candidate →（验证）→ 正式条件节点`

## 六、判定

- 条件节点可被独立创建/查询（declare/recall）
- 预测误差产出的 candidate 可提升为正式条件节点（验证通过）
- 条件组合（A+B→C）可生成新结论（组合引擎演示）
- 主库知识检索可沿 applies_to 边由条件路由到知识
