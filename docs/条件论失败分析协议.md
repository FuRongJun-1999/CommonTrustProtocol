# 条件论失败分析协议 v1.0
## —— 从行为层归因（症状）到条件层归因（根因）

> 2026-08-18 · 设计者洞察：
> 「我们之前的归因一直停在行为层（症状），没到条件层（根因）。
> 9 条机制注入全部是无条件规则——没有标注『这条纪律在什么条件下成立』。
> 灵枢的核心理念『一切知识都有条件空间』，恰恰在机制注入层被丢了。」

---

## 0. 为什么行为层归因不够

| 归因层级 | 例子 | 缺陷 |
|---|---|---|
| 行为层（症状） | 「只读不写」「搜索循环」「部分执行」 | 描述现象，不解释为什么 |
| 机制层（仍是行为） | 「收集终止纪律」无条件规则 | 治标——模型不知道何时触发 |
| **条件层（根因）** | 观测位置未知→搜索对抗不确定；沙箱假象→当真障碍；完成条件未对齐 | 失配维度明确，机制可针对性补条件 |

**判定标准**：如果一条「纪律/规则」没有声明适用条件，它就是无条件规则——
模型无法判断何时触发，注入等于「读到但不知道何时用」（呼应读而不应用现象）。

## 1. 三方条件空间（失败分析第一问）

任何失败，先分别列出三个条件空间：

| 条件空间 | 定义 | 示例（tax_prep_summary） |
|---|---|---|
| **任务真实条件** | 环境实际是什么（客观） | 1099 数据源客观存在（Payment Log 表格在库中） |
| **模型感知条件** | 模型以为是什么（主观） | 数据源坐标未知→用无限搜索对抗不确定性 |
| **机制声明条件** | 机制声明了什么（规范） | 执行闭环只说「信息齐了要写」，没定义「观测到什么位置算齐」 |

**失败 = 三方条件空间失配**。

---

## 2. 五失配维度（失败分析第二问）

失配发生在哪个条件维度：

| 维度 | 含义 | 案例 |
|---|---|---|
| **观测位置** | 数据源/目标在哪（坐标未知→搜索） | tax_prep_summary：数据存在但坐标未知 |
| **观测工具** | 用什么工具观测（工具发现失败→循环） | 搜索循环的源 |
| **时间窗口** | 何时生效（时序/时效） | 更新未生效（写后没回查） |
| **存在约束** | 什么是真实/可信（沙箱假象） | hubspot_sync：模拟环境返回值被当真障碍 |
| **条件边界** | 完成/成功的边界（断言为界） | docusign：发通知就收尾≠任务完成 |

---

## 3. 三问协议（失败分析流程）

```
第 1 问：三方条件空间分别是什么？
        任务真实条件 / 模型感知条件 / 机制声明条件

第 2 问：失配发生在哪个条件维度？
        观测位置 / 观测工具 / 时间窗口 / 存在约束 / 条件边界

第 3 问：机制注入缺什么条件声明？
        哪条机制无条件运行，导致在失配条件下失效 → 补条件
```

**输出**：每条失败 → （失配维度, 缺失的条件声明, 机制修补方案）。

---

## 4. 三个案例（2026-08-18 桥测试）

**① tax_prep_summary——失配维度：观测位置**
- 任务真实：1099 数据源客观存在
- 模型感知：坐标未知（任务文本没给 sheet 名）→ 无限搜索对抗不确定性
- 机制缺口：执行闭环没说「观测到什么位置算齐」→ 补「观测位置条件：坐标确定后才执行写」

**② hubspot_mailchimp_sync——失配维度：存在约束误判**
- 任务真实：模拟沙箱，工具返回值即真实
- 模型感知：UUID 格式/Drive 失败是真障碍 → 123 次调用研究环境
- 机制缺口：没声明「模拟环境返回值可信度」→ 补「存在约束条件：沙箱返回值=环境真实」

**③ docusign_deal_workspace——失配维度：条件边界**
- 任务真实：全部断言（通知+workspace+成员添加）
- 模型感知：已发通知 → 收尾
- 机制缺口：没把「完成=任务全动作清单（以断言为界）」声明为条件边界 → 补「条件边界：完成以断言全过为界」

## 5. 机制注入的条件声明规范

**每一条机制/纪律注入时，必须带「适用条件」声明**（v1.1 task_discipline.json 已落地）：

```
纪律：执行闭环——信息收集完成后必须执行写操作
适用条件：观测位置已确定时生效；位置未知时应先定位，而非硬写或无限搜索
```

**无条件规则 = 读而不应用**（模型读到但不知道何时用）；
**带条件规则 = 模型能判断触发时机**（条件空间即触发时机）。

---

## 6. 与灵枢体系的关系

- 这是条件论（ConditionSpace）在**失败分析**与**机制注入**两处的应用：
  1. 失败分析：三方条件空间对比 → 失配维度定位
  2. 机制注入：每条纪律带 condition 声明（同 ConditionSpace.existence_constraint）
- 与「搜索收敛纪律」闭合：观测位置未知的搜索循环 = 收敛纪律的触发条件之一
- 与「蒸馏机制」闭合：失败 → 条件层根因 → 带条件的纪律 → 不再犯
