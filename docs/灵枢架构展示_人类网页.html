核心命题：确定高效后，维持自身——白箱规则确立后的确定性执行 （零思考、可解释、自维持），这是 LLM 做不到的。

第一幕架构全景

五层结构，回答「为什么这样分层」：黑箱不可信 → 知识条件化写入、 路由命中可解释（白箱化）；规则会漂移 → 自维持层锚定（传感器发现退化、 三臂终裁、快照可回滚）；LLM 只做表达通道——确定性执行交给白箱规则。

第三幕一个中文程序的生命

protocol-compiler（白箱自举第六阶段完整产出：词法/语法/编译/VM/ 调试器/分析器，78/78 测试全绿）。以递归阶乘为例，四阶段逐层可追溯：

① 词法
字符流 → 记号流，中文标识符/全角括号/运算词各自成类，逐 token 可对照词法规则
② 字节码
函数定义编译为跳转+入口结构；递归调用 = CALL (1, ['n'])——逐指令可读
③ VM 执行
栈机 + 符号表：symbols["结果"] = 120.0，名实校验全程在场
④ 验收
基准 120/15/11/1/8 全绿（T9-2 自验收 5/5 实证，期望值可手工验算）

诚实面：本轮实测发现该编译器四个调用限制（多参数/嵌套/ 若则非递归/多函数）——定位方法为逐变体字节码对照。白箱的含义是 缺陷也可定位，黑箱系统同类问题只能看到「输出不对」。

附为什么不用 benchmark 测灵枢

T8→T9→T9-2→T10 四轮实验（30 题/6 项目/编译器域/复杂场景， GLM + DeepSeek 双端交叉）构成「单任务测量失效」的完整证据链： 简单任务上机制注入是纯固定开销；任务难度是相对模型的；验收器缺陷 会系统性污染数据。测得的有效信号反而支持白箱： 知识密集域输入 token −40%、轮次 3 vs 6、优势域项目级 A 反超—— 但这些都只是副产品。灵枢的价值在跨时间持续迭代，在每步决策可追溯， 在确定高效后的零思考维持。
