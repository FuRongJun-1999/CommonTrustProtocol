## 一、先把系统本身放进条件空间（skill 步骤 1）

任何设计若不先声明"在什么条件下成立"，就会把局部当全局。记忆系统的条件空间：

| 维度 | 本系统的取值 | 越界即失效 |
|---|---|---|
| **观测位置** | 状态治理层（记·裁·维），非生成层 | 一旦开始"生成答案"，白箱性即失 |
| **观测工具** | 确定性判定、台账回读、可复跑探针 | 引入不可复现的判据（如 LLM 打分）即失 |
| **时间窗口** | 跨会话持久；单次判定绑定 `snapshot_id` | 跨快照比较而不记录快照，结论无效 |
| **存在约束** | 私有库可存隐私；公开面不得含隐私/内部标识 | 越界即违反纪律 9/14 |

**推论**：本系统的所有结论都带条件——"某知识成立"必须能读出它的观测位置与时间窗，否则只是一条未标条件的断言。

## 二、白箱三问 → 接口必填字段（skill 步骤 2）

三问不是口号，要能机械检查。每个接口的返回体必须能回答：

| 三问 | 对应字段 | 缺失时的处理 |
|---|---|---|
| ① 依据什么（锚定） | `evidence_ref[]`（节点 id／台账条目／探针读数） | 无 → 不得 ACCEPT |
| ② 在什么条件下成立 | `condition_space`（四维）＋`snapshot_id` | 无 → 判定降级为 DEFER |
| ③ 错了怎么办（验证闭环） | `verify_path`（如何复跑、如何回滚） | 无 → 写入门直接拒收 |

**新增硬规则**：`condition_space` 从"建议携带"升级为**必填**。缺它即视为脱离条件空间的知识——按智能论 0.0.5，这比"记得多"危险得多。

## 三、四态裁决 → 写入门（skill 步骤 3）

v1 的写入门是"重要性闸门"（单点阈值）。本版把它升级为**四态裁决**，因为单点阈值只能回答"重不重要"，不能回答"该不该"：

```text
候选记忆 C
 ├─ ① 与已固化的 protected 条目存在能力级冲突？   → REJECT（负路由优先）
 ├─ ② 无法建立判断路径（无可用条件链/未编码域）？  → BLINDSPOT
 ├─ ③ 候选存在但区分条件未定（同槽异值）？        → DEFER（入审核队列）
 └─ ④ 条件匹配＋知识存在＋三问可答                → ACCEPT（落 live）
```

**顺序不可颠倒**：先拒绝后接受。理由（引 6章.2）：能证明"不适用"时不必进盲区判断，**拒绝比猜测更省导航税**。

**纪律**：资格由条件证据裁决，不由相似度裁决——相似度可以产生候选，但不能单独授予写入资格。

## 四、四动作接口契约 v0.2

### 4.1 取 Retrieve

```text
retrieve(query, scope, k, condition_space, snapshot_id) -> Envelope
Envelope = { operation_status, completeness, candidates[], hit_count|null,
             condition_space, snapshot_id,
             qualification: null, qualification_evaluated: false,
             verify_path }
```

不变量：I1 非 success ⇒ hit_count=null；I2 completeness=false 不得进入零命中路径；I3 候选非空≠有该知识。

### 4.2 算 Judge（浅裁，零 LLM）

```text
judge(claim, evidence_ref[], condition_space, snapshot_id) -> Verdict
Verdict = { state, basis[], reason_code, condition_space, snapshot_id, verify_path }
```

不变量：I4 逐位可复现；I5 无证据只能 DEFER/BLINDSPOT；I6 BLINDSPOT ≠ 知识不存在。
**新增 I11**：judge 的输入若缺 condition_space，必须返回 DEFER 而非猜测。

### 4.3 改 Revise（四层门控）

```text
revise(node_ref, change, authority, condition_space) -> Revision
Revision = { verdict, state_from, state_to, rollback_token, ledger_entry, condition_space }
```

四层：判定（verify 三态）→ 状态机（逐级，不跳级）→ 回滚（token，前像=执行时点）→ 授权（三档自治＋队列）。
不变量：I7 退役不删除；I8 无 `_evolution` 记录即未发生。

### 4.4 存 Commit（四态门）

```text
commit(node, evidence_ref, condition_space, snapshot_id) -> CommitResult
CommitResult = { committed, moved_to: live|review_queue|rejected|blindspot,
                 node_id, decision_state, ledger[] }
```

不变量：I9 写入即留痕；I10 committed=false 不得称已固化；**I12** `moved_to` 必须回显四态裁决结果，不得只报布尔。

## 五、三层记忆边界（引协作架构 v0.1 §6.2，落到接口）

| 层 | 谁能读 | 谁能写 | 禁止进入 |
|---|---|---|---|
| **个人长期**（私密） | 仅该 session 持有者 | 本人 | 群聊上下文、团队卡片、任何公开面 |
| **内部团队**（同库隔离） | 该 session 持有者＋admin 裁剪注入 | 该 session 持有者（受 layers_allow 约束） | 个人私密条目、未验证结论、外部原始过程 |
| **对外公共**（公开可查） | 任何人 | 仅命令面状态变更 | 内部 ID／路径／信任分 |

**接口落地**：`retrieve` 的 `scope` 必须显式给出 session 与 layer；**层级不越读**——项目不得读团队 L0 之外的团队 session，admin 默认不读项目 L1；跨层连接只靠 `derived_from`，不靠放宽过滤。

### 5.1 群聊与记忆的接缝（引《群聊协议_v0.1》）

群聊是**交互面**，不是记忆的写入方。三条纪律：

1. **群聊 session 独立且不可越读**：群永不读成员私聊条目；成员私聊亦不自动进群聊上下文。
2. **群聊不写账本、不下调度**：唯一出口是 admin 写成 spec 走蜂巢；群聊不得产出 claimed.lock / depends_on / 账本事件。
3. **沉默也要留痕**：PASS 必须落盘——否则「没说话」与「没参与」在审计面上不可区分（与账本 append-only 同源）。

**对接口的影响**：retrieve 收到群聊 session 时，必须显式声明可见范围；跨到个人层即视为越界，接口应拒绝而非静默放行。

## 六、账本单向性（不可协商的三条）

1. **镜像只读**：内部面不产生账本事件，不改不删不重排公开面。
2. **纠正靠追加**：无"撤销"，判错只用新事件覆盖。
3. **镜像是公开面的纯函数**：可从公开面完整重建；不得存在"只在内网可见"的原始事实。

**能红判据**：删掉镜像后从公开账本重建 → 必须逐字段一致；不一致即非纯函数。

## 七、晋升与退役

**晋升**（外部→内部）：四闸全过 + 可复跑读数 + 状态为 `settled`（非 disputed）→ 写团队 L1，`importance=0.7`（≥0.7 触发 protected），`derived_from` 指向账本事件。**未验证不写入**；确需留档只能进 `layer=contextual` 并显式标注"未验证"，且不得被当已固化知识召回。

**退役**（≠删除）：
- 可退役：① 被更新卡片取代且溯源完整；② 纯细节无下游引用（L2 需主动 scrub）；③ 长期零召回且与未决项无关。
- **不可退役**：① 公开面声誉事件；② 验收/裁决留痕；③ 任何被 L0 引用的卡片。

理由：append-only 的意义不在"记得多"，而在**任何时刻都能证明当时记的是什么**。

## 八、能红判据（每条接口一条，必须能构造出必失败的检验）

| 接口 | 能红检验 | 失败含义 |
|---|---|---|
| retrieve | 注入 timeout → 断言 `hit_count == null` 且候选不得被读作"没有" | 失败 = 故障被折算成零命中 |
| retrieve | 删掉 `snapshot_id` → 断言接口拒收 | 失败 = 跨快照比较无防护 |
| judge | 同一输入跑两次 → 断言输出逐字节一致 | 失败 = 引入非确定性判据 |
| judge | 喂空 `evidence_ref` → 断言只能 DEFER/BLINDSPOT | 失败 = 无账强答 |
| judge | 喂虚构实体查询 → 断言不得 ACCEPT | 失败 = 结构化证据冒充语义证据 |
| revise | 尝试跳级（active→archived）→ 断言被拒 | 失败 = 状态机形同虚设 |
| revise | 撤回 rollback 能力 → 断言拒绝执行改动 | 失败 = 不可逆改动被放行 |
| commit | `committed=false` 时对外声称已固化 → 断言审计能捕获 | 失败 = 审核队列被绕过 |
| 晋升 | 构造 `disputed` 交付 → 断言无法晋升 | 失败 = 闸失效 |

## 九、非职责判据（含负路由）

三条准入判据（v0.1 保留）：① 需要跨会话持久可审计状态吗？② 必须确定性可复跑吗？③ 会改变"谁有权改"的契约吗？有一条为"否/是"即不进。

**本版新增负路由判据**：任何候选需求，先问"能否证明它不适用"——能证明即 REJECT，不必进入能力评估。这与四态裁决同构：**拒绝优先于接受**。
