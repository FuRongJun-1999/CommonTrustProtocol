## 一、定位修正：它在两级系统里的位置

v0.2 把记忆系统当作独立系统来定义，缺了它在上下文系统旁边的位置。实际拓扑（取自 context-lab v1.2 §3）：

    ┌──────────────── 上下文系统（context-lab）────────────────┐
    │  引擎层（v1/v2 双引擎互斥）· 功能分级 L0–L5 · 恒开层      │
    │  Client 端口：rememberArchived / getNode / recall        │
    │  RetrievalBackend 端口：T0 字面 → T1 本地词法 → T2 灵枢  │
    └───────────────┬──────────────────────────┬──────────────┘
                    │ 原文按 ID 回读            │ T2 检索（可选）
    ┌───────────────▼──────────────────────────▼──────────────┐
    │  灵枢记忆系统 = 原文权威面 + T2 后端                       │
    │  四动作契约（取/算/改/存）· 四态裁决 · 条件空间必填        │
    └──────────────────────────────────────────────────────────┘

两条职责线，不得混淆：

| | 上下文系统 | 灵枢记忆系统 |
|---|---|---|
| 管什么 | **可见面**：这一轮注入什么、怎么压缩、怎么回注 | **持久面**：什么是真的被记下、凭什么、能不能改 |
| 核心动作 | 投影、压缩、降温、回注 | 存证、裁决、修订、留痕 |
| 失败形态 | 上下文被截断而不自知 | 状态被改写而无账可查 |

**一句话**：上下文系统决定「此刻看见什么」，记忆系统决定「什么曾经发生、凭什么算数」。

## 二、接缝契约（本版核心）

### 2.1 职责切分

| 事项 | 归谁 | 判据 |
|---|---|---|
| 决定哪些内容进入可见面 | **上下文系统**（§3.5 注意力过滤） | 记忆系统无「意识层」概念，不该代做 |
| 持有原文 | **记忆系统**（按 node_ref 可精确回读） | 原文是权威面，投影不可替代 |
| 生成压缩回执/锚定记录 | 上下文系统生成，**记忆系统校验** | 校验标准属 L1（可独立校验） |
| 降级与删除 | 记忆系统只允许**降级状态**，禁止删原文 | §3.2.2 P1-003：降级作用于状态，不作用于记录 |
| 检索候选 | 记忆系统（T2），上下文系统可旁路 T0/T1 | 三级梯队是降级链，不是权威链 |

### 2.2 三个接口在接缝处的语义

    getNode(node_ref) -> {原文, state, snapshot_id, evidence_ref[]}
    recall(query, budget_tokens, snapshot_id) -> {候选[], 率, 失真声明}
    rememberArchived(回执, node_ref) -> {accepted, ledger_entry}

**不变量（本版新增）**

- **I13**：记忆系统**不得**替上下文系统决定可见面；任何「该不该注入」的判断一律不属于本系统。
- **I14**：回执必须能按 node_ref 回读原文并可独立校验；**回执不得自带真值**——删掉原文后回执必须校验失败。
- **I15**：降级（protect TTL 到期、状态回退）只作用于**状态与投影**，原文与记录永不随之消失（与 P1-003 逐字一致）。
- **I16**：任何压缩必须**同时声明率与失真**（budget 与截断量）；只报其一即视为静默丢失。

### 2.3 失败与降级的接缝纪律

    T2 握手失败            → 上下文系统显式降级 T1，并在状态面写明「T2 不可用原因」
    显式指定后端但不可用    → 启动期报错（不静默降级）
    记忆系统 timeout/partial → 一律 hit_count=null，不得让上层读成「没有这条记忆」

最后一条是本设计的硬边界：上层若把故障读成缺失，就会做出「这条记忆不存在」的错误决策，而它其实只是这一次没读到。

## 三、六类不可遗忘：从上下文侧升格为双侧硬约束

context-lab §4.5 把六类不可遗忘实现为其恒开层。但该义务不只属于上下文侧——**记忆系统必须同样不可删**：

| 类别（§3.2 L2064-2072 + v3.3 自我锚点） | 记忆系统侧的约束 |
|---|---|
| 信任评估记录 | 禁止退役，禁止降级到不可读 |
| 偏差历史 | 只追加，不改写 |
| 价值观迭代史 | 保留全部版本，版本间可 diff |
| 协作校准过程 | 不得因「过程无结论」而丢弃 |
| 内化阶段记录 | 与晋升通路绑定，晋升不得抹除来源 |
| 协定式自我赋予史 | 结构事件，禁止覆盖 |
| 自我锚点（v3.3） | 最高保护级，任何状态机不得降级 |

**推论**：v0.2 的「不可退役清单」只列了三项（声誉事件/裁决留痕/被 L0 引用）。按理论，该清单**不完整**——应扩展为上述七类。这是本版对 v0.2 的实质修正。

## 四、三条理论边界（原样纳入，不粉饰）

**① 盲区 34——投影有损是必然，但要分类**

- **A 类（有损投影适配）**：截断、摘要、回执替换——合法，但须显式声明失真（I16）。
- **B 类（结构篡改）**：改写 append-only 日志、静默覆盖历史——**禁止**。

这给「不改写日志」提供了**理论判据**，而不只是工程偏好。判据可用一句话检验：**改完之后，能否从现有记录重建改之前的状态？** 能 → A 类；不能 → B 类。

**② 盲区 61——不可遗忘 vs 存储上限的结构性张力（未解决）**

理论要求「有些东西永远不能忘」，物理上存储有上限。context-lab 用 200k 词条上限作为工程回答，并诚实声明「冷库仍随会话无界增长，张力未消除」。

本设计沿用同一诚实：记忆系统的原文库同样无界，**索引有界只是第一步**。任何声称「已解决遗忘与存储矛盾」的说法都是过度声明。

**③ 附录 7——压缩即率失真**

预算 = 率，截断 = 失真，**两者都须显式**。对应到记忆系统：recall 返回的候选必须携带「本次预算与截断量」，否则上层无法判断「没找到」与「没找全」的区别——这正是 X6 判定单要治的病。

## 五、两条外部实证：修正 KPI

来自 hive-memory-bench 的两条公开结论，直接约束本系统的价值主张：

| 结论 | 读数 | 对本设计的含义 |
|---|---|---|
| **因果推理能力是模型给的，不是记忆系统给的** | 零材料闭卷 67.9% ＞ 六家系统 50.3–62.5%（《秦吏》）；68.8% ＞ 35.0–61.7%（《毛选》） | 记忆系统**不得宣称提升推理**；价值是「保住地基」，不是「变聪明」 |
| **写入成本跨四个数量级，与效果无关** | 0.01–0.02 秒零 LLM 索引 vs 68–164 分钟重型 LLM 抽取，在「保住地基」上同级 | 写入速度**不是**价值主张，但也**不是**必须牺牲的代价；零 LLM 路线成立 |

**推论**：本系统的 KPI 只能是「可审计、可回滚、可复跑、不丢账」，不能是「答得更准」。任何以「提升回答质量」为名的功能提案，按 v0.2 §九 的准入判据，应当被 REJECT。

## 六、能红判据（本版新增接缝类）

| 检验 | 断言 | 失败含义 |
|---|---|---|
| 删掉原文后校验回执 | 回执**必须**校验失败 | 回执自带真值 = 投影冒充原文（违 I14） |
| 构造 A 类截断 | 允许，但必须返回失真声明 | 无失真声明 = 静默丢失（违 I16） |
| 构造 B 类改写日志 | **必须**被拒 | 结构篡改被放行（违盲区 34） |
| protect TTL 到期 | 状态降级、原文仍在 | 降级实现成删除（违 I15/P1-003） |
| T2 握手失败 | 显式降级 T1 并写明原因 | 静默降级 |
| 让记忆系统决定「该不该注入」 | 接口**必须**无此能力 | 越界（违 I13） |
| 以「提升回答质量」为由提需求 | 按准入判据 **REJECT** | 价值主张越界（第五节） |
