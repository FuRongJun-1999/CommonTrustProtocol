# 灵枢记忆系统 · 接口与职责边界 v0.1

> 定位：**在《白箱认知记忆设计 v1》之上补接口契约与职责边界**，不推翻该 v1 的机制选择（五层记忆、四维条件空间、认知图=OS、语义时空图=记忆系统、闸门、完全确认）。
> 理论依据（智能论 3.4 分层）：本文属 **L3 协议条款层**（对"记忆系统的行为约束"），其字段定义属 **L1**，实现属 **L4**。公理层（L0）不参与本文讨论，任何工程结论不得反推。
> 证据等级标注沿用：〔实证〕＝可复跑读数；〔推断〕＝待反证；〔裁定〕＝设计者已定。

---

## 一、一句话定位

**灵枢记忆系统 = 一套"状态显式、可逆、可审计、可自维护"的存储与浅裁装置；它不生产智能，它让智能的每一次记忆行为都留得下账。**

黑箱管深算，白箱管**记 · 裁 · 维**〔实证·v0.3 §25〕。本文把这句话落成四件事：解决什么问题、功能怎么写、接口是什么、什么不归它管。

## 二、它要解决的四个问题

| # | 问题 | 没有它会怎样 | 对应机制 |
|---|---|---|---|
| **Q1** | 记什么、凭什么记 | 记忆退化为全量堆积，重要与不重要同权，噪音淹没信号 | 写入闸门（重要性＝信息差/信任及其二阶）〔实证〕 |
| **Q2** | 怎么找回来，且知道"找回来的可不可信" | 检索结果被误当事实；候选被当资格 | 多路召回＋**操作态/资格态分离**〔实证·X6〕 |
| **Q3** | 记错了能不能改、改坏了能不能退 | 修订不可逆，错误沉淀为"历史" | 「改」的四层：判定/状态机/回滚/授权〔实证〕 |
| **Q4** | 系统自己坏了，看得见吗 | 静默停摆，外部无法归因 | 自治面（心跳/自愈/自净/演化/整理/睡眠）＋台账〔实证〕 |

四问之外的一切，都不是它的 KPI。

## 三、什么不是灵枢该处理的

### 3.1 非职责清单

| 不做 | 归谁 | 判据 |
|---|---|---|
| 生成、推理、开放域泛化 | 生成器（黑箱 LLM） | 需要"参数化计算"，不是"状态治理" |
| 判定某知识在语义上是否为真 | **无人可判**；记忆系统只判"账上是否有据" | 语义真值超出账面能力，强答即失真 |
| 跨主体（多智能体）的权利义务 | CTP 协议层 | 涉及多方授权，单系统无权裁定 |
| 评测"这层白箱是否名副其实" | 《秤》 | 评测是对系统的外部度量，不能自评 |
| 编排、调度、并发执行 | 蜂巢 | 属执行面，不属状态面 |
| 决定"重要度阈值定多少" | **设计者〔裁定〕** | 阈值是价值判断，不是工程推导 |
| 训练/更新模型参数 | 训练侧 | 记忆系统只维护状态，不改权重 |

### 3.2 三条准入判据（比清单更好用）

任何新需求进来，先问三句；有一条为"是"就**不该**进记忆系统：

1. **它需要跨会话持久、可审计、可回滚的"状态"吗？** —— 否：属于当轮上下文或生成器内部。
2. **它必须是确定性的、可复跑的吗？** —— 否（必须生成式）：归深算。
3. **它会改变"谁有权改"的契约吗？** —— 是：归 CTP，不归记忆系统。

> 反例记录（X6 实战）：曾把"结构化证据是否足够支撑资格"交给记忆系统自己判，结果虚构实体查询同样返回 10 命中并被判 ACCEPT〔实证〕。这不是实现 bug，是**职责越界**——语义充分性不属记忆系统的账面能力。

## 四、能力分层（与智能论 L0–L4 对齐）

| 层 | 记忆系统里的对应 | 可变性 |
|---|---|---|
| L0 公理 | 不涉及（存在优先/信息条件性只作前提） | 冻结 |
| **L1 定义** | 五层记忆、四维条件空间、信息差 D、资格四态、操作态五值 | 精化需形式一致性检查 |
| **L2 架构** | 节点库＋台账族、认知图（OS）、语义时空图（记忆系统）、多路召回、状态机 | 可换实现 |
| **L3 契约** | **本文**：接口契约、不变量、降级规则、权限分层 | 需双方确认 |
| **L4 实现** | md_cg 代码、索引、探针、基准 | 可随工程变化 |

**要点**：接口契约属 L3，字段语义属 L1。改接口要双确认，改字段语义要走形式一致性——两者不能混谈。

## 五、四动作接口契约

记号：`->` 返回；`!` 不变量。所有接口**必须**携带 `snapshot_id`（否则跨运行不可比〔实证·漂移教训〕）。

### 5.1 取 Retrieve

```text
retrieve(query, scope, k, mode?) -> Envelope
Envelope = {
  operation_status : success | partial | timeout | unavailable | operation_error,
  completeness     : bool,
  candidates       : [ {node_ref, score, provenance[]} ],
  hit_count        : int | null,        ! 故障态必须 null，不得用 0
  qualification    : null,              ! 取不产生资格
  qualification_evaluated : false,
  evidence_ref     : [...] | null,
  snapshot_id      : str
}
```

**不变量**
- I1：`operation_status != success` ⇒ `hit_count = null` ∧ `candidates` 不得被解释为"没有"。
- I2：`completeness = false` ⇒ 不得进入零命中判定路径。
- I3：`candidates` 非空**不蕴含**"有该知识"，仅蕴含"有候选"。

### 5.2 算 Judge（浅裁）

```text
judge(claim, evidence_refs, snapshot_id) -> Verdict
Verdict = { state : ACCEPT | REJECT | DEFER | BLINDSPOT,
            basis : evidence_refs,
            reason_code : str,
            snapshot_id }
```

**不变量**
- I4：**零 LLM**；同输入同输出（逐位可复现）。
- I5：`evidence_refs` 为空 ⇒ 只能 `DEFER` 或 `BLINDSPOT`，**不得** `ACCEPT`。
- I6：`BLINDSPOT` 只表示"当前范围与证据下无法建立判断路径"，不得读作"知识不存在"。

### 5.3 改 Revise（四层，缺一不可）

```text
revise(node_ref, change, authority) -> Revision
Revision = { verdict, state_from, state_to, rollback_token, ledger_entry }
```

四层顺序与前置条件：

| 层 | 前置 | 拒绝条件 |
|---|---|---|
| ① 判定 | 改动须先过 verify 三态（confirmed/weakened/falsified） | 无判定直接改 → 拒 |
| ② 状态机 | 只允许逐级降级/回升（active→converged→demoted→archived） | 跳级 → 拒 |
| ③ 回滚 | 必须产出 rollback_token（前像＝执行时点） | 不可回滚的改动 → 拒 |
| ④ 授权 | 三档自治（计划/变更确认/完全访问）＋审核队列 | 越权 → 入队列，不静默执行 |

**不变量**
- I7：**退役不删除**；任何物理删除都不是本系统的合法操作。
- I8：每次改 = 一条 `_evolution` 记录（"这次改补了哪条缺失条件"），无记录即未发生。

### 5.4 存 Commit

```text
commit(node, evidence_ref) -> CommitResult
CommitResult = { committed : bool,
                 moved_to  : live | review_queue,
                 node_id   : str,
                 ledger    : [audit_ref, state_event_ref] }
```

**不变量**
- I9：写入即留痕（`_audit` ＋必要时 `_state_events`）；无痕写入 = 违规。
- I10：`committed = false` 时**不得**声称已固化；只能报"已入审核队列"。

## 六、降级与错误模型

```text
timeout / unavailable / operation_error  →  operation_status 显式取值
partial（部分返回）                       →  completeness=false
以上四类                                 →  一律 hit_count=null，禁止折算成 0 命中
零命中（success ∧ complete）              →  仅表示"本次查询范围内无候选"
```

**这条模型的教训来自 X6**：默认检索路径上，兜底候选会让"有结果"不等于"有知识"，而纯符号查询又能返回 0 命中〔实证〕。⇒ **零命中可达，但不能反推知识不存在**。

## 七、全局不变量（跨接口）

| 编号 | 不变量 | 违反后果 |
|---|---|---|
| G1 | 操作态与资格态分离 | 失败被当成判定结果 |
| G2 | 资格未评估不得填四态 | 伪装成"已判定" |
| G3 | 退役不删除、改必留痕 | 历史不可追 |
| G4 | 所有输出携带 snapshot_id | 跨运行比较失真 |
| G5 | 无账不强答 | 语义真值被冒充 |
| G6 | 写入未被裁决时不得称"已固化" | 审核队列被绕过 |

## 八、与外部系统的接缝

```text
生成器（黑箱）──备料──▶ 记忆系统 ──候选+操作态──▶ 生成器（深算）
                          │
                          ├──状态/证据交换──▶ CTP（多主体契约）
                          ├──被度量──────▶ 《秤》（评测，不可自评）
                          └──被调度──────▶ 蜂巢（执行面）
```

**接缝纪律**：记忆系统对下游只承诺"状态与证据的可信交付"，不承诺"结论正确"。下游若把候选当结论，责任在下游。
