## 一、一页摘要

**灵枢记忆系统 = 一套「状态显式、可逆、可审计、可自维护」的记忆装置。它不生产智能，它让每一次记忆行为都留得下账。**

它解决的问题只有四个：

| # | 问题 | 没有它会怎样 |
|---|---|---|
| Q1 | 记什么、凭什么记 | 全量堆积，噪音淹没信号 |
| Q2 | 怎么找回来，且知道可不可信 | 候选被当事实、被当资格 |
| Q3 | 记错了能不能改、改坏能不能退 | 修订不可逆，错误沉淀成历史 |
| Q4 | 系统自己坏了看得见吗 | 静默停摆，无法归因 |

**KPI 只有四要素**：可审计、可回滚、可复跑、不丢账。
**明确不是 KPI**：答得更准、更快、更省——bench 已证推理能力归模型、写入成本与效果无关。

## 二、双轴分层（本架构的核心约定）

过去四份稿子混用了两套坐标，导致「层」字含义漂移。本架构把两套轴显式分开，并要求**任何设计条目同时标注两轴**。

### 2.1 L 轴：治理轴（改东西该走哪条验证）

| L 层 | 内容 | 改动验证 |
|---|---|---|
| L0 公理 | 存在优先、信息条件性 | **冻结**，只能追加不适用条件 |
| L1 定义 | 条件空间、四态、五层记忆、信息差 | 形式一致性检查 |
| L2 架构 | 记录结构、认知图、状态机 | 回归 |
| L3 契约 | 接口、不变量、权限、边界 | 双确认 |
| L4 部署 | 实现、索引、探针、基准 | 记录即可 |

### 2.2 P 轴：运行时轴（数据怎么流）

| P 层 | 回答的问题 | 关键不变量 |
|---|---|---|
| P0 存在层 | 什么是不容否认的前提 | 冻结、局部性 |
| P1 条件层 | 这条知识在什么条件下成立 | 无条件空间不得 ACCEPT |
| P2 记录层 | 怎样持久化、如何回读 | 写必留痕、退役不删除 |
| P3 裁决层 | 这个候选有没有资格 | 先拒绝后接受、资格由证据裁决 |
| P4 会话层 | 谁在什么范围可见、可见多久 | 层级不越读、降级不改记录 |
| P5 投影层 | 怎样压缩而不丢账 | 回执不带真值、率与失真同时声明 |
| P6 服务层 | 上层如何完成一次交互 | I1–I16 |

### 2.3 两轴映射（消除歧义的关键）

| P 层 | 主要落在 L 轴 | 说明 |
|---|---|---|
| P0 | **L0** | 公理直接提供介质约束，中间无转换 |
| P1 | **L1** | 条件空间四维是定义层的可测化 |
| P2 | **L2** | 记录结构与状态机属架构 |
| P3 | **L1 + L3** | 判定规则是定义，准入契约是条款 |
| P4 | **L3** | 隔离与授权是多方契约 |
| P5 | **L3 + L4** | 压缩义务是契约，压缩实现是部署 |
| P6 | **L4** | 接口实现属部署 |

**读法**：说「这属于 L3」是在说**改动要走双确认**；说「这属于 P5」是在说**它是运行时压缩环节**。两者不冲突，且必须同时说清。

## 三、协议栈（P0–P6 逐层定型）

### P0 存在层

约束：0.0 元元公理、0.0.1 信息条件性、0.0.2 任意分层性、0.0.3 局部不可知。
原语：无（只提供约束）。
不变量：**P0-1** 冻结；**P0-2** 任何断言都是局部的。
能红：文档出现「工程读数证明公理需修订」→ 判层违规。

### P1 条件层（知识的地址空间）

原语：declare／switch／verify。
不变量：**P1-1** 无条件空间不得进入 ACCEPT；**P1-2** 切换须走「触发→声明→复核→执行→复核→记入结构层」。
能红：删字段 → P3 必须返回 DEFER。

> 普通存储用主键寻址，本系统用**条件**寻址——正如 IP 用地址而非内容寻址。

### P2 记录层

原语：commit／getNode。
不变量：**P2-1** 写必留痕；**P2-2** 退役不删除；**P2-3** 内容寻址幂等；**P2-4** 七类不可遗忘禁止退役。
能红：物理删除受保护记录必须被拒；账目缺条目必须报洞。

### P3 裁决层（准入控制）

原语：judge（零 LLM）／verify（外部基底）。
不变量：**P3-1** 先拒绝后接受；**P3-2** 资格由条件证据裁决不由相似度；**P3-3** 无账不强答；**P3-4** BLINDSPOT ≠ 知识不存在。
能红：虚构实体查询不得 ACCEPT；同输入两次判定逐字节一致。

> 这一层是「检索系统」与「记忆协议」的分界线：**先证明能连，再传输**。

### P4 会话层

原语：open／renew／close。
不变量：**P4-1** 层级不越读（跨层只靠 derived_from）；**P4-2** 降级只作用状态与投影；**P4-3** TTL 到期退出可见投影、原文不动。
能红：proj 读 team 必须取不到；TTL 到期原文仍可 getNode。

### P5 投影层

原语：compress／decompress／verifyAnchor。
不变量：**P5-1** 回执不带真值；**P5-2** A 类有损合法（须声明失真）、B 类结构篡改禁止；**P5-3** 率与失真同时声明；**P5-4** 不声称解决存储上限张力。
能红：无失真声明的截断必须被拒；改写 append-only 必须被拒。

> A/B 判据一句话：**改完之后，能否从现有记录重建改之前的状态？** 能 → A 类；不能 → B 类。

### P6 服务层（四动作）

原语：retrieve／judge／revise／commit（请求-指示-响应-确认）。
不变量：I1–I16（附录 A）。
能红：timeout 必须 hit_count=null；committed=false 不得称已固化。

## 四、封装与解封装

    P1 条件头 → P2 记录头 → P3 判定尾 → P5 投影头 → P6 服务头

上层读到的**永远不是「原文」**，而是带条件与证据的结构。
**这是与「返回最相似文本」的根本区别——返回的是有出处的结构，不是像样的文字。**

## 五、四动作接口（定型）

    retrieve(query, scope, k, condition_space, snapshot_id) -> Envelope
    judge(claim, evidence_ref[], condition_space, snapshot_id) -> Verdict{ACCEPT|REJECT|DEFER|BLINDSPOT}
    revise(node_ref, change, authority, condition_space) -> {verdict, state_from, state_to, rollback_token, ledger}
    commit(node, evidence_ref, condition_space, snapshot_id) -> {committed, moved_to, node_id, decision_state, ledger[]}

「改」是四层门控，缺一不可：判定（verify 三态）→ 状态机（逐级，不跳级）→ 回滚（token，前像＝执行时点）→ 授权（三档自治＋审核队列）。

## 六、职责边界

### 6.1 三条准入判据（任何新需求先过）

1. 需要跨会话持久、可审计、可回滚的**状态**吗？否 → 不进。
2. 必须确定性、可复跑吗？否（必须生成式）→ 归深算。
3. 会改变「谁有权改」的契约吗？是 → 归 CTP。

### 6.2 负路由（与四态裁决同构）

先问「能否证明它不适用」——能证明即 REJECT，不必进入能力评估。**拒绝优先于接受。**

### 6.3 明确不做

生成推理（生成器）｜语义真值判定（无人可判）｜跨主体权利（CTP）｜评测自评（《秤》）｜编排调度（蜂巢）｜阈值与档位（设计者）｜训练改参（训练侧）。

## 七、接缝（与相邻系统）

| 系统 | 关系 | 分界 |
|---|---|---|
| 上下文系统（context-lab） | 本系统的 **P6 消费者** ＋ T2 后端调用方 | 它决定可见面，本系统决定持久面 |
| 生成器（LLM） | 外部 | 深算归它，本系统只备料与裁决 |
| CTP | 横向互操作 | 跨主体权利不裁定 |
| 《秤》 | 外部度量 | 不可自评 |
| 蜂巢 | 执行面 | 不管调度 |

**三条接缝纪律**：

- **I13** 本系统不得代做「该不该注入」的决策——接口必须无此能力。
- **I14** 回执不得自带真值——删掉原文后校验必须失败。
- **I15** 降级只作用状态与投影，原文与记录永不随之消失（P1-003）。

失败传递：T2 握手失败 → 显式降级 T1 并写明原因；显式指定后端却不可用 → 启动期报错（不静默降级）；本系统 timeout/partial → 一律 hit_count=null，**不得让上层读成「没有这条记忆」**。

## 八、三层记忆边界与账本单向性

| 层 | 谁能读 | 禁止进入 |
|---|---|---|
| 个人长期（私密） | 仅该 session 持有者 | 群聊上下文、团队卡片、任何公开面 |
| 内部团队（同库隔离） | 该 session 持有者＋admin 裁剪注入 | 个人私密、未验证结论、外部原始过程 |
| 对外公共（公开可查） | 任何人 | 内部 ID／路径／信任分 |

账本单向性（不可协商）：**镜像只读**｜**纠正靠追加**｜**镜像是公开面的纯函数**。
能红：删掉镜像后从公开账本重建必须逐字段一致。

## 十二、本架构不声称

1. 不声称提升推理能力（推理归模型）。
2. 不声称解决不可遗忘与存储上限的矛盾（盲区 61 未解）。
3. 不声称语义真值判定（只判「账上是否有据」）。
4. 不替代验证单元（事实由外部基底裁决）。
