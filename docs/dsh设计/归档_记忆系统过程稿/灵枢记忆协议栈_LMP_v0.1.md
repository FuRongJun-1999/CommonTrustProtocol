# 灵枢记忆协议栈（LMP v0.1）

> **性质**：把已有的理论与工程条款，组织成一套**分层协议栈**——像 TCP/IP 那样，每层只对上提供一种服务，层间有明确的数据单元与不变量，任何一层可独立替换与独立验证。
> **依据**：智能论 3.4 全文（5229 行 / 283 标题，骨架索引见 智能论3.4_全文骨架_v1.md）；设计者视角 skill 五步与 references 01–05；前序设计 v0.1/v0.2/v0.3；《灵枢协作架构_设计_v0.1》§六§七、《群聊协议_v0.1》、context-lab v1.2、hive-memory-bench 两条公开结论。
> **不新增理论**：本栈不引入智能论之外的任何概念，只做分层归位与接口固化。

---

## 一、为什么需要协议栈（而不是再写一份设计）

已有设计缺的不是内容，是**分层纪律**。当前状态是三处混层：

1. 公理（存在优先）与实现（索引结构）出现在同一段论证里；
2. 判定（能不能）与检索（像不像）被同一句「返回最相关」含混过去；
3. 投影（回执/摘要）被视为等价于原文。

协议栈解决的就是这件事：**每层只回答一个问题，层间只通过固定原语交互**。这与 TCP/IP 的收益同源——不是分层好看，而是任一层可独立替换、独立测试、独立归因。

## 二、分层总览（自下而上）

    ┌─────────────────────────────────────────────────────────────┐
    │  P6 服务层   取 / 算 / 改 / 存 四原语（应用可见面）           │
    ├─────────────────────────────────────────────────────────────┤
    │  P5 投影层   压缩 · 锚定回执 · 率失真声明                     │
    ├─────────────────────────────────────────────────────────────┤
    │  P4 会话层   session 隔离 · stable 租约 · TTL                 │
    ├─────────────────────────────────────────────────────────────┤
    │  P3 裁决层   四态资格（先拒绝后接受）· 证明候选                │
    ├─────────────────────────────────────────────────────────────┤
    │  P2 记录层   节点帧 · 台账族 · 内容寻址 · 退役不删除           │
    ├─────────────────────────────────────────────────────────────┤
    │  P1 条件层   条件空间四维 = 地址空间                          │
    ├─────────────────────────────────────────────────────────────┤
    │  P0 存在层   存在优先 · 信息条件性（冻结，不可协商）           │
    └─────────────────────────────────────────────────────────────┘
      横切面：安全（边界/自治）· 可观测（台账）· 自维护（六档）· 互操作（CTP/秤/蜂巢/上下文系统）

**分层铁律（四条，违反即栈失效）**

- **R1 单向依赖**：第 N 层只可调用第 N-1 层提供的服务，不得反向。
- **R2 单一职责**：每层只回答一个问题；跨层问题必须在层间拆开。
- **R3 不变量下沉**：越靠下的不变量越不可协商（P0 冻结，P6 可变）。
- **R4 可独立替换**：替换某一层，只要其对外原语不变，上下层无需改动。

## 三、逐层定义

### P0 存在层（Substrate）——不可协商的介质

| 项 | 内容 |
|---|---|
| 回答的问题 | 什么是不容否认的前提 |
| 条款 | 0.0 元元公理、0.0.1 信息条件性、0.0.2 任意分层性、0.0.3 局部不可知 |
| 服务原语 | 无。只提供约束，不提供数据 |
| 不变量 | **P0-1** 冻结：任何上层结论不得反推修改；**P0-2** 局部性：任何断言都是局部的 |
| 能红判据 | 若某设计文档出现「工程读数证明公理需修订」的表述 → 判为层违规 |

对应 TCP/IP 的物理层：不能通过改应用协议去改变介质特性。

### P1 条件层（Condition / Addressing）——知识的地址空间

| 项 | 内容 |
|---|---|
| 回答的问题 | 这条知识在什么条件下成立 |
| 条款 | 3.1 四维定义、3.2 声明格式、3.3 切换流程、0.0.5 条件论 |
| SDU | condition_space{observation_position, observation_tool, time_window, existence_constraint} |
| 服务原语 | declare（声明）／switch（切换）／verify（复核） |
| 不变量 | **P1-1** 无条件空间的知识不得进入 P3 的 ACCEPT；**P1-2** 切换须走「触发→声明→复核→执行→复核→记入结构层」六步 |
| 能红判据 | 删除 condition_space 字段 → P3 必须返回 DEFER 而非 ACCEPT |

**与普通存储最根本的差异**：普通系统用主键寻址，本栈用**条件**寻址——正如 IP 用地址而非内容寻址。

### P2 记录层（Record / Framing）——数据单元与账本

| 项 | 内容 |
|---|---|
| 回答的问题 | 一条记录被怎样持久化、如何可回读 |
| 条款 | 3.2 动态记忆系统、3.2.1 结构锚定记录、3.2.2 stable 租约 |
| SDU | node 帧 {id, content, layer, condition_space, evidence_ref[], derived_from} ＋ 台账条目 |
| 服务原语 | commit（写入）／getNode（按 id 回读原文） |
| 不变量 | **P2-1** 写必留痕；**P2-2** 退役不删除；**P2-3** 内容寻址（同内容幂等）；**P2-4** 七类不可遗忘（六类 §3.2 + 自我锚点）禁止退役 |
| 能红判据 | 尝试物理删除一条受保护记录 → 必须被拒；日记账缺条目 → 审计必须报洞 |

对应链路层的帧与校验和：帧有边界，**账本就是本栈的校验和**。

### P3 裁决层（Qualification / Admission）——准入控制

| 项 | 内容 |
|---|---|
| 回答的问题 | 这个候选有没有资格被采信/执行 |
| 条款 | 6章.2 四态判定、负路由、三层分工（概率/条件/验证） |
| SDU | claim ＋ evidence_ref[] |
| 服务原语 | judge（浅裁，零 LLM）／verify（外部基底裁决事实） |
| 不变量 | **P3-1** 先拒绝后接受（REJECT→BLINDSPOT→DEFER→ACCEPT）；**P3-2** 资格由条件证据裁决，不由相似度裁决；**P3-3** 无账不强答；**P3-4** BLINDSPOT ≠ 知识不存在 |
| 能红判据 | 虚构实体查询不得 ACCEPT；同输入两次判定必须逐字节一致 |

对应 TCP 的握手与准入：**先证明能连，再传输**。这层的存在，正是「检索系统」与「记忆协议」的分界线。

### P4 会话层（Session / Connection）——隔离与租约

| 项 | 内容 |
|---|---|
| 回答的问题 | 谁在什么范围内可见、可见多久 |
| 条款 | 3.2.2 stable 租约、三层记忆边界（协作架构 §6.2）、群聊 session 隔离 |
| SDU | session_id{team:/proj:/sub:/group:} ＋ lease{scope, ttl} |
| 服务原语 | open／renew／close |
| 不变量 | **P4-1** 层级不越读（跨层只靠 derived_from）；**P4-2** 降级只作用于状态与投影，不改记录（P1-003）；**P4-3** TTL 到期 = 退出可见投影，原文不动 |
| 能红判据 | 用 proj:X 读团队 L0 → 必须取不到；protect TTL 到期 → 原文仍可 getNode |

对应 TCP 连接与 keepalive：**连接有关闭，但关闭不等于数据销毁**。

### P5 投影层（Projection / Presentation）——压缩与表示

| 项 | 内容 |
|---|---|
| 回答的问题 | 在不丢账的前提下，怎样把大东西变成可见的小东西 |
| 条款 | 3.2.1 锚定记录、附录 7 率失真、盲区 34（A/B 类）、盲区 61（存储张力） |
| SDU | 回执{anchor_id, 摘要, 率, 失真声明, 可回读 ref} |
| 服务原语 | compress／decompress／verifyAnchor |
| 不变量 | **P5-1** 回执不得自带真值（删原文后校验必须失败）；**P5-2** A 类有损合法（须声明失真），B 类结构篡改禁止；**P5-3** 率与失真必须同时声明；**P5-4** 不声称已解决不可遗忘与存储上限的张力 |
| 能红判据 | 无失真声明的截断 → 必须被拒；改写 append-only 日志 → 必须被拒 |

**盲区 34 的判据可一句话检验**：改完之后，能否从现有记录重建改之前的状态？能 → A 类；不能 → B 类。这让「不改写日志」从工程偏好升为理论判据。

### P6 服务层（Service Primitives）——应用可见面

| 项 | 内容 |
|---|---|
| 回答的问题 | 上层如何用四个动作完成一次交互 |
| 条款 | 前序 v0.2 四动作契约 |
| 服务原语 | retrieve／judge／revise／commit（请求-指示-响应-确认四型） |
| 不变量 | **I1–I16**（见附录 A） |
| 能红判据 | 注入 timeout → hit_count 必须 null；committed=false 却称已固化 → 审计须捕获 |

## 四、封装与解封装（本栈最像 TCP 的部分）

一次写入，自下而上逐层加头：

    P1 条件头   condition_space（四维）          ← 没有它，记录无法被正确寻址
    P2 记录头   id / layer / derived_from / 摘要
    P3 判定尾   verdict（四态）＋ evidence_ref[]
    P5 投影头   回执 anchor_id ＋ 率/失真声明（仅当发生压缩）
    P6 服务头   operation_status / completeness / snapshot_id

**解封装**沿反方向：上层读到的永远不是「原文」，而是**逐层剥开后的、带条件与证据的记录**。这就是与「直接返回最相似文本」的根本区别——**返回的是一个有出处的结构，而不是一段像样的文字**。

## 五、跨层机制（对应 TCP 的流控/重传/版本协商）

| 机制 | 本栈落法 | 依据 |
|---|---|---|
| **流控** | budget_tokens = 窗口；超窗口必须显式声明截断量 | 附录 7 率失真 |
| **重传** | 故障态不冒充成功：timeout/partial 一律 hit_count=null，由上层决定是否重试 | X6 判定单 |
| **幂等** | 内容寻址（同内容同 id），重复写入不产生第二条 | P2-3 |
| **版本协商** | 一切结论携带 snapshot_id；跨快照比较必须显式声明 | 漂移教训（31047→31065） |
| **错误模型** | 操作态五值（success/partial/timeout/unavailable/operation_error）与资格四态正交，不得互相折算 | X6 判定单 |
| **优先级** | 七类不可遗忘 > protected（importance≥0.7）> 普通知识 > 情境层 | §3.2 + 晋升通路 |
| **拥塞信号** | 失真声明率升高 = 上下文超载，应降注入量而非加预算 | 附录 7 |
| **审计** | 台账族（审计/状态事件/演化）即抓包：任何交互可事后复现 | 3.2 + 协作架构 §6.3 |

## 六、横向面（贯穿所有层）

| 面 | 职责 | 关键约束 |
|---|---|---|
| **安全面** | 三层记忆边界 + 三档自治 | 私密/团队/公开三级 ACL；越权入审核队列，不静默执行 |
| **可观测面** | 台账族 + 探针 | 状态变化必须可复现；自治面停摆必须可归因（stale_tick 点名卡点） |
| **自维护面** | 六档循环（心跳/自愈/自净/演化/整理/睡眠） | 任一无界阻塞即整体停摆，须有界化 |
| **互操作面** | CTP（跨域）、《秤》（一致性测试）、蜂巢（调度）、上下文系统（消费者） | 只承诺状态与证据的可信交付，不承诺结论正确 |

## 七、与相邻系统的分界

| 系统 | 与本栈的关系 | 分界 |
|---|---|---|
| 上下文系统（context-lab） | 本栈的 **P6 消费者** ＋ T2 后端调用方 | 它决定可见面（P5 之上），本栈决定持久面（P0–P4） |
| 生成器（LLM） | 本栈之外 | 深算归它；本栈只备料与裁决 |
| CTP | 横向互操作 | 跨主体权利；本栈不裁定 |
| 《秤》 | 外部度量 | 本栈不可自评 |
| 蜂巢 | 执行面 | 本栈不管调度 |

**一句话边界**：本栈是**记忆的协议**，不是智能的协议；它能保证「记了什么、凭什么、能不能改」，不能保证「答得对」。

## 九、本栈不声称什么

1. **不声称提升推理能力**——bench 两条公开结论已证：推理能力是模型给的，写入成本与效果无关。本栈 KPI 只有四要素：可审计、可回滚、可复跑、不丢账。
2. **不声称解决遗忘与存储上限的矛盾**（盲区 61 未解，索引有界只是第一步）。
3. **不声称语义真值判定**——本栈只判「账上是否有据」。
4. **不替代验证单元**——《秤》与本栈之外的验证基底才是事实裁决者。
