## 一、理论依据（3.4）

### 1. 三端口架构（0.0.7）——验证回路的结构前提
- 输入端口(感知机×5)：外→内，物理信号→条件候选「现在是什么」
- 内部端口(预测引擎)：内→内，记忆→未来候选「接下来可能是什么」
- **输出端口(行动执行器)：内→外，改变世界→制造验证机会**——无行动端口则完全确认不可达
- 感知机=换能+特征提取+语义锚定→产物为条件；传感器输出信号，感知机输出条件候选
- **辨识问题四类结构**：传感器(证据)/概率(置信)/导数(变化)/图(关系)
- **多重一致性**：候选四维一致最高者胜；但内部一致≠外部真实→必须外接世界裁决(2.9.3)

### 2. 信息差分离（2.7.0）
- D_norm = **D_task**(图上操作性距离，可增可减，学习前提)；D_meta=未被建模现实总量(d≥0，结构性边界)
- 验证度量：**实现的 KL_task**(实际闭合的 D_task)；D_meta 不纳入数值计算

### 3. 完全确认（2.9.3a 操作性）
- Confirmed(S) = 全路径 c_i≥θ_c 且 强验证 realized_KL_task>θ_g 且 跨时间稳定 且 无内部矛盾
- **验证收益双层**：Value = ΔD_task·σ(Gain_task)——Gain 筛选(值不值得做)，ΔD 定价(对任务值多少)
- 完全确认不是「真」，是「当前条件下最可信」(缸中之脑边界，保留被推翻可能)

## 三、我们的验证端（白箱执行端）

三端口(0.0.7): 感知(传感器→条件候选) → 预测(记忆→未来候选) → 行动(改变世界→制造验证机会)
  → 辨识(四类证据) → 多重一致性 → 外接世界裁决
  → 感知机测 ΔD_task(生成→感知→cycle-consistency 残差=D_norm) → 完全确认(2.9.3a)
  → 验证收益: Gain(筛选)+ΔD(定价) → 打卡/审计/红队门(白箱化)

界面：递归反思(前端,已有,想对) → 执行 → 验证端补全(后端,做完+核对+审计)
验证端接：感知机(cycle-consistency 测 D_norm=D_task) + 子部件规格 + 世界模型(预测→验证)
缸中之脑边界：完全确认=当前条件最可信，保留被推翻可能(诚实)

## 五、记忆/上下文处理标准（认知图方式）

- 记忆/上下文的"压缩/组织"**用认知图**（逐条件分析+子内容拆解+关系边），**非 SmartCrusher 粗截断**；
- 逐条件：每内容→条件空间节点(o/t/窗/约束)；拆解：部分→子部分→细节；关系：part_of/causal/similar；
- 这是**通用功能**（视觉子部件细分=实例）；验证端接认知图，记忆成为认知的一部分。
