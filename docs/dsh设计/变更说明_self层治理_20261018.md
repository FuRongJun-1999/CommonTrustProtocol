# 变更说明 · self 层污染治理（方案 A + C）

> 日期：2026-10-18　对象：灵枢记忆系统生产库（D:/program/AEIS/data/mdcg）
> 性质：**数据变更记录**。以下写明实际做了什么、为什么、怎么回滚。

---

## 一、问题

实测（只读分析，未改数据）：

    self 层共 780 条
      ├─ 769 条  rev_*_r*  ← 审核裁决审计记录（98.6%）
      └─ 11 条   真实自我节点（self_anchor_* / self_state_* / self_relation_* 等）

这 769 条的 frontmatter 本就是证据：

    audit_source: "hippocampus/decisions.jsonl"
    decision: "accept"　pid: "prop_*"　round: 1
    role: "tool-output"　importance: 0.2
    sensitivity: "secret"　body: <!-- mdcg-enc:v1:… -->

**为什么这比「数据脏」严重**：self 层属层保护（layer∈{self,anchor} ⇒ is_protected 恒真）。
于是 769 条 sensitivity=secret 的裁决日志被「不可遗忘」永久占用自我层，
任何按 layer=self 做的自我认知分析，98.6% 拿到的是裁决日志。

语义上它们属**结构事件**（审计痕迹），不属**扮演依据**（自我锚点）。

## 二、做了什么

### A · 堵源头（代码变更）

    md_cg/mdcos.py  _write_review_record
        layer="self"  →  layer="structural"
        tags=[…]      →  tags=["audit", "audit_trace", …]   ← 同时自动打标

只影响**此后新产生**的裁决记录。隔离副本实测：新节点 layer=structural、
protected=(False,'')——不再享受层保护。

### C · 存量打标（数据变更）

**不迁移**。理由：迁移会动 is_protected 判定面、record_hash 引用可能断；
而这 769 条已在 self 层「不可遗忘」，强行搬动本身就在冒风险。

改为打 audit_trace 标签 + 在读取面过滤：

    备份      self.bak.20261018-163851（整个 self 目录）
    打标      769 / 769 条（rev_*_r1 767 条 + r2 2 条）
    方式      只改 frontmatter 的 tags 一行，其余字节不动
    失败      0

### 读取面（新增能力）

    md_cg/self_surface.py
        self_surface(cg)                           → 真实自我面（默认排除 audit_trace）
        self_surface(cg, include_audit_trace=True) → 含审计痕迹（供排查）
    判据单点 AUDIT_TRACE_TAG，调用方不各写一份过滤逻辑

## 三、实测效果

    过滤前 self 层        780 条
    过滤后自我面          11 条（正是真实自我节点）
    审计痕迹             769 条，仍可审计（include_audit_trace=True）

## 四、怎么回滚

| 变更 | 回滚方式 |
|---|---|
| 代码层（A） | 把 layer="structural" 改回 "self" |
| 数据（C） | 用 self.bak.20261018-163851 覆盖回 self/ |
| 索引 | 回滚后跑一次 rebuild_index |

新增两步钉住：
* audit_layer_not_self：新审计记录落 structural 且不受层保护
* self_surface_filter：审计痕迹带标、被自我面排除、不过滤时仍可见

## 六、边界（本文不声称）

1. **不声称已解决分层设计问题**——只把一类记录挪了位置并加了标签；审计记录是否该有独立层，另议。
2. **不动正文数据**：769 条正文（加密）一字未改，只加了一个标签。
3. **不覆盖其他端**：zcode / codebuddy 若仍跑旧代码，其新产生的裁决记录仍会落 self，
   需要各自重启（参见同日「索引被旧代码进程覆盖」的记录）。
