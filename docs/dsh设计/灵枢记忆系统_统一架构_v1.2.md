## 一、一页摘要

**灵枢记忆系统 = 一套「状态显式、可逆、可审计、可自维护」的记忆装置。它不生产智能，它让每一次记忆行为都留得下账。**

它解决的问题只有四个：

| # | 问题 | 没有它会怎样 |
|---|---|---|
| Q1 | 记什么、凭什么记 | 全量堆积，噪音淹没信号 |
| Q2 | 怎么找回来，且知道可不可信 | 候选被当事实、被当资格 |
| Q3 | 记错了能不能改、改坏能不能退 | 修订不可逆，错误沉淀成历史 |
| Q4 | 系统自己坏了看得见吗 | 静默停摆，无法归因 |

**KPI 只有四要素**：可审计、可回滚、可复跑、不丢账。
**明确不是 KPI**：答得更准、更快、更省——bench 已证推理能力归模型、写入成本与效果无关。

## 二、双轴分层（本架构的核心约定）

过去四份稿子混用了两套坐标，导致「层」字含义漂移。本架构把两套轴显式分开，并要求**任何设计条目同时标注两轴**。

### 2.1 L 轴：治理轴（改东西该走哪条验证）

| L 层 | 内容 | 改动验证 |
|---|---|---|
| L0 公理 | 存在优先、信息条件性 | **冻结**，只能追加不适用条件 |
| L1 定义 | 条件空间、四态、五层记忆、信息差 | 形式一致性检查 |
| L2 架构 | 记录结构、认知图、状态机 | 回归 |
| L3 契约 | 接口、不变量、权限、边界 | 双确认 |
| L4 部署 | 实现、索引、探针、基准 | 记录即可 |

### 2.2 P 轴：运行时轴（数据怎么流）

| P 层 | 回答的问题 | 关键不变量 |
|---|---|---|
| P0 存在层 | 什么是不容否认的前提 | 冻结、局部性 |
| P1 条件层 | 这条知识在什么条件下成立 | 无条件空间不得 ACCEPT |
| P2 记录层 | 怎样持久化、如何回读 | 写必留痕、退役不删除 |
| P3 裁决层 | 这个候选有没有资格 | 先拒绝后接受、资格由证据裁决 |
| P4 会话层 | 谁在什么范围可见、可见多久 | 层级不越读、降级不改记录 |
| P5 投影层 | 怎样压缩而不丢账 | 回执不带真值、率与失真同时声明 |
| P6 服务层 | 上层如何完成一次交互 | I1–I17（I13–I17 为跨层不变量，在此汇总而非专属 P6） |

### 2.3 两轴映射（消除歧义的关键）

| P 层 | 主要落在 L 轴 | 说明 |
|---|---|---|
| P0 | **L0** | 公理直接提供介质约束，中间无转换 |
| P1 | **L1** | 条件空间四维是定义层的可测化 |
| P2 | **L2** | 记录结构与状态机属架构 |
| P3 | **L1 + L3** | 判定规则是定义，准入契约是条款 |
| P4 | **L3** | 隔离与授权是多方契约 |
| P5 | **L3 + L4** | 压缩义务是契约，压缩实现是部署 |
| P6 | **L4** | 接口实现属部署 |

**读法**：说「这属于 L3」是在说**改动要走双确认**；说「这属于 P5」是在说**它是运行时压缩环节**。两者不冲突，且必须同时说清。

### 2.4 信息 / 表示 / 载体（概念基座，v1.1 新增）

理论从不区分「文档」，只承认**可认知信息**——0.0.1「每一个信息差都是条件化的」，0.0.7「产物统一为条件」。本架构据此立三层：

| 层 | 是什么 | 判定问题 |
|---|---|---|
| **信息** | 条件空间 C 下可被观测、可被证据支持的断言 | 在什么条件下成立？证据是什么？ |
| **表示** | 同一信息的不同编码（md 段落／json 字段／代码注释／群聊消息／台账行） | 是否无损承载该信息？ |
| **载体** | 表示的存放位置（文件／库节点／账本／消息流） | 是否可被回读？ |

**三条纪律**

1. 信息是一等对象，表示与载体是手段；**不存在「文档」这个类型**。
2. 同一信息可有**多份投影**，但只算**一条**知识——去重按信息，不按文件。
3. 任何投影都不构成权威；权威在「信息 ＋ 条件空间 ＋ 证据链」三元组（见 I17）。

**日常词的协议化翻译**

| 日常说法 | 协议里的说法 |
|---|---|
| 写了一份文档 | 产生了一条信息，并用某种表示落到某载体 |
| 归档文档 | **降低该投影的可见等级**，信息本体不消失 |
| 文档重复了 | 同一信息的多份投影（须合并引用，不得计为多条） |
| 文档过期了 | 该信息的**条件空间**已不成立（时间窗失效），不是文件旧了 |
| 文档写错了 | 该信息与其证据链不一致；**跨投影不一致**才是判据 |

## 三、协议栈（P0–P6 逐层定型）

### P0 存在层

约束：0.0 元元公理、0.0.1 信息条件性、0.0.2 任意分层性、0.0.3 局部不可知。
原语：无（只提供约束）。
不变量：**P0-1** 冻结；**P0-2** 任何断言都是局部的。
能红：文档出现「工程读数证明公理需修订」→ 判层违规。

### P1 条件层（知识的地址空间）

原语：declare／switch／verify。
不变量：**P1-1** 无条件空间不得进入 ACCEPT；**P1-2** 切换须走「触发→声明→复核→执行→复核→记入结构层」。
能红：删字段 → P3 必须返回 **REJECT**（打回作者，非入队；见 §10.1 V1 与 §10.0 第 6 步）。

> 普通存储用主键寻址，本系统用**条件**寻址——正如 IP 用地址而非内容寻址。

### P2 记录层

原语：commit／getNode。
不变量：**P2-1** 写必留痕；**P2-2** 退役不删除（archived 是状态非删除，见 §八）；**P2-3** 内容寻址幂等；**P2-4** 七类不可遗忘永久 active，禁入任何降级档。
能红：物理删除受保护记录必须被拒；账目缺条目必须报洞。

### P3 裁决层（准入控制）

原语：judge（零 LLM）／verify（外部基底）。
不变量：**P3-1** 先拒绝后接受；**P3-2** 资格由条件证据裁决不由相似度；**P3-3** 无账不强答；**P3-4** BLINDSPOT ≠ 知识不存在。
能红：虚构实体查询不得 ACCEPT；同输入两次判定逐字节一致。

> 这一层是「检索系统」与「记忆协议」的分界线：**先证明能连，再传输**。

### P4 会话层

原语：open／renew／close。
不变量：**P4-1** 层级不越读（跨层只靠 derived_from）；**P4-2** 降级只作用状态与投影；**P4-3** TTL 到期退出可见投影、原文不动。
能红：proj 读 team 必须取不到；TTL 到期原文仍可 getNode。

### P5 投影层

原语：compress／decompress／verifyAnchor。
不变量：**P5-1** 回执不带真值；**P5-2** A 类有损合法（须声明失真）、B 类结构篡改禁止；**P5-3** 率与失真同时声明；**P5-4** 不声称解决存储上限张力。
能红：无失真声明的截断必须被拒；改写 append-only 必须被拒。

> A/B 判据一句话：**改完之后，能否从现有记录重建改之前的状态？** 能 → A 类；不能 → B 类。

### P6 服务层（四动作）

原语：retrieve／judge／revise／commit（请求-指示-响应-确认）。
不变量：I1–I17（附录 A）。
能红：timeout 必须 hit_count=null；committed=false 不得称已固化。

## 四、封装与解封装

    P1 条件头 → P2 记录头 → P3 判定尾 → P5 投影头 → P6 服务头

上层读到的**永远不是「原文」**，而是带条件与证据的结构。
**这是与「返回最相似文本」的根本区别——返回的是有出处的结构，不是像样的文字。**

## 五、四动作接口（定型）

    retrieve(query, scope, k, condition_space, snapshot_id) -> Envelope
    judge(claim, evidence_ref[], condition_space, snapshot_id) -> Verdict{ACCEPT|REJECT|DEFER|BLINDSPOT}
    revise(node_ref, change, authority, condition_space) -> {verdict, state_from, state_to, rollback_token, ledger}
    commit(node, evidence_ref, condition_space, snapshot_id) -> {committed, moved_to, node_id, decision_state, ledger[]}

「改」是四层门控，缺一不可：判定（verify 三态）→ 状态机（逐级，不跳级）→ 回滚（token，前像＝执行时点）→ 授权（三档自治＋审核队列）。

**实现状态（2026-10-18 核对，外部 issue #5 追问后补）**

| 动作 | 实现状态 | 证据 |
|---|---|---|
| 取 retrieve | **已实现**（2026-10-18）：md_cg/retrieve.py 返回定型 Envelope | conformance 第 5f 步 envelope |
| 算 judge | 部分：四态在，**work_done 走的是形式完备闸**，语义判定外置 | §10.1 |
| **改 revise** | **已实现**（2026-10-18）：md_cg/revise.py — revise + rollback | conformance 第 5c 步 revise_rollback |
| 存 commit | 在：condgate + condaccept + 落盘 + 台账 | §10.0 conformance |

**"改"整条缺失是当前最大的落地缺口**——上面那个签名是**设计**，不是既有能力。
读者若据此以为能修订、能回滚，会做出错误假设。故：

- 本节签名一律视为**目标态契约**，不代表代码已实现；
- conformance 有对应步骤（revise_rollback / anchor_verify）把这条钉成可见读数；
- 修订语义的三个未决问题（取代态 / 双降权维 / 并发）见 §8.4。

## 六、职责边界

### 6.1 三条准入判据（任何新需求先过）

1. 需要跨会话持久、可审计、可回滚的**状态**吗？否 → 不进。
2. 必须确定性、可复跑吗？否（必须生成式）→ 归深算。
3. 会改变「谁有权改」的契约吗？是 → 归 CTP。

### 6.2 负路由（与四态裁决同构）

先问「能否证明它不适用」——能证明即 REJECT，不必进入能力评估。**拒绝优先于接受。**

### 6.3 明确不做

生成推理（生成器）｜语义真值判定（无人可判）｜跨主体权利（CTP）｜评测自评（《秤》）｜编排调度（蜂巢）｜阈值与档位（设计者）｜训练改参（训练侧）。

## 七、接缝（与相邻系统）

| 系统 | 关系 | 分界 |
|---|---|---|
| 上下文系统（context-lab） | 本系统的 **P6 消费者** ＋ T2 后端调用方 | 它决定可见面，本系统决定持久面 |
| 生成器（LLM） | 外部 | 深算归它，本系统只备料与裁决 |
| CTP | 横向互操作 | 跨主体权利不裁定 |
| 《秤》 | 外部度量 | 不可自评 |
| 蜂巢 | 执行面 | 不管调度 |

**三条接缝纪律**：

- **I13** 本系统不得代做「该不该注入」的决策——接口必须无此能力。
- **I14** 回执不得自带真值——删掉原文后校验必须失败。
- **I15** 降级只作用于状态与投影，原文与记录永不随之消失（见 §8 生命周期：archived 是状态不是删除）。

失败传递：T2 握手失败 → 显式降级 T1 并写明原因；显式指定后端却不可用 → 启动期报错（不静默降级）；本系统 timeout/partial → 一律 hit_count=null，**不得让上层读成「没有这条记忆」**。

## 八、信息生命周期（v1.2 新增，接既有实现）

「不遗忘」的指代必须写清楚，否则会推出「存储必然单调增长」的错误结论。

### 8.1 五档状态机（v1.3 草案：新增 superseded）

真源：md_cg/lifecycle.py，状态全集与迁移表单点定义。

    active → converged（同构聚合定型，降权轴）→ demoted（importance 弱化，降权轴）
           → superseded（被新版本取代）→ archived（退出默认检索面，文件保留、可恢复）

| 状态 | 默认检索/注入面 | 语义 |
|---|---|---|
| active | 参与 | 缺键或非法值同此（fail-open，存量零迁移） |
| converged | 参与（降权） | 同构聚合已定型，**不是退役** |
| demoted | 参与（降权） | importance 被下调，**不是退役** |
| **superseded** | **默认剔除** | **被新版取代的旧版本**：有新版、旧版退出默认检索面，文件保留、可恢复（与 archived 的「主动归档、不再需要」区分） |
| archived | 默认剔除 | 退役不删除：节点文件仍在、可显式恢复 |

迁移纪律：**禁止跳级**（active→archived 被拒）；archived→active 需显式恢复。
判据单点 lifecycle.is_archived(e)，检索面／stg 面／续接包共同引用，不各写一份口径。

### 8.2 两条处置路径，指代不同故不冲突

| 信息类别 | 处置 | 约束 |
|---|---|---|
| **非保护信息**（临时信息、噪音、一次性过程） | 遗忘曲线降权 → converged/demoted → archived；旧段冷热分层压缩归档，只留索引指针，审计时按需解压 | 可降权、可归档、可压缩；**永不物理删除**（可逆、可审计） |
| **受保护信息** | **永久 active** | 禁止进入 converged/demoted/archived 任一档；禁止覆盖 |

**受保护 = 什么？以代码谓词为准（P1-7 修正，2026-10-18）**

此前本节写「七类不可遗忘 = 永久 active」，但那**不是代码能判定的集合**。实际谓词是
md_cg/protect.py 的 is_protected_entry()，三条真源：

| # | 真源 | 判定 |
|---|---|---|
| 1 | 层保护 | layer ∈ {self, anchor} |
| 2 | 显式位 | frontmatter.protected is True |
| 3 | 按分保护 | importance ≥ 0.70 且 importance_source ∈ {None, "hint"}（heuristic 不触发） |

**七类与这三条不是同一集合**：一条写在 knowledge 层、importance 0.5、未打保护位的
「信任评估记录」，按本节旧表述该永久 active，按代码**却不受保护**。

处理（外部评审第二份建议二选一，此处取第二条）：**把七类降为「政策清单」，可执行
承诺只保留上述三条谓词**，并给出可判定的落地方式——要让它真受保护，必须满足其一：

    layer=self/anchor          或
    protected=True（附 protection_reason 说明属哪类）   或
    importance ≥ 0.70 且 importance_source="hint"

**不保留代码无法验证的「恒为 active」声明**。这条落差的实测断言见 §10.0 conformance

**判据**：「不遗忘」只约束右行。左行走遗忘曲线——这正是「遗忘」与「不遗忘」能共存的原因，**它们作用的对象不同**。

### 8.3 残余张力（这才是真正未解的部分）

七类不可遗忘**只增不减**且永久 active，因此**受保护集本身无界增长**。冷热压缩能压低非保护信息的存储与检索开销，但对受保护集无效——它不能降权、不能归档。

本节如实声明：**受保护集的无界增长未解**。这与上一版笼统的「盲区 61 未解」不同：非保护信息的处置路径已经完整（且有实现），未解的只是受保护集这一块。

### 8.4 修订语义的三个未决问题（v1.3，外部 issue #5 提出并核对成立）

**① 缺「被修订取代」状态（superseded）——最大的结构性缺口**

revise 是四动作之一，而 P2-3 内容寻址下修订必然产生**新节点**。旧版本怎么办？

| 处理 | 后果 |
|---|---|
| 留 active | 检索面污染：新旧两版并存，且必撞 V4 同槽冲突 |
| 直接 archived | 违反状态机「禁止跳级」（active→archived 被 TRANSITIONS 拒绝） |
| 受保护信息「禁止覆盖」 | 纠错只能追加 → 双 active 版本 |

现状：md_cg/lifecycle.py 的 STATES 只有四档，**没有 superseded**；revise 本身也未实现
（§五 实现状态表）。故这不是"实现错了"，而是**语义尚未定义**。

**已裁定：方案 A（2026-10-18 使用者选定）——增设 superseded 档，已落地**

    STATES    = active → converged → demoted → **superseded** → archived
    _RANK     = 0 / 1 / 2 / **3** / 4

    新增迁移：
        active    → superseded      在用状态可被取代（取代不必先降权）
        converged → superseded
        demoted   → superseded
        superseded → active         撤销取代（回滚到旧版）
        superseded → archived       进一步归档
    刻意不收录：
        superseded → converged / demoted   被取代是「版本关系」，不与「重要性弱化」混轴

    **判据单点拆成两个**（避免一名多义）：
        is_archived(e)   仅 archived          —— 原语义不变，显式管理面仍用它
        is_retired(e)    archived ∪ superseded —— 检索面/拓扑面改用它

    落地范围：lifecycle.py（状态机 + is_retired）、mdcg.py 检索候选面、
    chain.py 拓扑面（两处 is_archived → is_retired）。
    conformance 第 5 步 supersede_semantics 钉住四条：旧版状态=superseded、
    is_retired 真、is_archived 假（可区分）、新版不受影响、旧版仍可 get 读回。

**② converged 与 demoted 被排成线性链，但语义是两个独立维度**

聚合定型（converged）与 importance 弱化（demoted）可任意先后发生，而现有状态机把它们
编码成深度 1 与深度 2：允许 active→demoted（跳过聚合），但**不允许 demoted→converged**
——即「已弱化后又被聚合定型」无法表达。

澄清（不是缺陷，是限制）：_RANK 的线性序位只用于两件事——**禁止跳级**与**受保护豁免**，
不表示"必须先聚合再弱化"。但表达力确实不足。

方案：改为两维标志位（聚合定型 × 弱化程度）＋ archived 开关；或补全迁移表并接受
「已弱化未聚合」不可表达。属 v1.3。

**③ 并发语义完全未提**

同槽并发 revise/commit 如何仲裁？现状：**单写者假设**（库层有 node_write_lock 串行化
同 id 落盘，但没有跨版本的 CAS）。未来 revise 落地时应采用乐观并发——

    revise 返回的 state_from 天然可作 CAS 前置条件：
    state_from 与当前状态不符 → DEFER 并让调用方重读，而不是覆盖。

**未声明并发口径前，「可复跑」KPI 在并发下不可达。**

### 8.5 封装链为何不含 P4（外部 issue #5 第 10 条）

§四 的封装链是 P1→P2→P3→P5→P6，**P4 会话层刻意缺席**，理由：

- P4 决定的是**可见性**（谁能看到这条记录），作用于读取时的投影，不改变记录本身；
- 把会话头塞进记录会让「同一条信息因观察者不同而有不同封装」，违反 I17（投影不得自称权威）；
- 会话身份在 §五 的四个动作里作为**显式参数**传递（scope / session），不是隐式上下文。

### 10.1a 锚定与独立校验（I14 的代码落点）

理论依据：§3.2.1 结构锚定记录（架构层 70–98 行）——五字段（锚定标识／授予方／
接收方／时间戳／状态摘要）＋三条验证需求（不可篡改、**可独立校验**、多节点冗余）。

实现在 md_cg/anchor.py，字段按原文对齐，并额外分出 content_hash（正文指纹）与
state_digest（结构状态摘要）两个：前者判「内容变了」，后者判「结构变了」，
分开才能分别归因。

**I14 的落点**：回执**不含正文**，只带指针与摘要。故

    原文不存在 → 校验必须失败（reason=missing_node）
    正文被改写 → 必须失败（reason=content_changed）
    回执被篡改 → 必须失败（content_changed）

若回执能脱离原文独立"通过"，它就不再是回执，而是一份冒充原文的投影（I17）。

**诚实边界**：三条验证需求里，**多节点冗余未实现**——那是部署面的事，单库内做不了。
本模块也不声称实现了完整的「协定式自我赋予」流程（属 L3 契约面），它服务的是
「信息锚定 + 回执校验」。

### 10.1 形式完备闸（原称「验收器」——名不副实，已正名）

**能力边界（2026-10-24 社区评审后的自核）**

本闸零 LLM，三个阻断判据的实际能力是：

| 判据 | 实际做的事 | 做不到的事 |
|---|---|---|
| V1 条件空间齐全 | 检查四维键非空 | ——（本就是结构检查） |
| V2 见出处标记 | **正则匹配**「依据／出处／来源」、节号、node_id、实测读数等标记 | 判不出该出处在**语义上**是否真能支撑本条断言 |
| V4 无字面同槽冲突 | CCG 三要素指纹相同 + 前 200 字**字面**不同 | 判不出「换种说法还是同一条」，也判不出「字面不像但意思冲突」 |

故本闸只做**形式完备**判定：

    ACCEPT  = 形式完备（字段齐、见出处标记、无字面同槽冲突）
    REJECT  = 形式不完备（并说明缺什么）
    ⇒ ACCEPT 不等于内容为真

响应体恒带两层解耦语义：acceptance（formal_pass／formal_reject）与
verification_state（本闸恒给 unverified——它无权判真）。两者**刻意不合并**，
合并会让「形式过了」被读成「内容对了」。

**语义判定归谁**：架构 P3 的 verify（外部基底／验证单元）。把它塞进零 LLM，
是把「能不能判」与「判得对不对」混为一谈。

**已知缺口（不假装已完成）**：节点 frontmatter 尚未落这两个字段（需改
mdcos.add 的 fm 构造，属跨模块改动），当前只在写入响应面提供。

work_done 类写入的**形式完备闸**应审**信息**，不审文件（原写「验收器」，已随正名统一）：

| # | 判据 | 失败态 |
|---|---|---|
| V1 | 断言显式声明条件空间四维 | 缺 → **REJECT（打回写入方）** |
| V2 | 证据引用可回溯到具体投影位置 | 不可回溯 → REJECT |
| V3 | 同一信息的多份投影互相一致 | **只读旁证**（记录不阻断）——理由见下 |
| V4 | 与已固化的同槽信息不冲突 | 冲突 → REJECT（负路由优先） |
| V5 | 冗余投影已合并，未新增重复条目 | **只读旁证**（记录不阻断）——理由见下 |

**为什么 V3/V5 不阻断（外部评审第三份 2.2 追问的落差，此处正面回答）**

V3/V5 都要在**写入时**检索「同信息的其他投影」「同槽的既有条目」，而这两项在实现上
有两个未解风险：写时检索的代价（每次写入都要扫索引）、以及自指（正在写的这条会不会
被自己检索到）。在这两点解决前，把它们做成阻断判据会同时引入性能问题与误判。
故明确为**只读旁证**——记录读数，不改变判定。这是**有意为之**，不是遗漏。

代价要讲清：这也意味着 §2.4「同一信息只算一条知识（去重按信息）」目前**只是约定，
不是强制**——重复投影仍可入库，只是被记录下来。这一条已列进 R 类待办。

原「文件存在／行数／章节齐备／哈希一致」一类检查**降级为载体可核对性**，只能支撑 V2，不能单独构成 ACCEPT。

**为什么 V1 是打回而不是入队（2026-10-24 使用者裁定）**

| | DEFER 入队 | **REJECT 打回（本架构）** |
|---|---|---|
| 责任方 | 裁决者 | **写入方** |
| 后果 | 占裁决队列，等一个不会来的裁决 | 立刻告知缺什么，作者补齐重提 |
| 实测代价 | **队列** 957 条中 954 条缺条件空间（注意：这是队列写入 payload 的构成，**不代表已落盘节点**——落盘节点实测 87.7% 合格，见 §10.0 口径订正） | 不入队，不占裁决资源 |

判据：**缺条件空间是作者未声明，不是裁决者未判断**。把作者的责任转嫁给裁决队列，就是那 954 条积压的成因。

**归档的正确含义**：archive 不是移动文件，而是该**投影可见等级**降级；信息本体仍在（P2 退役不删除）。目录整理只是这一语义在文件系统上的当前实现，不是协议条款。

## 十一、接口形状（issue #5 第 15 条）

四个动作此前只有签名、没有字段表。现已定型**已实现的部分**，并与实现共用一份定义：

真源：md_cg/interface_schema.py（schema 与 golden 例子同文件，文档与测试共同引用）。

    detail.acceptance          formal_pass | formal_reject | undetermined
    detail.verification_state  unverified | confirmed | weakened | falsified
    detail.return_to           可选：author | adjudicator（责任方）
    detail.action              可选：补救动作

**Envelope**（retrieve 的返回，**目标态，未实现**）

    items[]            条目数组
    completeness       bool（false 时不得进入零命中路径，见 I2）
    hit_count          int | null（非 success 时恒 null，见 I1）
    snapshot_id        str | null（跨快照比较必须显式声明）

**Ledger**（账本条目，部分实现）

两条纪律：

1. **golden 例子与 schema 同文件**：verdict_accept／verdict_reject／verdict_blindspot

2. **schema 只约束已实现的部分**：把目标态字段写成必填，会让实现永远无法通过校验，

## 附录 B：七类不可遗忘（政策清单，非代码谓词）

信任评估记录｜偏差历史｜价值观迭代史｜协作校准过程｜内化阶段记录｜协定式自我赋予史｜自我锚点。

**性质**：这七类是一条**政策**（应当永不遗忘），不是代码可判定的集合。代码能判定的
只有 protect.py 的三条真源（层保护／显式位／按分保护）——见 §8.2。

**落地方式**（要它真受保护，必须显式满足其一）：

| 方式 | 写法 | 适用 |
|---|---|---|
| 层保护 | 写入 self 或 anchor 层 | 自我锚点类 |
| 显式位 | protected=True，并在 protection_reason 写明属哪一类 | 其余六类 |
| 按分保护 | importance ≥ 0.70 且 importance_source="hint" | 重要度直观可判时 |

**未按上述任一方式声明的七类内容，代码不保证其永久 active**——这是诚实的边界，
不是遗漏。§10.0 conformance 有对应断言（protected_not_demoted）把三条谓词钉住。
