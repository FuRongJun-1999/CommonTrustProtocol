# 灵枢架构展示 · 第四段：可解释性案例集（2026-08-28）

> 主张：白箱的核心价值不是「更聪明」，是**每步决策可追溯**——
> 包括错误也可定位、可归因、可修正。本节用四个真实案例（三正一反）
> 展示可解释性在实际运转中的形态。全部案例可复现（commit 号可查）。

## 案例一 · 通道 B 三缺陷闭环（失败→留痕→修正→固化）

**背景**：通道 B（LLM 初稿 → 物理裁决 → 固化）在消化队列时卡死。

**可追溯链**：
1. 观察层捕获：`bootstrap_log.jsonl` 显示 queue 多轮未消化
2. 根因定位（三缺陷）：failed 无标记无限重试 / llm_api 无 cases 条目
   永久占位 / 写回覆盖人工条目
3. 修复提交 `3743578`（diff 可查每一处）
4. **拒绝留痕**：`rejected_log.json` 记录每次物理裁决失败
   （任务/层/原因/时间戳）——「列表串接」cases 嵌套错一层被拒的
   完整记录在案
5. 收敛：子串判定/列表串接先后 verified，固化库 12→13

**黑箱对照**：LLM 系统的同类失败只会表现为「效果变差」，无从定位。

## 案例二 · CSRE 索引自动重建（退化被传感器捕获）

**背景**：CSRE 词向量索引是静态 npz 快照——新增知识卡后新词不入
词典，路由对这些卡**零向量**（不可见的静默退化）。

**可追溯链**：
1. 基准暴露：18 问一致性测试 28%（正确率口径显式排除空值——
   空串 `in` 恒真的假 100% 教训在案）
2. 根因：快照过期（2846→2871 行）——手动重建后 56%
3. **机制化**：bootstrap_loop 每轮 kp 指纹比对（COUNT+MAX(created_at)
   sha256），变化才重建——`csre_rebuild` 事件两次自动触发实证
   （2874/2880 行，与新卡入库精确对应）

**意义**：静默退化被变成有声事件——这是可解释性的高级形态。

## 案例三 · 验收器自验收（T9 数据作废声明）

**背景**：T9 项目级对照一轮/二轮数据「A 贵 68%、双败 5 轮」——
数据形态看起来完全合理。

**可追溯链**：
1. T10 自验收（手工正确实现 × 全断言）暴露 NameError——
   断言文本引用 `ns[...]` 但执行命名空间无 `ns` 键
2. **T9 全部数据作废**（公开声明，不掩饰）：第一轮实现必然
   NameError 必败；failing 带断言文本 → 模型第二轮「学会」造
   ns 字典满足断言——实测的是错误的东西
3. 修复：`ns['ns'] = ns` 自引用（`fba77f1`）+ 教训写入知识层
   （importance 0.95）：**验收器必须先用手工正确实现自验收**

**意义**：可解释性不仅对外（解释给用户），也对内（发现自己的
验收器坏了）。黑箱 benchmark 出现同类缺陷只会产出错误的分数。

## 案例四 · 规范型卡纪律（从实验反哺到写卡规范）

**背景**：T9 排序项目 A 组 5 轮失败——归因过程逐变体排查，锁定
卡文案的「像整理手牌」类比文字干扰实现方向。

**可追溯链**：
1. 归因：描述型卡 vs 规范型卡对照（字符串项目 A 组 2 轮过的正例）
2. 反哺：单源规范新增「四·五节 写卡纪律 · 规范型优先」四条
   （`c6296f1`）——执行字段必须精确行为规范/按用途分卡型/数值
   边界显式/直答兼顾判定口径
3. 落地：T10 预置卡 3 张全部按新纪律写，card_route 冒烟 3/3

**意义**：实验结论不停留在报告里——变成写卡的永久纪律。
