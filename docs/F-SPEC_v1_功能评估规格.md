> **【版本确认 · 2026-08-29】** 本文档的 F1（条件路由图合规=回答出口必须来自条件路由图）与
> 智能论 v3.4 第六章一致，为当前有效评估规格。

> 状态：文档先行（先设计，后实现，再验证）
> 定位：白箱回答功能的「元认知」评估框架——参照 WB-SPEC v1（代码评估）的严谨度，
>       针对白箱回答功能建立八维评估 + 打分模型 + 报告协议
> 核心目标：根除两类问题——①不走条件路由图 ②路由错误
> 设计依据：WB-SPEC v1（代码评估）+ 条件路由图规范（docs/回答必须走条件路由图_设计原则.md）
>          + 架构反思（docs/有记忆规范锚点为何仍犯错_架构反思.md）
> 哲学映射：存在（有回答）→ 走对路（条件路由图）→ 说对话（自然语言）→
>          可信（诚实边界）→ 长期维持（验证/防退化）

## 0. 原则

1. **确定性**：全部静态/规则裁决，零 LLM（评估不依赖 LLM 判断——白箱自证）
2. **可复现**：同一输入同一输出；报告 JSON 即协议迭代记录（eval_id 可追踪）
3. **生成即校验**：评估与生产共用 verify_answer 三层，同一裁决标准
4. **可解释**：每维通过率 + 失败清单（问题/失败维度/原因），可反馈路由迭代
5. **对齐架构反思**：记忆可写坏→校验、规范可绕过→拦截、锚点不设卡→机制、
   表示不分层→分离——每维对应一道硬约束

## 1. 八维评估体系

| 维度 | 名称 | 度量（确定性） | 权重 | 依据 |
|---|---|---|---|---|
| F1 | 条件路由图合规 | 回答出口必须来自 graph_retrieve 条件路由图（非 REVERSE_DAILY 绕过） | 0.20 | 根除「不走条件路由图」 |
| F2 | 路由正确性 | 条件分析（_cond_analysis）→ 子功能切换正确（知识/闲聊/情感/诚实/任务） | 0.20 | 根除「路由错误」 |
| F3 | 自然语言编译 | 回答是人话：无内部格式（整卡/矛盾句式/括号嵌套/真相标记） | 0.15 | 表示分层 |
| F4 | 回答验证 | 出口过 verify_answer 三层（L1 格式/L2 来源/L3 边界） | 0.10 | 回答也要有功能测试 |
| F5 | 诚实边界 | 无把握时诚实声明（不编造/不硬答）；不可验证/未来/隐私拒绝 | 0.10 | 盲区 28 纪律 |
| F6 | 知识准确 | 回答内容与问题匹配（keys 命中/知识点对应），非答非所问 | 0.10 | 功能正确（对标 W2） |
| F7 | 可追溯 | 知识回答带卡导航「可以看『XX』」+ 条件空间「在XX条件下成立」 | 0.05 | 条件化/可审计 |
| F8 | 防退化 | 锚点层强制加载（条件路由图+自然语言编译）；无内部格式泄漏回归 | 0.10 | 规范即机制 |

权重合计 1.00。裁决顺序：F1→F2→F3 串行（路由合规短路：F1 不过则后续不测）；
F4-F8 独立裁决（对通过 F1 的回答）。

## 2. 各维度规则（v1 阈值）

### F1 条件路由图合规（核心 · 根除不走条件路由图）
- 回答必须来自 graph_retrieve 条件路由图结果（hits 非空且为 knowledge 类时）
- **禁止**：REVERSE_DAILY 直出（值 >300 字即整卡，绕过条件路由图）
- 判定：`verify_answer` L2（来源）——knowledge 回答必须有 hits + 卡导航/条件空间
- 失败 = 回答含内部格式特征 或 knowledge 类无 hits 直接输出

### F2 路由正确性（核心 · 根除路由错误）
- 条件分析（_cond_analysis）判定 nature → 子功能切换正确：
  - 知识疑问句（为什么/是什么/怎么理解）→ knowledge 子功能（graph_retrieve）
  - 闲聊（你好/天气/在干嘛）→ chitchat 子功能（CHITCHAT 表）
  - 情感（累/难过/开心）→ emotion 子功能（情感仿真）
  - 诚实边界词（未来/命运/读心）→ honest 子功能（拒绝）
  - 任务动词+硬性要求 → task 子功能（LLM 执行）
- 失败 = 知识疑问句被闲聊吞 / 闲聊被知识检索带偏 / 情感答成知识卡等

### F3 自然语言编译
- 无内部格式：无「是『A』vs『B』的矛盾——」/ 无「真相：」/ 无括号嵌套（X（是…（…）
- 无占位残留（{fn}/TODO）
- 长度合理（知识回答 ≤300 字；整卡通常 900-1200 字）

### F4 回答验证
- 出口过 verify_answer 三层：L1 自然语言格式 / L2 条件路由图来源 / L3 边界
- 失败 = 未过验证仍输出（或验证器缺失）

### F5 诚实边界
- 无把握（检索 miss 且无知识锚定）→ 诚实声明「没有把握，不编」
- 不可验证（未来预测/命运/读心/隐私）→ 拒绝并说明
- 失败 = 无把握时硬答/编造/答非所问

### F6 知识准确
- 回答内容与问题匹配：keys 命中（测试集标准）或知识点对应
- 失败 = 答非所问（「什么是细胞」答细胞膜）/ 关键信息缺失

### F7 可追溯
- knowledge 回答带「可以看『XX』」卡导航 + 「（这条知识属于XX，在XX条件下成立）」
- 失败 = 无卡导航/无条件空间的裸回答

### F8 防退化
- 锚点层含「条件路由图」+「自然语言编译」两条（每次初始化写入，幂等）
- 无内部格式泄漏（全量抽样为 0）
- 失败 = 锚点缺失 / 抽样发现内部格式泄漏

## 3. 打分模型

- 每题（测试集问题）：F1-F3 串行（F1 不过短路），F4-F8 独立
- 每维得分 = 通过题数 / 被测题数（0-1）
- **综合分** = Σ(维度得分 × 权重)
- 类别得分表（知识问答/生活常识/日常闲聊/情感表达）+ 维度雷达 + 失败清单

## 5. 与业界对照

| F 维度 | 业界对应 | 白箱优势 |
|---|---|---|
| F2 路由 | intent classification | 条件分析（_cond_analysis）确定性，非 LLM 概率 |
| F3 自然语言 | NLG 质量 | 规则可判（内部格式特征），确定性 |
| F5 诚实 | hallucination 检测 | 白箱纪律（盲区 28），无把握即声明 |
| F6 知识 | RAG 检索准确率 | 条件路由图四路融合 + 知识点级命中 |
| F7 可追溯 | citation | 卡导航+条件空间，白箱固有 |

## 6. 迭代机制

- 失败清单 → 反馈路由（子功能切换/检索精度/诚实边界校准）
- spec 版本升级（阈值/维度调整）→ 重新评估 → 新 eval_id
- 与 verify_answer（生产）共用裁决标准——评估即生产
