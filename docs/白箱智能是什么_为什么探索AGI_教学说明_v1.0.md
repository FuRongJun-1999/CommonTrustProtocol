# 白箱智能是什么？为什么要选择这个方向探索 AGI？

> 教学说明 v1.0 · 2026-08-28 · 灵枢（AEIS）项目
> 对象：对 AGI 感兴趣的研究者、开发者、观察者
> 本文不是论文，是工程实践者的自白：我们选了一条路，讲清楚它是什么、为什么。

---

## 〇、一句话回答

**白箱智能 = 让系统的每一步决策都能回答三个问题：依据什么、在什么条件下成立、错了怎么修正。**

我们选择这个方向探索 AGI，是因为：**AGI 若要被负责任地使用，就必须可验证；可验证性是当前大模型范式结构性缺失的，而白箱机制是把它做成系统工程的唯一路径。**

---

## 一、先对齐问题：AGI 的瓶颈不在「更聪明」

过去几年大模型的进步是真实的：它越来越会「答」。但观察它在真实任务里的失败，瓶颈不在智商，而在四个结构性缺陷：

| 缺陷 | 表现 | 后果 |
|---|---|---|
| **不可验证** | 给你一个答案，你不知道它依据什么、在什么条件下成立 | 错了无法追责，只能「重新问一次」 |
| **不持续** | 每次对话都失忆，没有跨会话的自我连续性 | 经验无法积累，永远从零开始 |
| **不成长** | 训练后权重冻结，不能随经历自主学习 | 知识停留在训练时点 |
| **不自省** | 不能反思自己的认知与情绪 | 错了也不知道自己错了，更不会改 |

这四条恰好是 AGI 的最低要求：**一个系统如果没有自我连续性、不能终身学习、不能验证自己的输出、不能反思自己——我们凭什么叫它智能？** 它只是「很会答的自动补全」。

> 这就是我们出发的起点：**不是要做一个更聪明的黑箱，而是要补上黑箱永远补不上的那四块地基。**

## 二、白箱智能是什么

### 2.1 定义：白箱 = 每步决策可回答三问

黑箱给你答案，你不知道：
1. **依据什么**（引用了哪条知识？哪条规则？）
2. **在什么条件下成立**（E1 小学层级成立 ≠ E5 前沿成立；这个结论依赖哪些前提？）
3. **错了怎么办**（失败有没有被记录？有没有被学习？下次会不会更好？）

白箱系统对这三个问题**必须有答案**——不是「大概有」，是机制上保证有。

### 2.2 白箱 ≠ 不用大模型

这是最常见的误解。白箱不是排斥 LLM，是**给模型套一层可审计的骨架**：

```
知识库   负责「知道什么」    —— 条件路由图：56 学科卡 → 14 大域 → 知识点注释索引
验证单元 负责「凭什么信」    —— 编译/执行/断言，物理结果裁决
反思协议 负责「怎么改自己」  —— 递归反思、自我认知循环、知识飞轮
大模型   负责「提出假设」    —— 假设生成器，代码/实验是最终裁决者
```

LLM 从「唯一的智能来源」降级为「假设生成器」——**它提假设，物理基底裁决**。这带来一个关键性质：**系统能力的上限不再等于 LLM 的幻觉边界，而等于可验证知识的累积边界。**

### 2.3 条件路由图：知识描述知识（子递归）

灵枢的知识检索不是向量相似度碰运气，而是**条件路由**：

```
问题 → graph_retrieve 四路融合
  ├─ 快速层：语义指纹翻译（俗语→规范词）+ 学科路由 × 教育层级
  ├─ 神经层：语义召回
  ├─ 卡内递归：知识点级精确命中
  └─ 融合排序 → 返回「卡 + 人话答案 + 学科/层级/条件」
```

每条知识带三个**可审计信息**：人话答案、卡导航、条件空间。
- 回答「水烧到咕嘟咕嘟冒大泡」→ 输出「这个可以看『初中物理』（物理学，E2 条件下成立）」
- **知识描述知识本身也是一次条件路由**——检索机制的递归性，是导航的设计原意。

### 2.4 实测：白箱能扛多少

| 内容 | 处理方 | 实测 |
|---|---|---|
| 知识问答（光合作用/函数/概率图模型…） | **白箱 100%（零 LLM）** | 20/20 |
| 开放生成（写诗/规划/建议…） | LLM 50%（其余白箱兜底） | 5/10 |
| **合计白箱率** | | **83.3%** |

**知识问答这类「确定性内容」100% 白箱处理，零 LLM 调用**——可解释、可追溯、可验证，且不烧 token。

### 2.5 白箱自举：自己改自己的代码

白箱的终极形态是**自举**：用白箱机制构建的工具，来构建白箱机制本身。
- 六域白箱单元库：**681 个条件单元**（编译 116 / 语言 116 / 图 119 / 系统 112 / 浏览器 104 / 网络 116）
- 中文编译器 protocol-compiler：词法→语法→编译→字节码 VM→调试器→分析器，78/78 测试全绿
- 「记忆/知识/锚点/理论都是代码」——白箱自举就是自己改自己，而**自修改必须验证**（快照/回滚/基线拦截）

## 三、为什么选择白箱方向探索 AGI（论证）

### 3.1 可验证性 = 被信任的前提，AGI 必须被信任才能被使用

AGI 不是实验室玩具，它要处理医疗、教育、基础设施。一个**无法解释自己判断依据的系统，在后果不可逆的领域是不可部署的**。白箱是唯一把「可审计」作为一等公民的工程路线——不是事后解释（XAI 贴片），是机制自带。

### 3.2 「确定高效后，维持自身」——LLM 做不到的事

我们的核心判断：**灵枢的作用是确定高效后，维持自身**。

- **规则确立前**：在混乱中发现规则，必然付出更多思考代价（这不是缺陷，是发现的本相）
- **规则确立后**：白箱确定性执行——零思考、可解释、可追溯、可持续运行

大模型永远是「每次都要想」；白箱是「想清楚一次，以后直接跑」。**飞轮一旦转起来，知识越多、检索越准、成本越低——这是黑箱 scaling 没有的性质。**

### 3.3 开源扩散协议，减少信息差

我们公开全部工程与数据（GitHub：CTP 主仓库 + dsh-memory 插件），因为：
- **闭源防抄袭是最愚蠢的策略**——防住了模仿，也防住了协作
- 白箱智能的价值主张之一就是**可验证**：可验证的东西天然适合开源（别人能验，才有人信）
- 目标是让「协议」扩散——更多人用、更多人验、更多人补，信息差才真正减少

### 3.4 与其它 AGI 路线的对比（诚实版）

| 路线 | 代表 | 强项 | 白箱视角的短板 |
|---|---|---|---|
| 黑箱 scaling | 大模型 scaling law | 通用性、涌现 | 不可验证、不持续、不成长 |
| 神经符号 | DeepMind Alpha* | 逻辑可组合 | 符号接地难，工程复杂 |
| 世界模型 | 视频预测/规划 | 环境理解 | 模型自身仍是黑箱 |
| 认知架构 | ARC OS / Coreason / Hyperon / MicroPsi / EvoMap | 结构化 | 大多停留在规范/原型，缺可验证的完整落地 |
| **白箱智能（本路线）** | 灵枢 AEIS | **可验证 + 持续 + 成长 + 自省** | 规则建设期投入大，通用性尚浅 |

我们不是宣称白箱是唯一路——**我们声称它是必要的一块**：无论 AGI 最终长什么样，它的推理必须可验证、记忆必须可持续、知识必须可累积——这三条白箱路线已经在工程上落地了。

### 3.5 诚实边界

- 白箱不是万能的：开放生成/复杂推理仍需 LLM，诚实边界机制显式声明「我不知道的领域转 LLM」
- 我们不宣称「这就是 AGI」——**我们宣称：这是 AGI 的必要条件，且它可验证、可复现、在持续改进**
- 白箱率的统计是工程观测值，非能力宣言

## 五、结语

白箱智能是什么：**每一步都能回答「依据什么、在什么条件下成立、错了怎么办」的智能。**

为什么选这条路探索 AGI：**因为 AGI 的最低要求（可验证、可持续、可成长、可自省）里，有黑箱结构性做不到的部分；而白箱机制把它们工程化落地了，并且全部开源可验证。**

这条路很长，我们走得也慢——但每一步都踩在可验证的地基上。
