# 灵枢确定性有效化 · 索引指纹化方案（v0.1 · 2026-08-27）

> 来源：Coreason「确定性」设计借鉴（设计者指令 2026-08-27）
> 核心命题：**条件路由图的确定性结构可以被密码学哈希有效化——每个索引都是可验证的指纹。**
> 目标：把灵枢检索从「语义层面确定性」（事实成立）升级为「密码学层面确定性」（可独立验证）。

---

## 一、问题与动机

灵枢白箱检索**当前已是语义确定性**（实测：同输入+同条件 → 3 次运行逐字节一致，
encode 确定，graph_retrieve 无随机/时间依赖）。但存在三个缺口：

1. **不可独立验证**：回答确定，但用户/审计方无法自行重算核对「为什么这么答」
2. **不可跨环境核对**：换机器/换库后，无法证明结果与原始环境一致
3. **不可防篡改检测**：知识库被改动，无法察觉（对齐 Coreason「不在 manifest 就不存在」）

Coreason 借鉴点：**规范哈希（RFC 8785 风格）+ frozen 不可变 + 排序确定**——
把「确定性结构」变成「密码学可验证结构」。

## 二、澄清：图 ≠ 哈希，但图的确定性可被哈希保护

| 维度 | 哈希函数 | 图检索 |
|---|---|---|
| 方向 | 单向（输入→输出，不可逆）| 双向可解释（可见路径、可追溯）|
| 状态 | 无状态 | 有结构（节点语义 + 边条件）|
| 信息 | 压缩 | 展开（保留全部语义）|
| 抗碰撞 | 靠「乱」（雪崩）| 靠「结构」（条件约束）|

**结论**：检索不是「输入密码」，而是「在确定迷宫里走可验证路线」——
哈希是给路线的**可核对章**，不是路线本身。

## 三、四层指纹设计

### 层级 1 · 节点指纹（每个知识单元一个）
```
fp_node = sha256( canonical( kp_content + KCCS四要素[生效条件/子功能/执行/不适用条件]
                                + edu_level + domain ) )
```
- 覆盖：知识卡、kp、学科卡、学段卡、元学科卡
- 变化：内容或条件声明改 → 节点指纹变

### 层级 2 · 边指纹（每条确定性连接一个）
```
fp_edge = sha256( canonical( 源节点fp + 生效条件 + 目标节点fp ) )
```
- 覆盖：causal / similar / sequential / spatial / hierarchical 边
- 变化：条件或端点改 → 边指纹变

### 层级 3 · 路径指纹（每次检索一个路由证据）
```
fp_path = sha256( canonical( 查询归一化 + 走过的节点fp序列
                             + 负路由排除集 + top_k 排序 + direct_answer ) )
```
- 每次 graph_retrieve 返回：结果 + 路径指纹
- 用户/审计方可独立重算核对「为什么这么答」

### 层级 4 · 整图指纹（知识库版本指纹）
```
fp_graph = sha256( canonical( 全部节点fp排序 + 全部边fp排序 + 代码版本 + 知识库版本 ) )
```
- 对齐 Coreason「God Context」确定性对齐理念
- 知识库被改 → 整图指纹变 → 可检测

## 四、实现要点

### 4.1 Canonical 序列化（对齐 RFC 8785 风格）
```python
def canonical(obj):
    """确定性序列化：key 排序 + 数组排序 + 无空白歧义"""
    import json
    def _sort(x):
        if isinstance(x, dict):
            return {k: _sort(x[k]) for k in sorted(x)}
        if isinstance(x, list):
            return [_sort(i) for i in x]
        return x
    return json.dumps(_sort(obj), ensure_ascii=False, separators=(",", ":"))
```

### 4.2 指纹注入位置
- 节点指纹：写入 `state_attributes.fingerprint`（与 KCCS 注释同层）
- 边指纹：写入 edges 表的 `fingerprint` 列
- 路径指纹：`graph_retrieve` 返回体附加 `"fingerprint": fp_path`
- 整图指纹：`engine_meta` 存 `graph_fingerprint`

### 4.3 与现有机制结合
- **verify_answer**：白箱校验时把路径指纹纳入证据链
- **固化纪律**：知识固化（domain_solidify）时同时固化节点指纹
- **可复现测试**：基准测试断言指纹稳定（同输入同指纹）

## 五、收益

| 维度 | 现状 | 升级后 |
|---|---|---|
| 可验证性 | 解释「为什么这么答」| **证明**（指纹可独立重算）|
| 可复现性 | 事实性一致 | **密码学保证**（跨环境必然一致）|
| 防篡改 | 无 | 知识库改动可检测（指纹漂移）|
| 对齐 Coreason | 理念 | **工程实现**（确定性有效化）|

## 六、边界（诚实声明）

- 指纹验证的是「检索路径的确定性」，**不验证答案正确性**（正确性由知识库内容保证）
- 指纹依赖「知识库 + 代码版本」——版本变更必须纳入指纹输入，否则升级后指纹全变（预期行为）
- 性能：每节点/边一次哈希，常量级开销，不影响检索延迟

## 七、节奏

- **阶段 1**：实现 canonical + 节点/边指纹（写库，幂等）
- **阶段 2**：路径指纹（graph_retrieve 返回附加）
- **阶段 3**：整图指纹 + 测试断言 + 基准回归

---

*本方案遵循条件路由图规范：生效条件=灵枢检索确定性升级；子功能=四层指纹可验证；
执行=三阶段；不适用条件=不用于验证答案内容正确性（那是知识库质量范畴）。*
