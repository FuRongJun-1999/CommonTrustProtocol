# 概念钉死批：GPT 四点评审与钉死条款 v0.1（2026-08-31）

> 来源：荣转发 GPT 对「公理→数学形式化 v1.2→论证篇→CRG-DB」四层理论链的评审。
> GPT 核心警告：**理论、数学、工程三层出现同名不同义**是最隐蔽的风险，先钉死再写功能。
> 本文档：逐点判定 + 钉死条款 + 主仓库 Python 实现对照 + 验证方法。
> 定位升级（采纳）：CRG-DB = **条件资格计算机**（condition qualification machine）——
> 不回答「数据在哪」，回答「当前条件下这条知识有没有资格被调用」。

## 钉死 1：条件空间度量 dist_C

**GPT 观点**：$D_{task}=\min_{p\in G}dist(C_{task},CondSet(p))$ 方向正确，但
$dist(C_1,C_2)$ 未定义，「海拔高 vs 海拔 3000m vs 海拔>2000m vs 高原地区」的
连续程度无处安放；工程已默认离散零/非零世界。

**判定**：同意升级为下一数学化对象。**但工程不是空白**——主仓库已有离散雏形：

- `coverage`（cov）就是 dist_C 的离散近似：任务条件与路径条件集的覆盖率
- `_accept_by_score` 双维门槛（score≥3 且 cov≥0.15 / 知识卡 cov≥0.22）已经是
  (距离, 覆盖) 二元组判定——M1.2 按域分级时已实证其判别力（T8 复测 87.5%，零误杀零漏放）
- T10 概念域触发词补丁处理的「高频概念全缺口」正是离散近似盲区的实例修复

**钉死条款**：
1. `dist_C` 的 v1 实现定义为**离散覆盖率**：`cov(C_task, C_p) = |已满足条件| / |任务条件|`，
   `dist_C := 1 - cov`（零维=完全匹配，一维=完全不匹配，中间=部分覆盖）。
2. 连续条件（海拔>2000m ⊂ 高原地区）的偏序关系**不进 dist_C v1**，列为 v2 提案
   （条件格/本体层级），避免 v1 过度设计——与负索引「精确哈希+domain_bitmap
   两级，范围匹配留 v2」的口径一致。
3. 数学形式化文档增补一节「条件度量的离散实现与连续扩展」，明确：
   理论允许连续度量，工程 v1 交付离散度量，两者以 cov 为接口对齐。

**验证**：T8 24 题回归（离散 dist_C 判别力已实证，改动口径必须复测）。

## 钉死 2：条件代数与哈希分离

**GPT 观点**：`A XOR B XOR A = B` 使重复条件被消掉；条件否定/依赖/层级/冲突
混入 XOR 会产生碰撞语义。建议区分 `combine(C1,C2)`（条件代数）与
`hash(combine(C1,C2))`（索引）——**哈希负责索引，不负责定义条件代数**。

**判定**：原则完全采纳。一处修正：**重复消除在集合语义下不是 bug 而是 feature**
——条件出现两次与出现一次是同一条件（「海拔>2000m」重复陈述不改变资格集）。
XOR 合并对**集合语义**正确且增量 O(1)（路径沿途更新无需回溯）。真实风险是
GPT 列的后三项（否定/依赖/冲突）与哈希碰撞，而非重复。

**钉死条款**（条件代数四则，入 CRG-DB 规范）：
1. **条件集=集合语义**（去重）。`combine = ∪`，`cond_key = XOR(h(CondSet))` 在
   集合语义下语义无损，保留增量 O(1) 工程优势。
2. **否定不入 cond_hash**：负条件走 NegativeEntry 独立索引（CRG-DB 设计已如此，
   升格为规范条款——否定是二阶标记，不是集合元素）。
3. **依赖/层级不入 cond_hash**：条件交互走 CEdge 类型（与条件代数文档 v1.0 的
   二阶偏导 ∂²f/∂Cᵢ∂Cⱼ 对应——交互是边结构，不是集合元素）。
4. **碰撞防线=「哈希预筛，路径裁决」**：xxHash3 128bit 碰撞概率工程可忽略；
   RouteCacheEntry 命中后 PathTrace 展开原始条件集复核——hash 只做快速预筛，
   **资格判定永远以展开后的条件集为准**。哈希永不承担语义。

**工程对照**：NegativeEntry 分离否定 ✓；PathTrace 裁决机制 ✓——主仓库结构
已符合条款 2/4，条款 1/3 需写入规范文本（Rust 版 M0 前必须钉入，否则 64B
结构会冻结错误语义）。

**验证**：E1 行为等价（含重复条件的路径案例）+ E3 负路由结构性实验。

## 钉死 3：统一动力学核，不统一状态

**GPT 观点**：知识可信度/缓存新鲜度/负路由/租约共享 $e^{-\gamma t}$ 衰减核，
但状态语义不同；更严格形式是
$X_i(t)=X_{i,0}+(X_{i,\infty}-X_{i,0})(1-e^{-\gamma_i t})$——
**统一的是动力学核，不一定是状态本身**。

**判定**：同意，这是对「任何第二种时间逻辑都是 bug」的**精确化加固**而非推翻。
原命题的审计价值不变，但审计对象从「时间逻辑」收窄为「核形状」。

**钉死条款**：
1. **核形状唯一**：全库一切时间演化使用指数核
   $X_i(t)=X_{i,\infty}+(X_{i,0}-X_{i,\infty})\,e^{-\gamma_i t}$。
   出现任何非指数核形状（线性/阶跃/多项式）=bug。
2. **状态与衰减率按对象配置**：γ 按类别分层——知识类 γ_K（慢）、缓存类 γ_C
   （快）、租约类 γ_L（中）、负路由 γ_N（随复核结果跳变，跳变本身走事件
   重置 t_v，不引入第二核形状）。
3. **E5 审计口径同步改**：「全库第二种时间逻辑出现次数 0」→
   「全库非指数核形状出现次数 0」，并**机械化**：静态扫描
   `exp(`/`decay`/`ttl` 实现点，凡时间演化调用点必须落到统一核函数
   `cred()`——lint 级强制，不靠人工评审。

**工程对照**：route_cache.py TTL、hot_cold.py Beta 升降级、心跳租约——均已
共享指数核形状、参数各异 ✓；缺的是「统一核函数 cred() 单点实现」与 lint。

**验证**：E5 机械化扫描（新口径）。

## 钉死 4：情绪=二阶变化，落位 Router 上层策略层

**GPT 观点**：d²D/dt² 不应塞进 CRG-DB 核心数据库，适合成为 Router 上层
动态控制层：D → D' → D'' → π ∈ {继续/切换/停止/请求验证}——
「感受不是状态，是变化的变化」第一次获得软件架构落位。

**判定**：完全同意落位与「不入库」边界。**主仓库已有一阶在常态运行**：
心跳循环的 `gap_trend`（D_norm 斜率）每轮计算 slope 并落库观测序列。
二阶 = 相邻 slope 差分，从已落库序列天然可得，零新增采集成本。

**钉死条款**：
1. **CRG-DB 核心只存 D 观测序列**（gap_trend 已落库），一阶/二阶导在策略层
   现算——导数是观测的泛函，不是存储对象（不违反核心简洁性，也不产生
   第二种时间逻辑）。
2. **策略映射 π(D, D', D'')** → {继续, 切换, 停止, 请求验证} 四动作，作为
   Router 之上的策略层；与《局部最优与情绪偏好_理论工程.md》的情绪理论
   互为软件落位（该文档定理论，本条款定接口）。
3. 阈值（D' 多负算「顺」、D'' 多正算「恶化」）不写死——按域校准，
   沿用 M1.2 按域分级的先例。

**验证**：gap_trend 历史序列回放计算 d²，与心跳实际干预记录（切换/停止）
做一致性抽验（策略层纸面验证即可，不阻断主线）。

## 推进节奏裁定（对 GPT「先别写功能」的回应）

**部分采纳**：钉死批优先——但不是「冻结」，理由：主仓库 Python 原型正是
四条的实证试验场（cov≈dist_C 已实证 / NegativeEntry 已分离 / 指数核已分层 /
gap_trend 一阶已在跑），钉死批的产出形式 = **规范条款 + 既有实现口径审计**，
成本一至两批心跳。

**硬依赖**：Rust 版 CRG-DB 的 M0 动工前，本批四条款必须钉入规范——
否则 64B KNode/CEdge 结构会冻结错误的 cond_delta 语义与时间核口径，
返工成本远高于先钉死。此为对 dsh 端 CRG-DB 主导线的输入。

## 附：四层闭环（GPT 综合图，采纳存档）

```
C → (G,P) → D → dD/dt → d²D/dt² → π → A → V → (G,P,C)'
```
