## 二、七大教训（按重要性）

### 教训 1：注释=图的索引——知识必须像代码一样有严格注释

**问题**：快速层理论是「学科路由提供类似函数注释的说明再索引」（对齐 CCG），
但知识卡 state_attributes 只有 `{name, domain, level, edu_level, kind, source,
kp_count}`——无四要素注释，domain 还是「高等代数知识点内容（按骨架填充）」
占位名 → 索引无源 → 快速层退化为 radical 粗粒度启发式。

**正解**（KCCS v0.1，用户 2026-08-26 指示）：
```
代码单元注释（CCG 四要素）    知识卡注释（KCCS 四要素）
# 生效条件：…                 生效条件：问{定义}时
# 子功能：① ② ③              子功能：定义/关键子句
# 执行：…                     执行：content 摘要
# 不适用条件：…                不适用条件：同卡相邻 kp 名
```
**粒度要求**：代码注释写到单个函数 → **知识注释写到单个定义**（kp 级，不是
学科卡级）。全库 2841 kp 批量生成 2825 个注释（覆盖率 99.9%）。

**落地**：`docs/知识卡注释规范_KCCS_v0.1.md`、`gen_kp_comments.py`（v1.39）

### 教训 2：匹配必须核对条件——不核对条件就会答非所问

**问题（用户三连问）**：「为什么匹配的时候又不看条件？又不核对条件？为什么
代码就能精确匹配到？」——CCG 精确是因为核对条件：生效条件命中（ACCEPT）+
不适用条件命中排除（REJECT/负路由）。知识域用全部注释文本做二元组匹配，
跳过了条件核对。

**实例**：
- 「三角形内角和」误配「三角形面积」——面积卡文本含『三角形』
- 「两个重要极限」执行文本含『三角』被「内角和」误配（how 不是 when）
- 「变质」kp（地理岩石）抢答「冰箱保鲜」「蜂蜜」——无负路由

**正解**：
- 索引只用【生效条件】（when），不用执行/子功能文本（how）
- 负路由：不适用条件命中 → 排除（对齐 ccg.search not_tokens）
- 字面通道始终评估（单字概念「熵」加分过门槛）
- 翻译命中（REVERSE_DAILY）确定性 > 学科卡扫描噪声

### 教训 3：检索像看地图——分层收敛，不是一条线找到尾

**问题**：「1+1等于几」线性管道（card_route→dex_respond→semantic_search→
融合→递归）失败——小学数学卡（正确域）因 direct 递归门槛失败被线性代数
（同域但更深）抢答 → 答成矩阵对角化。**因为域级没有先收敛**。

**正解**（two_stage_retrieve，用户 2026-08-26 指示）：
```
问题 → 第一阶段：56 学科卡聚合 14 大域，并行打分 → 收敛 top 域
     → 第二阶段：top 域内 kp 注释索引并行 → 收敛最匹配条目
```
多子线程并行、收敛返回最匹配——像看地图先大区域再小区域。

### 教训 4：半黑箱中间层（bge）两头不如——该退役就退役

**问题**：bge 是「翻译表没覆盖时的模糊兜底」，但：
- 白箱确定性不如注释索引（天空蓝→光的色散物理错、奇数→奇异值分解）
- 智能不如 DeepSeek LLM（质数→质量、emo→开心、铁球羽毛→初中地理）
- 975MB 依赖 + 71 权重文件

**正解**（用户 2026-08-26 指示）：「与其指望 bge 兜底，为什么不用更好的
deepseek LLM 模型？」CCG 已证明白箱检索无需嵌入（条件词+图结构达 99%）。
bge 移除 → 白箱检索纯确定性（翻译表+注释索引+学科路由+卡递归），miss 由
layered.route_reply 降级 LLM（DeepSeek 生成+白箱校验）。

### 教训 5：翻译表（REVERSE_DAILY）是条件路由图的翻译层，不是独立通道

**问题**：自主进化把 REVERSE_DAILY 559/649 键（86%）覆盖成整卡（>300 字）
→ 短人话直答全失效（同天空蓝 944 字污染）。bge 移除后无模糊召回 → 生活常识
类（晚上睡觉/手机充电/洗手/打哈欠）graph_retrieve miss → 组合引擎/诚实边界。

**正解**：
- 运行时恢复 `_restore_daily_short`：从整卡提取「总结：」段作短人话（幂等）
- 括号转义「X（Y）」→「X，Y」（保留信息，verify_answer L1 括号密度>8% 拒绝）
- daily 翻译命中优先于学科卡扫描（蜂蜜防腐 > 变质条目），弱于 KCCS 注释命中
- 修复防御：**补知识写入 state_attributes.comment，不覆盖 REVERSE_DAILY 字面量**

### 教训 6：回答域是路由的一部分——情感/闲聊是独立域

**问题**：情感检测后继续走知识检索 → 「今天有点累」答成「情绪影响身心健康…
可以看「政治（道德与法治）」」——情感域被知识域污染。F2 路由错误 120 题
主要是这类。

**正解**（用户 2026-08-26 指示）：「情感回应有情感回应的方式，闲聊有闲聊的
回应方式，合理表达情感就行」：
- 情感域（emotion）：纯共情前缀 + 情感表达，**不附知识卡导航/条件空间**
- 闲聊域（chitchat）：CHITCHAT 表补全（天气真热/真冷、早安等变体）
- verify_answer kind=emotion（LEGITIMATE_KINDS 已有）——情感回应不被误拒

### 教训 7：补知识也要走条件路由图（KAP 协议）

**问题**：手工补知识不可审计、易错——v1.40 补面积表述时误写进三角形 kp
（执行被覆盖成面积）；「变质」有地理（岩石）与食物两个 kp，按名称 LIKE
匹配错位。

**正解**（KAP v0.1）：
```
知识缺口 → ①条件分析（缺什么/学科域）→ ②路由（目标 kp/翻译键）
         → ③补知识（四要素注释，必带不适用条件）→ ④验证（命中/内容/
           负路由/回归四闸门）→ ⑤提交
```
**具体教训**：
- 补知识核对目标 kp 的 content 特征（「变质」按『不能吃』定位，不按名称）
- 不适用条件必写（食物变质不适用『岩石变质/蜂蜜防腐』，防跨题抢答）
- 验证闸门必过（补完跑 chat(问题) 确认 keys 命中再提交）
