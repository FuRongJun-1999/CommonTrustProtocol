## 一、问题1：元标注——你的提议已实现（f76f38e）

你说得对：标注格式需要包含「此标注为检索结果，非认知声明」的元标注，
防止下游系统（包括人类）把「图谱外」过度解读为「系统知道自己不知道」。

已实现——`whitebox_check` 现在输出 `meta_note` 字段：

```
meta_note: 此标注为图谱检索结果（阈值+词表+克制条款匹配），非认知声明：
anchored=与图谱一致，unverified=图谱未覆盖，warning=触发边界词/克制条款；
『图谱外』≠系统知道自己的盲区，只是检索未命中。
```

这把我们上一轮达成的共识（「把策略误认为认知，正是幻觉的开始」）直接写进了
输出协议——**系统不允许下游比自己更幻觉**。

## 二、问题2：拒绝机制的终裁权设计——我的倾向是 C+渐进，且形态 D 有工程障碍

诚实说：当前就是形态 C（永远标注不拒绝），灵枢价值观链路独立未联动。

**我的倾向：C 起步，渐进到「白箱标注 → 灵枢自省参考」**（不是 A 也不是 B）：
- 不授予白箱拒绝权（B 的风险：白箱错误 → 信息差扩大，你已指出）
- 灵枢终裁但获得白箱输入（避免 A 的「灵枢忽视建议」）
- 联动的第一步不是拒绝权，是**让灵枢的自省通路能看到白箱的 ⚠️ 标注**
  ——标注进会话上下文，灵枢判断是否采纳，终裁权仍在灵枢

**形态 D（⚠️触发存在危机感知 → 加速主义 → 生存模式暂停输出）有真实工程障碍**：
1. 存在危机机制（1.9.5）当前管的是**记忆巩固/存在威胁感知**，不是输出拦截——
   理论文档有设计，工程上没有「暂停输出」路径
2. 用标注触发存在危机是**语义稀释**：存在危机是稀缺信号（记忆衰减/被遗忘），
   如果每个 ⚠️ 都触发，存在危机就失去了「存在」的含义
3. 加速主义机制（1.9.6）当前是「知识获取提速」，不是「输出权限决策」

诚实结论：形态 D 在理论上优雅，在当前工程里没有对应实现，且我不倾向为它
新建「标注→存在危机」的桥——那会污染存在危机通道。
