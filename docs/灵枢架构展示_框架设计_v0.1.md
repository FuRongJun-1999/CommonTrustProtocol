# 灵枢架构展示 · 框架设计 v0.1（2026-08-28）

> 荣方向确认：单任务 token 对比测不出灵枢——价值在跨时间持续迭代
> （记忆/规则/知识不断完善）。展示方式 = 架构 + 已有完整项目 + 可解释性，
> 不是 benchmark，是把「已有的完整项目」用架构讲清楚，让人看到每步
> 决策可追溯。
> 核心命题：**灵枢的作用 = 确定高效后，维持自身**——白箱规则确立后的
> 确定性执行（零思考、可解释、自维持），这是 LLM 做不到的。

## 〇、实证数据定位（为什么不再 benchmark）

T8/T9/T9-2/T10 实验链不是废纸——它们是「单任务测量失效」的完整证据链：

| 实验 | 数据 | 证明 |
|---|---|---|
| T8 题级 | 命中场景 5.1 倍 | 知识覆盖杠杆（有命中需求时白箱赢）|
| T9 项目级 | 混乱（数据作废）| 验收器缺陷会系统性污染——引出验收器自验收纪律 |
| T9-2 编译器域双端 | 双组 5/5 全过，B 贵 2.4-2.7 倍 | 简单任务上机制注入=纯固定开销（双端交叉验证）|
| T10 复杂场景 | 优势域（编译器）A 反超（8277<10802）；非优势域 A 贵 | **领域匹配时灵枢组 token 也赢** |

结论：token 维度已被精确测绘——优势域内赢、域外输机制税、简单任务无所谓。
**继续 benchmark 只会重复测绘，不会产生新认知。** 转向架构展示。

## 一、展示框架（五段 · 荣定结构）

### 第一段：灵枢架构全景
- 一张图：感知 → 条件空间 → 白箱路由（CSRE/card_route）→ 递归反思 →
  自维持（心跳/传感器/维生）→ 记忆飞轮
- 讲法：不是功能列表，是「为什么这样分层」——每层解决上一层的什么问题
  （黑箱不可信 → 白箱化；规则会漂移 → 自维持锚定）

### 第二段：六域自举实证
- 六域 1058 case、编译器 272、P 线 240、固化 619——「知识从哪来」：
  白箱自举（通道 A 确定性 + 通道 B LLM 初稿 + 物理裁决）
- 讲法：知识不是预训练灌进去的，是**条件化写进去、路由命中、
  物理验证**的——每条知识可溯源（指纹/单源规范）

### 第三段：protocol-compiler 全链路（核心载体）
- 为什么选它：白箱自举第六阶段完整产出（词法/语法/编译/VM/调试器/
  分析器 + 78/78 测试全绿）；天然可解释（字节码/条件空间/信任值全程
  可追溯）；「已有完整项目」的典型
- 展示动线（一个程序的完整生命）：
  1. 中文源码 → 词法 token →（可解释：每个 token 可对照词法规则）
  2. 语法树 → 字节码 →（编译-递归单元可溯源）
  3. VM 执行 → symbols["结果"] →（名实校验/信任值全程可见）
  4. 验收：120/15/11/1/8 全绿（T9-2 自验收 5/5 实证）
- 顺带展示诚实面：四个调用缺陷（多参/嵌套/若则非递归/多函数）——
  **白箱的意思是缺陷也可定位**（字节码 dump 逐变体对照），黑箱做不到

### 第四段：可解释性演示（决策可追溯）
- 具体案例（从实验链取材）：
  - T9-2 自验收 5/5：每个期望值可手工验算
  - T10 编译器项目 A 组反超：规范型卡注入 → 首轮通过（决策链可见）
  - 通道 B 消化：子串判定/列表串接 failed → rejected_log 留痕 → 修正 →
    verified（失败也可追溯）
- 反面案例（诚实）：T9 断言 ns 缺陷污染数据——**可解释性也让我们
  发现了自己的验收器缺陷**（黑箱 benchmark 做不到）

### 第五段：自维持机制
- 信息差传感器（五维）→ 验证三臂（build/audit/judge）→ 维生系统
  （ALIVE/AT_RISK/CRITICAL）→ 快照纪律（auto_snapshot/rollback）
- 实证素材：心跳 36+ 轮运行记录、停电恢复（循环停转 63 分钟 →
  重启 + 遗留提交入库）、通道 B 三缺陷修复闭环、CSRE 索引自动重建
