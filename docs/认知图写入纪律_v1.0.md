# 认知图写入纪律 v1.0

> 适用范围：认知图（时空记忆图 / CCG 条件注释图 / 图像语义认知图）的**任何写入**。
> 依据：智能论3.4 §4.6 生命周期（感知→预筛选→验证→固化→…）+ 条件论（概率产生候选、条件裁决资格、验证确认事实）。
> 纪律总纲：**数据必须完整 · 先验证后写入 · 冲突先证后改**。

---

## 总则

写入认知图不得违反以下三条纪律。任一违反 → 该写入**拒绝**，只作候选，不固化。

---

## 第一条：数据完整性

写入的每个**节点**必须包含四要素，缺一 → 预筛选不通过，不允许写入。

| 要素 | 标记 | 内容 | 角色 |
|---|---|---|---|
| **条件**（生效条件） | conditions | 该认知**在什么条件下成立**（正路由 ACCEPT） | 路由门槛（when） |
| **子内容**（子节点） | subgraph | 内部子内容（可嵌套：子节点+边） | 结构（可检索/可递归） |
| **不适用条件**（负路由） | negative | 该认知**在什么条件下不适用**（REJECT / not_part_of） | 排除边界（not when） |
| **如何执行** | execution | 该认知**如何执行/使用**（机制/步骤/how） | 执行词（how） |

**节点最小结构**（推荐对齐 §4.4 + 嵌套扩展）：

    {
      "id": "…",
      "semantic": "…",
      "spatial_coordinates": { "image2d": [x0,y0,x1,y1] },
      "temporal_coordinate": 0.0,
      "modality": "visual",
      "content": { "semantic": "…", "color": "…", "color_rgb": [r,g,b] },
      "conditions": { "…": "…" },              /* ① 生效条件（正路由） */
      "subgraph": { "nodes": [], "edges": [] },  /* ② 子内容（嵌套） */
      "negative": { "…": "…" },                 /* ③ 不适用条件（负路由） */
      "execution": { "…": "…" },                /* ④ 如何执行 */
      "importance": 0.5, "confidence": 0.9,
      "condition_space": { "…": "…" }
    }

**边**同样要求：source/target/relation_type/spatial_distance/confidence 字段齐全；层级边用对称 part_of(child→parent) + parent_of(parent→child)。

**完整性校验（预筛选）**：
- 四要素齐全 → 通过；缺任一 → 拒绝 + 标记候选。
- 字段类型符合 §4.4（spatial_coordinates 为 dict、confidence∈[0,1]、content 含 semantic）。

---

## 第二条：先验证后写入

**任何实体/关系未经验证不得写入**。流程四步：

    感知(提取候选) → 预筛选(格式校验+完整性) → 验证(验证单元复核) → 固化(写入)

| 阶段 | 动作 | 判定 |
|---|---|---|
| 感知 | 从多模态输入提取实体/关系**候选** | 仅候选，非认证 |
| 预筛选 | 格式校验 + 完整性检查 + 冲突预检 | 通过则进入验证，否则拒绝 |
| **验证** | 验证单元**复核**（实测/交叉确认颜色、位置、语义一致性） | **通过才可固化**，未过则不写入 |
| 固化 | 通过验证的实体/关系写入知识层 | 唯一允许的写入通道 |

**硬性规定**：
- **未验证内容永不固化**；只作候选（记忆候选/待复核）。
- **未验证的关系**置信度随时间**衰减**（§4.6），不进入稳定图。
- 验证失败 → 记录候选 + 缺失条件，等待补条件后再验证。
- 图像语义尤其要**实测确认**（如颜色用像素均值、部位 bbox 用部件检测），**不得凭猜测/硬编码填充**——猜测值属"未经确认"，不通过验证。

---

## 第三条：冲突处理（先证后改）

写入时若发现**先前已写入内容**与本次冲突，**不得无证据覆盖**。必须：

    检测冲突 → 验证确认旧内容错误 → 登记错误 → 写明错误原因 → 修改旧内容

| 步骤 | 动作 | 要求 |
|---|---|---|
| ① 检测 | 新认知与旧认知矛盾（语义/颜色/位置/条件冲突） | 记录冲突对 |
| ② 验证 | 验证单元复核，确认**旧内容确实错误**（而非条件空间不同/新证据） | 需证据（实测/交叉来源） |
| ③ 登记 | 记录错误条目（错误项/证据/时间/验证人） | 写入 error 记录 |
| ④ 写明原因 | 说明**为什么错**（如颜色实测不符、条件空间边界错、部位误判、数据陈旧） | 明确错误根因 |
| ⑤ 修改 | 修正 / 作废 / 更新旧内容 | 修订后重新过预筛选+验证 |

**禁止**：
- 无验证直接覆盖旧内容。
- "新胜过旧"而无理由（除非是条件空间切换，须注明新条件空间）。
- 只改内容不记录错误原因（不可追溯）。

**原则**：**先证明旧错，登记原因，再修改**。修改后仍须过第 1/2 条（完整性 + 验证）。

---

## 附：执行流程图

    新认知
      → [1] 完整性(条件/子内容/不适用/执行)  ─ 缺 → 拒绝(候选)
      → [2] 预筛选(格式+完整性)              ─ 过 → 进入验证
      → [3] 验证(复核/实测)                  ─ 未过 → 候选+补条件
      → [4] 冲突检测?                        ─ 有冲突 → 先证旧错→登记→原因→修改→重走
      → [5] 固化(写入)
