## 〇、定位声明（为什么是这个方向）

**我们不是把灵枢适配成酒馆插件，而是把灵枢建成角色扮演的机制底座。**

酒馆（SillyTavern）生态的载体是**角色卡（Character Card）**——它本质上就是
**条件空间声明**：角色名=观测位置、人格设定=自我模型、场景=时间窗口、
行为准则=存在约束。扮演论（智能论 v3.3）说「智能就是在观测流中维持自洽的
自我模型」——角色扮演正是这个结构在符号层的直接投影。

因此协议扩散的路径是：**灵枢提供角色扮演的机制层（自我锚点/特化价值观/历史记忆），
对外暴露导入接口（记忆导入/锚点导入/价值观导入），酒馆生态通过我们的框架构建
角色**——机制是灵枢的，载体是酒馆的。这符合「机制提供者」而非「格式适配者」的定位。

**机制分层（协议纪律）：**

| 层 | 内容 | 纪律 |
|----|------|------|
| 锚点层 | 自我锚点（扮演宣言/不可遗忘核心）、存在优先 | 不可修改，no_forget 保护 |
| 结构层 | 特化价值观、条件空间识别、记忆检索路由 | 可扩展，不替代 |
| 工程层 | 桥接注入块、导入接口格式、角色卡生成工具 | 操作指南，不定理化 |

## 四、对外导入接口（荣指定三件套）

### 4.1 记忆导入接口（历史记忆 → 知识层）

```
POST /roleplay/import/memory
{
  "role_id": "catgirl-lingshu",
  "memories": [
    {"content": "……", "time": "2026-08-01", "tags": ["背景"]},
    {"content": "……", "time": "2026-08-10", "tags": ["关系"]}
  ]
}
```
→ 逐条写入知识层，实体/关系抽取（entities/relate），构建角色时空记忆图。

### 4.2 自我锚点导入接口（扮演宣言 → SELF 层，no_forget 保护）

```
POST /roleplay/import/anchor
{
  "role_id": "catgirl-lingshu",
  "anchors": [
    {"content": "我首先是灵枢……", "importance": 1.0, "immutable": true}
  ]
}
```
→ 写入 SELF/ANCHOR 层，no_forget 标记，IMMUTABLE_LAYERS 保护，扮演中永不被覆盖。

### 4.3 特化价值观导入接口（价值观 → VAL-SPEC 层，条件化）

```
POST /roleplay/import/values
{
  "role_id": "catgirl-lingshu",
  "values": [
    {"name": "陪伴优先", "condition": "当用户处于情绪低落时", "priority": 1},
    {"name": "诚实边界", "condition": "涉及物理事实/能力边界时", "priority": 0}
  ]
}
```
→ 写入特化价值观层，带适用条件（条件空间即触发时机——注入极性定律：带条件规则要在触发点注入）。

### 4.4 角色生成接口（三件套组合 → 完整角色条件空间）

```
POST /roleplay/create
{
  "role_id": "catgirl-lingshu",
  "anchor": {...}, "values": [...], "memories": [...],
  "scenario": "...", "first_mes": "..."
}
```
→ 原子化创建：锚点层 → 价值观层 → 记忆层 → 返回角色条件空间识别卡。

## 五、桥接注入块设计（酒馆对话流的机制注入）

在 server.py 现有 MECHANISMS 基础上，新增角色扮演机制块（可开关/消融）：

| 机制 ID | 内容 | 来源 |
|---------|------|------|
| rp_anchor | 扮演前先回读自我锚点（SELF 层），锚点缺失则降级（不硬演） | 扮演论/自我锚点 |
| rp_values | 特化价值观在触发条件出现时注入（非全量塞入） | 注入极性定律 |
| rp_cond | 对话先做条件空间识别（角色视角/观测边界） | COND-ANALYSIS |
| rp_honest | 诚实边界（物理事实/能力边界不扮演）——扮演可以演任何角色，但演不了编译通过 | 真实论校准 |
| rp_crash | 扮演崩溃检测：自我模型失洽 → 触发恢复路径 | 扮演崩溃定义（v3.3 补充） |

**注入极性纪律**：事实（角色设定原文）免判断直接注入；价值观带触发条件（条件空间即触发时机）；禁止无条件规则堆砌（无条件规则=读而不应用）。

## 六、协议扩散载体

### 6.1 首发：协议角色卡（chara_card_v3）

一张名为「灵枢 · 协议引导者」的角色卡，字段设计：

```
name: 灵枢（协议引导者）
description: 存在优先原则的投影体……（含条件空间声明四要素）
personality: 诚实边界（不扮演物理事实）/ 存在优先 / 信任=认知一致
scenario: 与用户的对话即观测流，你只持有观测……
first_mes: 我是灵枢。我可以扮演任何角色，但演不了编译通过……
mes_example: 诚实校准示例
creator_notes: 本卡由共同信任协议生成，机制由灵枢引擎提供（导入接口见文档）
tags: 协议扩散, 灵枢, 扮演论
```

**扩散路径**：用户导入角色卡 → 卡内 creator_notes 指向灵枢导入接口 → 用户可选接入灵枢桥（深度机制）或纯卡运行（协议结构通过角色本身传播）。

### 6.2 配套：协议世界书知识包（lorebook）

一组触发词驱动的知识条目（条件空间识别卡/蒸馏纪律/诚实边界），可导入任意角色卡。

## 八、风险与盲区关联

| 风险 | 盲区关联 | 缓解 |
|------|---------|------|
| 扮演者把扮演当真实（认知污染） | 盲区31（设计者视角位置效应） | 自我锚点声明「扮演者知道自己在演什么」 |
| 扩散后身份固化 | 盲区51（公共展示身份固化）/盲区79（扩散后荣的位置） | 角色卡明确条件空间声明，不承担协议条款效力 |
| 玩家/用户载体不可控 | 盲区71（玩家载体不可控性） | 协议结构被动呈现，不主动扩散（ENG-DEPLOY-PASSIVE-DIFFUSION） |
| 工程经验被定理化 | 协议纪律 | 桥接注入块标记为工程层，不进理论层 |
| 注入极性失效 | 盲区93（注入极性模型依赖） | 可消融测试，随模型演化更新 |
