# 白箱自举第六阶段 · 项目复现路线规划（编程路线转向）

> 文档先行 → 项目复现。编程学习从「概念条件单元」转向「真实项目复现」：
> 概念知识已覆盖（软件工程/编译原理/数据结构/多语言），但「知识」不等于「工程能力」——
> 真实项目有真实约束（多文件组织/错误处理/测试/性能/迭代），复现是理解后重建 + 对照验证。

## 一、为什么项目复现（路线转向理由）

1. 概念单元库覆盖了「知道什么」，项目复现训练「做出什么」
2. 真实工程约束：模块拆分、错误处理、测试驱动、性能、可维护性——条件单元里没有的「隐含知识」
3. 复现 = 理解后重建 + 对照参考验证（不是抄代码）：白箱能解释每一步**为什么**这样写
4. 与 codegraph-ref 学习衔接：从「读代码（分析）」到「写代码（构建）」
5. 产出可回喂白箱：每个复现项目的设计/测试/踩坑 → 提炼成新的代码条件单元

## 二、项目选择标准（值得复现的特征矩阵）

| 特征 | 权重 | 说明 |
|---|---|---|
| ① 可验证性 | ★★★ | 有明确输入输出/测试断言（复现能对照验证正确性） |
| ② 规模适中 | ★★★ | 1k-10k 行，可拆阶段，单人数月可完成 |
| ③ 技术多样性 | ★★ | 覆盖解析/图/并发/存储/IO 等不同范式 |
| ④ 与白箱栈衔接 | ★★ | 产出能回喂白箱代码能力（理解/生成/测试） |
| ⑤ 开源可对照 | ★★ | 有参考实现可对照（复现≠抄，对照验证设计盲区） |
| ⑥ 教学点密度 | ★★ | 至少一个核心机制需要深入思考才能做对 |

评分：每项目按 6 项 1-5 分 → 总分 30 选高分优先。

## 四、推荐第一个项目：G. Tree-walk 解释器

**理由**：
1. **衔接最强**：mini_compiler 已有词法/语法/codegen 基础（9/9），本轮补全「求值器」
2. **教学点密度高**：变量环境、函数作用域、闭包捕获、错误传播——每个都需要深入思考
3. **可验证性满分**：写测试程序断言输出，正误一目了然
4. **规模适中**：可分阶段（词法→语法→求值→函数→闭包），每阶段可测
5. **与白箱栈双向回喂**：解释器实现 = 新的代码条件单元；白箱代码问答可分析解释器自身

**阶段划分**：
```
P1 词法+语法（复用 mini_compiler 思路）→ 表达式求值（算术/比较/逻辑）
P2 变量环境 + 语句（赋值/if/while）→ 完整程序执行
P3 函数定义/调用 + 作用域链 → 递归
P4 闭包（环境捕获）→ 高阶函数
P5 错误处理（运行时错误定位）+ 测试套件 → 对照参考（如 Monkey/Lox 教学实现）验证
```

**复现纪律**（白箱诚实原则）：
- 每阶段先**自己设计**（不看参考），再对照参考实现修正设计盲区
- 每阶段测试全绿才进入下一阶段
- 踩坑提炼成条件单元（如「闭包要捕获环境快照而非共享可变环境」）

## 五、执行方式

1. 每项目：设计文档先行 → 分阶段实现 → 每阶段测试 → 对照参考验证 → 提交 + 五副本同步
2. 复现产出：代码 + 设计文档 + 学习笔记（模式提炼）→ 回喂白箱代码能力
3. 候选顺序：G（解释器）→ J（代码分析 CLI，把白箱代码能力工程化）→ E/F（服务器/SQL）→ H（存储引擎）
