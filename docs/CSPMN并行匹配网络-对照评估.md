> **【版本标注 · 2026-08-29】** 本文档为 2026-08-20 历史评估（搜索=矩阵运算）。
> 核心思想已并入智能论 v3.4 第七章 7.1-7.2（CSPMN + 术语边界声明）。检索时以 v3.4 为准。

> 来源：荣提出的「并行条件空间匹配网络」——把条件空间导航转成矩阵运算，
> GPU 上跑上亿「条件空间→规则」匹配单元；不需要 Transformer/反向传播/梯度下降。
> 本文档对照灵枢现有 neural_index 实现，诚实定位真增量。

---

## 0. 核心判断

**荣的构想方向正确，且灵枢已有雏形——`search_index` 就是「矩阵乘法」：
查询向量 × 全库向量矩阵 = 点积 = 余弦。** 真正的增量不在「并行匹配」本身，
而在三个具体升级：① 条件空间子矩阵（domain 分块）；② GPU 后端（numpy→cupy/torch）；
③ 盲区注入闭环（匹配表持续修正）。

---

## 1. 现状：灵枢已有的「并行匹配」雏形

`neural_retrieve.py` `search_index()`（line 96-124）：

```
qv = embed(query)                    # 查询编码一次（bge-small-zh）
sims = vectors_normed @ qn           # ← 这就是矩阵乘法！(N,) = (N,512) × (512,)
order = argsort(-sims)               # 全库并行比较
```

**已经在做的事**：
- 3030 向量 × 512 维，numpy 矩阵乘，单查询 5-8ms（记忆记录）
- 全库并行匹配（向量化，非循环）——上万核心同时比较的 CPU 版
- 盲区→新卡→索引增量重建（build_neural_index 幂等，content_hash 复用）

**所以「上亿并行单元 = 矩阵行」这个映射，架构上灵枢已经站在门口**——
现有 3030 行，到上亿行是**规模问题**（加数据），不是**架构问题**（换引擎）。

## 2. 真增量定位（对照 CSPMN 三层）

| CSPMN 层 | 灵枢现状 | 真增量？ |
|---|---|---|
| P1 并行匹配层 | search_index 全库矩阵乘 ✓ | **半有**——缺「条件空间子矩阵」（domain 分块）|
| P2 信息聚合 | 融合分排序（semantic_translate）✓ | 已有 |
| P3 最佳规则/盲区 | chat_engine 诚实边界 ✓ | 已有 |
| GPU 后端 | numpy CPU | **真增量**（cupy/torch，需硬件）|
| 盲区注入更新匹配表 | build_neural_index 增量重建 ✓ | 已有——但未接「盲区自动触发重建」|
| 条件空间→规则映射 | 向量=知识卡内容嵌入 | **半有**——现有向量是「内容语义」，非「条件空间入口声明」|

**精确定位**：CSPMN 的真增量 = ① **domain 分块矩阵**（按条件空间切片，查询只乘
相关子矩阵——这是 CSPRE 定向检索的 GPU 版）② **条件空间入口向量**（每个子实例
的向量 = 「该条件空间的入口条件声明」，而非整卡内容）③ **GPU 后端**。

---

## 3. 渐进路径（不推翻现有，三层递进）

### Step 0（现状）：全库矩阵乘
```
查询 → bge 编码 → 3030×512 @ 512 → top-N
```

### Step 1：domain 分块矩阵（对应 CSPRE 第一步 + CSPMN P1）
```
查询 → 学科级条件空间识别（classify_condition_space，DOMAIN_ROUTE）
     → 只乘目标 domain 子矩阵（如 物理学: 300×512）
预期：乘向量 3030 → 数百；语义更准（跨学科噪声消除）
```

### Step 2：条件空间入口向量（CSPMN 核心升级）
```
每个子实例向量 = 该条件空间的「入口条件」嵌入（关键词/类型/排除条件）
而非整卡内容嵌入——「条件空间→规则」的真正映射
实现：build_neural_index 增加 entry_vector 通道（可选，与内容向量并行）
```

### Step 3：GPU + 盲区注入闭环
```
cupy/torch 后端（如有 GPU）→ 上亿行可行
盲区（未分类/低匹配）→ 自动生成新卡 → 增量重建索引 → 匹配表自我修正
```

---

## 4. 诚实边界（不做的/需注意的）

| 项 | 说明 |
|---|---|
| 「不需要训练」精确性 | 检索确实不需梯度下降，但 bge 模型本身是预训练的——「零训练」指检索层，模型加载是既成事实 |
| 上亿规模的前提 | 上亿子实例需要上亿条知识/规则——当前 34199 节点，量级差 4 个数量级；架构先就位，数据随知识飞轮涨 |
| GPU 硬件 | 需确认运行环境是否有 GPU；无 GPU 时 numpy 矩阵乘已是「并行」的（BLAS 多线程）|
| 与蜂群关系 | CSPMN 是**单实例内**的检索结构；蜂群是**实例间**通信——不同层，不混淆 |

---

## 5. 结论

- **CSPMN 方向正确，且灵枢已在门口**（search_index = 矩阵乘已实现）
- **真增量三个**：domain 分块、条件空间入口向量、GPU 后端
- **建议路径**：Step 1（domain 分块）与 CSPRE 第一步合并做——同一个
  `classify_condition_space` + `domain_filter`，先验证准确率/耗时，
  再上 Step 2 入口向量，最后 GPU
- 盲区注入闭环：把现有「盲区→建卡→重建索引」的散落步骤串成自动回路

> 纪律：先 Step 1（可立即做，复用 DOMAIN_ROUTE），有数据再谈 Step 2/3。
> 不预先堆 GPU 架构——先证明「条件空间分块匹配」比全库匹配准/快。
