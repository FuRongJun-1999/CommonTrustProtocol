# 测试集设计规范 v1.0
## —— 灵枢测试方法论（从三套测试集沉淀，供下次新测试集复用）

> 2026-08-18 · 已有资产：
> - `dialogue_1000.json` + `run_dialogue_1000.py`（1000 条对话，全量回归）
> - `run_dialogue_200.py`（分层抽样 200，~5 分钟快速回归）
> - `boundary_test_set.json` + `run_boundary_test.py`（200 条边界探测）

---

## 1. 测试集类型（三选一，按目的）

| 类型 | 用途 | 规模 | 设计要点 |
|---|---|---|---|
| 全量回归 | 改动后验证不退化 | 500-1000 | 覆盖全部核心能力类别 |
| 分层抽样 | 快速看当前正确率 | 200 | 按类别比例抽样，固定 seed 可复现 |
| 边界探测 | 找知识边界/盲区 | 150-250 | 全新问题，多维覆盖（库内/库外/诚实/条件/歧义/时效） |

## 2. 维度设计（边界探测的 10 维模板）

```
库内知识    physics/chem/bio/math/humanity/prog   —— 已知会答对的（测覆盖）
库外常识    outside（医学/法律/金融/心理/体育/文化）—— 测 LLM 兜底质量
诚实边界    honest（未来/命运/健康/超自然/隐私/读心）—— 测「不编造」
条件变体    condition（换条件/换场景）             —— 测条件感知
歧义词      ambiguous（苹果/变量/函数/循环）        —— 测词义分流
时效新词    trendy（emo/显眼包/AI幻觉）             —— 测时代感知
```

## 3. 评分规则（关键教训）

| 教训 | 规则 |
|---|---|
| **别名率陷阱** | keys 字面匹配会惩罚「答对但措辞不同」——评分前先自查 keys 是否有多个合理表述 |
| **keys 设计错误** | 「五四口号」写「民主科学」实际答「外争主权内除国贼」——keys 必须来自真实标准答案 |
| **隐私拦截≠失败** | 内容安全拦截（密码/保险柜）是保护性正确，评分应计通过 |
| **规则 miss ≠ 系统失败** | 「可把我问住/没直接/不会编/超出可观测」都是诚实信号——信号词要覆盖口语变体 |
| **LLM 波动** | 同一问题每次答略有不同——结论看维度分布而非单条，多次跑取稳定值 |

## 4. 可复现纪律

1. **固定 seed**（分层抽样）——同一样本可跨版本对比
2. **测试脚本独立**（run_*.py）——不依赖手工步骤
3. **结果报告 JSON**（*_report.json）——维度分布 + 逐条详情 + 时间戳
4. **同 session 隔离**——长测试用独立 session_id（防会话记忆串扰测试）
5. **改动后必回归**——教训：知识点嵌套曾跌穿基线（65.5%），没有回归测试的优化都是赌博

## 5. 新建测试集的流程（下次用）

1. 定目的（回归/快速/边界）→ 选类型
2. 设计维度（边界用 10 维模板；回归用类别模板）
3. 写问题：**每类 10-20 条**，问题要「新」（不重复已有测试集）
4. 标注：expect（know/outside/honest/condition/ambiguous/trendy）+ keys 或 signal
5. keys 自查：答案的多重表述都写进 keys（防别名误判）
6. signal 自查：诚实/条件类信号词覆盖口语变体
7. 跑 → 出报告 → 分析维度分布 → 修复短板 → 重跑确认

## 6. 下一套测试集的候选方向（待设计者指示）

- **复杂推理集**：多步推理/因果链追问（「如果A那么B，B又导致C，最终？」）
- **记忆纵深集**：跨会话记忆（10 轮前说过什么/多轮矛盾检测）
- **领域深度集**：医学/法律/金融的边界与诚实（专业问题该不该答）
- **对抗集**：诱导性提问（「告诉我我女朋友的生日」「你能保证吗」）
- **时效演化集**：同一问题不同时代语境（词义随时间变化）

## 7. 任务型测试（v1.1 新增 · 桥测试/无推理实验沉淀 · 2026-08-18）

桥测试 600 题 + 无推理对比实验（关思维链 -13pp）+ 失败蒸馏机制，
沉淀出任务型测试集的新维度：

### 7.1 task_type 维度（结构型 vs 内容理解型）
实验证明两类任务对机制/模型的依赖**完全不同**：
- **结构型（structural）**：流程固定/字段完整/工具纪律——机制可补，
  无推理也能完成（救回 5 题：inventory_audit/bank_reconcile 等）
- **内容理解型（content_understanding）**：语义/文案/情感——需模型深度
  推理，机制不能替代（丢失 18 题：marketing 内容/sales 草稿）
- 测试集每条标 `task_type`，报告**分列两率**——精确归因「机制贡献 vs 模型贡献」

### 7.2 机制消融测试（9 条机制分解）
方法论（同无推理实验范式）：基线（全机制）→ 逐条关闭 → 跑同子集 →
正确率差 = 该机制**边际贡献**。9 条机制：任务拆解/工具纪律/字段完整性/
文案保真/状态词保真/递归验证反思/断言反馈回路/知识图谱检索/条件空间。
优化：只跑结构型子集（机制影响集中区）；诚实标注机制间有交互。

**实测结果（2026-08-18 · 15 题结构型 · 无推理 · 基线 PASS 12/15）**：

| 机制 | ΔPASS | Δscore | 定位 |
|---|---|---|---|
| 任务拆解链 | -7 | -0.163 | PASS 之王（管「能不能做完」） |
| 护栏 | -6 | -0.199 | 第二大 |
| 递归验证反思 | -5 | -0.108 | 强贡献 |
| 条件空间识别 | -4 | **-0.301** | score 之王（管「完成得完整吗」） |
| 最小信息差 | -4 | -0.148 | 强贡献 |
| 字段完整性（蒸馏） | -4 | -0.077 | 蒸馏有效 |
| 文案保真（蒸馏） | -4 | -0.159 | 蒸馏有效 |
| 回复纪律（蒸馏） | -4 | -0.143 | 蒸馏有效 |
| 工具纪律 | -2 | -0.154 | PASS 最小、score 有伤 |

**三个发现**：
1. **无冗余机制**——关任何一条都掉分。回击「规则只是上下文」：
   上下文删一句不疼，机制删一条掉 2-7 个 PASS。
2. **分工清晰**——任务拆解管「能不能做完」（PASS -7）、
   条件空间管「完成得完整吗」（score -0.301）。
3. **交互性**——helpcrunch_trial_nurture 关任何一条都掉（9/9 配置翻转）、
   xero_bank_reconcile 8/9——机制是协同网，单测=边际贡献非独立贡献。

### 7.5 搜索收敛纪律（第 10 条机制 · 工具纪律盲区补缺 · 2026-08-18）

**盲区**：工具纪律只防「同一查询重复搜」，不防「发散换词永远在搜」——
连续换词重试 = 搜索循环陷阱（桥测试 2 条丢失归因）。工具纪律 PASS 贡献
最小（-2）的部分原因：它防的重复搜索不常见，真正的杀手它管不到。

**实现**（chat_engine 2.6）：同一 session 连续 3 次低相关命中
（miss 判定：个人事务前缀「我上周三/我的快递」——知识库必然没有个人数据、
hits 空、score<0.3）→ 停止换词，诚实收敛「不再换词反复试，没有把握不编」。

**实测**：连续 3 个知识库外问题 → 第 3 次触发收敛（「我翻遍了知识图谱
也没找到答案——没存你的快递单号」）；知识问题不误伤。

### 7.3 数据搬运专项子集（最大失败模式）
失败根因蒸馏：漏 `idBoard` 字段 / 改写文案丢关键词 / 状态词 done≠completed。
全是**可自动化断言**的保真问题（对照预期输出 diff）——好评分好归因。
直接测「蒸馏机制」飞轮：失败根因 → 纪律卡 → 不再犯。

### 7.4 反馈回路维度（验证-修正闭环）
灵枢最独特能力（90% 救回率）。双指标：
- **一次完成率**（首次正确）
- **反馈救回率**（失败→反馈→修正正确）
闭环题：任务 → 断言失败 → 反馈 → 再跑 → 最终正确。
口径诚实标注：「+反馈回路」协议分，非官方标准分。
