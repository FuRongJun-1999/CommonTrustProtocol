# T12-M1 · 两节点最小互联详细设计 v0.1（2026-08-29 心跳）

> 依 docs/T12_蜂群互联蓝图_v0.1.md §四 M1 与条件卡纪律（「M1 具体协议
> 字段/接口在实现前另立详细设计」）。本文 = M1 实现的条件卡。

## 一、M1 目标拆解（对应蓝图 G2/G3）

**最小闭环**：节点 A（灵枢·ZCode 侧）向节点 B（dsh 网页端侧）发起一次
跨节点能力协商（G2），并对其产出发起一次互验证裁决（G3）。
G1 组网（消息可达+中继）由蜂群 6 单元承载，M1 只做协议层。

## 二、消息协议字段（教学模拟口径，JSON 行）

```json
{"type": "<msg_type>", "from": "<node_id>", "to": "<node_id>",
 "id": "<msg_id>", "reply_to": "<msg_id|可选>", "ts": <epoch>,
 "payload": {...}}
```

| msg_type | 方向 | payload | 对应命题 |
|---|---|---|---|
| HELLO | 双向 | {capabilities: [..]} | G1 组网发现 |
| CAP_QUERY | A→B | {capability: str} | G2 资格判断入口 |
| CAP_REPLY | B→A | {verdict: ACCEPT/REJECT/DEFER/BLINDSPOT, reason: str} | **四态路由跨节点** |
| TASK | A→B | {capability, input} | 分工（仅 ACCEPT 后合法） |
| RESULT | B→A | {output, basis: 验证基底说明} | 产出带基底 |
| VERDICT | A→B | {pass: bool, evidence: str} | **G3 互验证**（A 用自己的基底裁决 B 的产出） |
| ADOPTED | 双向 | {verdict_id, side} | 结果固化登记 |

**白箱纪律约束**：
- TASK 仅在 CAP_REPLY=ACCEPT 后允许发送（资格先于执行）
- VERDICT 由**接收方**用己方验证基底裁决（自验证不采信）
- BLINDSPOT 回复必须被 A 记录为 B 的能力边界（不猜测重试同能力）

## 三、传输载体（分批）

- **第一批（本轮实现范围）**：本地目录总线 `data/swarm_bus/`
  ——每节点一个收件箱目录，消息为 JSON 行文件；发送=写入对方收件箱。
  教学模拟口径，与蓝牙域「模拟射频层」限制显式一致；中继/多跳由蜂群
  单元语义复用（M2 再扩展）。
- 第二批（创造层边界）：真实 socket/蓝牙射频映射——挂账。

## 四、实现载体与批次

- `tools/swarm_m1.py`：Node 类（收件箱轮询/消息分派/能力注册表/裁决记录）
  + Bus（目录总线）+ 演示 main（双线程模拟 A/B 对话）
- 批次 1：协议消息构造/校验 + Bus 收发 + HELLO/CAP_QUERY/CAP_REPLY
- 批次 2：TASK/RESULT/VERDICT/ADOPTED + 裁决记录 + 端到端演示
- 每批配套验证用例（见 §五）+ 提交

## 五、验收清单（V-M1 系列，实现时逐条勾）

- V-M1.1 消息字段校验：缺字段/非法 type 显式报错
- V-M1.2 HELLO 收敛：双方交换 capabilities 后可查询对方能力表
- V-M1.3 四态协商：B 对已注册能力回 ACCEPT、未注册能力回 BLINDSPOT
  （不猜测），A 对 BLINDSPOT 记录边界
- V-M1.4 资格先于执行：未协商直接 TASK → 协议层拒绝
- V-M1.5 互验证：B RESULT 带 basis，A 用己方基底裁决出 VERDICT，
  pass=true 后双方各有 ADOPTED 记录
- V-M1.6 端到端：双 Node 经目录总线完成一次完整闭环（消息序列可追溯）

## 六、诚实边界

- M1 的「节点」是**协议角色**——ZCode 侧由心跳会话扮演 A，dsh 侧真实
  接入（MCP/HTTP）属 M1 之后的联调批次；本文实现阶段两节点均为
  swarm_m1.py 进程（先协议正确性，后真实接入）
- 教学模拟总线 ≠ 真网络：真传输走第二批，不宣称「真互联」
