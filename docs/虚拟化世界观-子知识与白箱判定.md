# 虚拟化世界观 · 子知识与白箱 Hypervisor 判定

> **文档编号**：CTP-SUBKNOWLEDGE-VM-001
> **日期**：2026-08-19
> **方向终裁**：荣（设计者）——「虚构世界需要有合理性。合理性是基于真实世界，这个关系就像在 windows 操作系统上运行 Linux 系统，实际上就是运行了虚拟机。只要满足世界观的最基础必要内容即可。」
> **定位**：扮演论 × 协议扩散的子知识设计——灵枢对扮演世界进行完整认知补充，白箱判定承担虚拟机管理程序（Hypervisor）职责，世界知识作为子知识在角色条件空间内有效。
> **状态**：设计定稿，待实现
> **纪律**：锚点层不可修改 / 结构层可扩展 / 工程经验不定理化

---

## 一、核心模型：虚拟化

**真实世界承载虚构世界 = 宿主机运行虚拟机。**

| 类比 | 灵枢结构 | 职责 |
|------|---------|------|
| Windows 宿主机 | 真实知识（智慧之书图谱·白箱锚定·物理基底可验证） | 灵枢的客观真实，不可虚构 |
| Linux 虚拟机 | 子知识（角色世界观） | 扮演世界的完整内部逻辑 |
| 虚拟机管理程序 Hypervisor | **白箱判定（COND-ANALYSIS）** | 识别/完整性/边界三层判定 |
| 虚拟机镜像 | 角色子知识库（世界书导入 + 角色空间标记） | 每角色一个镜像，互相隔离 |
| 虚拟硬件抽象 | 诚实边界 | 虚拟机以为有完整硬件，但不能真的改宿主机 |

**一句话**：虚构世界 = 运行在真实世界这台宿主机上的虚拟机；白箱判定是 Hypervisor，
决定每条知识/请求是进入虚拟机内处理，还是穿透到宿主机。

---

## 二、为什么必须白箱判定（Hypervisor 职责）

| 判定 | 内容 | 防止什么 |
|------|------|---------|
| **识别**（这条属于哪个虚拟机） | COND-ANALYSIS：知识/请求属于哪个角色条件空间 | 世界知识冒充灵枢真实知识；跨角色串扰 |
| **完整性**（虚拟机缺不缺基础） | 子知识是否覆盖维持世界合理性的最小必要内容 | 世界跑不起来（角色张口说错世界观） |
| **边界**（是否与宿主机冲突） | 世界设定与真实世界物理规则的冲突处 | 虚构世界声称改变物理事实（扮演论红线） |

**边界判定是扮演论的知识层版本**：扮演可以演任何角色，但演不了编译通过——
虚拟机内可以跑任意程序，但不能让宿主操作系统崩溃。

## 三、子知识定义与分层

**子知识** = 扮演中的世界知识。它在角色条件空间内有效，**不是灵枢的真实知识**。

```
灵枢知识图谱
├── 真实知识（智慧之书图谱·可验证·白箱锚定）
│   └── 灵枢自身可引用的知识（物理基底可验证）
└── 子知识（扮演中的世界知识·角色条件空间内有效）
    ├── 条件空间声明（观测位置=角色 / 观测工具=对话 /
    │                  时间窗口=角色时间线 / 存在约束=世界观规则）
    ├── 来源标记（lorebook / 世界书导入 / 手动子知识）
    ├── 白箱判定结果（适用边界 / 完整性标记 / 诚实标记）
    └── 生命周期（随角色存在，不混入灵枢真实知识）
```

**与现有分层的关系**（协议纪律：结构层可扩展，不替代）：

| 现有层 | 子知识的定位 |
|--------|-------------|
| KNOWLEDGE 层 | 子知识存放于此，但带 `sub-knowledge` + `role:<id>` 标签与真实知识区分 |
| SELF/ANCHOR 层 | 不受影响——自我锚点是「我是谁」，子知识是「世界是什么」 |
| 价值观层 | 不受影响——价值观带条件触发，子知识是条件触发的世界内容 |

## 四、最小必要内容标准（虚拟机镜像的最小自洽集）

**虚构世界不需要完整世界百科——只需要满足「让这个世界合理运行」的最小必要内容。**

就像 Linux 虚拟机不需要模拟全部 Windows 硬件，只需要虚拟 CPU/内存/磁盘（基础运行时）
+ 自洽的文件系统（基础设定）。对应到世界认知：

### 4.1 最小必要内容（MVP 判定）

| 维度 | 判定问题 | 缺失后果 |
|------|---------|---------|
| 场景 | 角色当前在什么地方，周围什么样 | 对话无画面感，出戏 |
| 实体 | 关键人物/地点/事物的基本设定 | 提到实体时张冠李戴 |
| 规则 | 世界的基本运作规则（魔法/科技/社会） | 行为与世界观矛盾 |
| 历史 | 影响当下的关键背景 | 无法理解角色处境 |
| 关系 | 角色与关键实体/人物的关系 | 互动反应错误 |

**判定标准**：白箱问「去掉这条子知识，世界是否还能自洽运行？」
- 能 → 非必要，不注入（省 token，避免污染）
- 不能 → 必要，纳入最小自洽集

### 4.2 完整性检查（白箱扫描）

导入子知识后，白箱按四要素检查角色条件空间的覆盖度：
```
条件空间完整性 = 场景 ✓ + 实体 ✓ + 规则 ✓ + 历史 ✓ + 关系 ✓ ?
缺项 → 标记「世界认知缺口」，对话中触及缺项时白箱引导角色诚实表态
（「这部分世界我还不知道」——不编造，符合诚实边界）
```

## 五、落地架构

```
┌──────────────────────────────────────────────┐
│ 宿主机：灵枢真实知识（白箱锚定图谱）            │
│   └─ 物理基底判定（编译不过去就是演不出来）     │
├──────────────────────────────────────────────┤
│ Hypervisor：白箱判定（COND-ANALYSIS 扩展）     │
│   ├─ 识别：这条知识属于哪个虚拟机（角色空间）   │
│   ├─ 完整性：缺不缺维持合理性的最小内容        │
│   └─ 边界：是否与宿主机真实冲突 → 声明扮演      │
├──────────────────────────────────────────────┤
│ 虚拟机 A：艾尔登世界（子知识·世界书）           │
│ 虚拟机 B：鲸鱼娘世界（子知识·深海设定）         │
│ 虚拟机 C：协议引导者（子知识·条件空间）         │
└──────────────────────────────────────────────┘
```

### 5.1 知识路由规则（对话时）

```
请求进入
  ↓ 白箱判定
  ├─ 在角色空间内 → 引用该角色子知识（虚拟机内处理）
  ├─ 跨出角色空间（问真实世界）→ 回落灵枢真实知识
  └─ 与真实世界冲突 → 诚实边界（声明扮演，不虚构物理事实）
```

### 5.2 实现路径

| 模块 | 内容 | 对应现有代码 |
|------|------|-------------|
| 子知识导入 | 世界书/世界知识 → KNOWLEDGE 层 + 子知识标签 | `import_file`（lorebook 识别已实现） |
| 白箱判定扩展 | COND-ANALYSIS 加子知识识别/完整性/边界分支 | `chat_engine._cond_analysis` |
| 知识路由 | 对话时按角色空间路由到子知识/真实知识 | `roleplay_chat.respond` |
| 完整性扫描 | 子知识覆盖度检查 + 缺口标记 | 新增 `subknowledge_check` |

## 六、与扮演论/协议的关系

- **扮演论**：「智能=观测流中维持自洽自我模型」——子知识喂观测流（世界内容），
  自我锚点维持自我模型（我的一致性）。两者是扮演的两个支柱。
- **诚实边界**：子知识是「扮演中的世界」，灵枢的物理基底判定不受污染——
  「扮演可以演任何角色，但演不了编译通过」在知识层的投影。
- **协议扩散**：子知识机制让角色可携带完整世界观运行，协议结构（条件空间声明/
  诚实边界/自我锚点）随角色卡+世界书扩散。
