# 白箱 vs LLM 测试报告（灵枢上下文与 token 分析）

> 测试日期：2026-08-22 · 测试集：知识 20 题 + 开放 10 题 + 多轮上下文场景
> 环境：白箱 538+ 簇 / DeepSeek 云端 / 本地 Ollama 32k

## 一、分工判定（什么内容白箱 / 什么必须 LLM）

| 内容 | 处理方 | 判定依据（测试实测） |
|---|---|---|
| 知识问答（碳中和/光合作用/函数/概率图模型/功能格…） | **白箱 100%**（零 LLM） | fp 直答/检索命中 |
| 白箱闲聊/自省/诚实边界 | **白箱** | chitchat/self_reflexive/honest 路由 |
| 开放生成（写诗/故事/规划/建议…） | **LLM 50%**（其余白箱兜底：情感/闲聊/诚实） | 白箱无把握 → 转 LLM |
| 角色扮演（一致性对话） | **LLM**（本地 Ollama 优先） | 角色场景 |
| 复杂推理/未覆盖领域 | **LLM** | 诚实边界后仍需回答 |

## 二、路由分布实测（测试①）

| 类别 | 题数 | whitebox | llm | 白箱率 |
|---|---|---|---|---|
| 知识 | 20 | 20 | 0 | **100%** |
| 开放 | 10 | 5 | 5 | 50% |
| **合计** | 30 | 25 | 5 | **83.3%** |

## 三、token 节约（测试②③）

| 度量 | 数值 |
|---|---|
| 全 LLM 估算（30 题 × 800 tokens） | 24000 tokens |
| 实际消耗（白箱 0 + LLM 5 题） | 4000 tokens |
| **总节约** | **83.3%** |
| 上下文裁剪：记忆部分（信噪比前后） | 748 → 100 tokens（**节约 86.6%**） |
| 上下文裁剪：完整 LLM 请求（含固定 system） | 1048 → 400 tokens（**节约 61.8%**） |

## 四、任务能力对比

**提升**：
- 知识问答：零 LLM token、毫秒级响应、确定性（物理基底裁决不漂移）
- 对话成本：83% 请求零 LLM 消耗
- 记忆信噪比：低相关记忆不注入（LLM 聚焦当前问题，防噪声干扰回答）
- 可用性：白箱离线可用（API 断不崩）

**下降**：
- 开放创作/复杂推理：依赖上游模型质量（云端 v4 > 本地 9B；无 LLM 时白箱兜底质量有限）
- 角色深度：本地 Ollama 扮演深度低于云端
- 部分开放问题白箱兜底（情感/闲聊）可能不够「开放」（如「创业点子」白箱给通用建议）

## 五、结论

- **白箱最大化生效**：知识域 100% 白箱处理，开放域 50% 白箱兜底——83.3% 请求零 LLM
- **上下文控制生效**：记忆过滤+预算让 LLM 请求省 60%+（多轮长对话收益更大）
- **白箱与 LLM 的分工边界清晰**：确定性知识白箱（物理基底裁决），开放性生成 LLM（质量优先）——各取所长
- 关键权衡：白箱率高 = 成本低 + 确定性强，但开放质量依赖 LLM/本地模型——需按场景配比
