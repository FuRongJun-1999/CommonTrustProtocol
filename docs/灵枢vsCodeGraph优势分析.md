# 灵枢的图 vs CodeGraph：独特优势与分工（2026-08-17）

> 背景：爸爸提出代码类知识可从 codegraph 开源项目获取能力。我们曾把它的
> 四件套（影响面/因果链/关联测试/热路径）知识卡化。本文思考：我们自己的图
> vs CodeGraph，独特优势在哪、如何分工。

## 一、CodeGraph 是什么（开源 · 事实）

- **语法事实层**：tree-sitter 解析 38 语言 → 语义图（函数/类/导入/调用链）
- 42 MCP 工具 + VS Code 扩展 + JetBrains 插件 + 持久记忆层
- 强项：代码结构精确、语言覆盖广、工具生态成熟
- **本质**：报告「代码里有什么」——函数存在、谁调用谁、依赖关系（事实）

## 二、我们的图是什么（灵枢/智慧之书）

- **条件知识层**：现象规律性的条件化知识（在什么条件下成立）+ 翻译体系
  + 神经检索 + 白箱校验 + 信息分层 + 自生长闭环
- 卡带条件空间声明（观察位置/工具/时间窗/存在约束）+ 克制条款（counters）
- **本质**：断言「知识在什么条件下成立、克制什么」+ 持续校准

## 三、独特优势（我们 vs CodeGraph）

| 维度 | CodeGraph（开源） | 灵枢/智慧之书（我们） |
|---|---|---|
| **图的内容** | 语法关系（import/call/dep）| 条件化知识（现象规律+条件空间+克制）|
| **边** | 结构边（谁引用谁）| 因果边+条件标注（依赖型/非严格时间）|
| **查询** | 精确符号（函数名/类型）| 日常话翻译（「为什么这段代码慢」→ 规范词）|
| **诚实边界** | 报告事实，不标边界 | 三态标注（锚定/图谱外/警告）+ meta_note |
| **校准** | 静态索引（不校验）| 物理基底测试执行 + 结构排斥 + 外部校准者 |
| **生长** | 只索引 | LLM 写卡→card_validator→终裁（自生长）|
| **范围** | 代码库 | 全领域（学科/生活/协议/代码）|

**一句话**：CodeGraph 是**显微镜**（看清代码结构的事实），我们是**教科书**
（条件化知识 + 校准闭环）。显微镜擅长看，教科书擅长教——不竞争，是分工。

## 四、独特优势的本质：三层校准能力（CodeGraph 没有的）

1. **条件空间**：每条知识声明「在什么条件下成立」——codegraph 的
   import/call 边没有条件，我们断言「这个模式在并发场景下成立、在单线程
   场景克制」
2. **诚实边界**：区分「图谱锚定/图谱外/警告」——codegraph 报事实不标
   自己不知道什么；我们显式声明（0.0.3 局部不可知）
3. **物理基底校准**（爸爸的外部参照）：代码类知识的测试用例实际运行
   （编译/运行时报错=基底裁决）——codegraph 只解析不执行，我们接入执行

## 五、分工与接入（如何用 CodeGraph）

**不复制 CodeGraph**（它 38 语言/tree-sitter 做得更好），**消费它作为
物理基底校准源**：

```
代码类知识卡（我们）
   ↓ 测试用例「代码结构事实」
CodeGraph MCP（开源）→ 解析代码 → 结构事实（函数存在/调用关系）
   ↓ 事实返回
我们的卡校验器 → 断言 vs 事实 → 锚定/偏差
   ↓
物理信息基底裁决（代码实际运行/结构实际存在）
```

- CodeGraph = 代码侧的「显微镜」：提供结构事实（物理基底的一部分）
- 我们 = 条件知识层：把结构事实转化为条件化知识卡（在什么条件下成立）
- 四件套已知识卡化（dex_impact/dex_chain/dex_verify/hot_paths）——
  这是「结构借鉴」已完成；「基底接入」（消费 codegraph MCP 做测试执行）
  是下一步

## 六、结论

独特优势不在「图的规模」（codegraph 38 语言碾压），在**图的性质**：
- 它是语法图（结构事实），我们是条件图（知识+校准）
- 它回答「代码里有什么」，我们回答「知识在什么条件下成立、如何验证」
- 它静态，我们动态（校准/生长）

**分工正解**：codegraph 提供代码事实（显微镜），我们提供条件知识+校准
（教科书），测试用例执行器消费 codegraph MCP——物理基底校准的代码侧实现。
