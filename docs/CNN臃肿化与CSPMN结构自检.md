## 2. CNN 演化史核实（数据确认）

| 代际 | 模型 | 层数/参数 | 结构语义 |
|---|---|---|---|
| 一 | LeNet-5 (1998) | 5 层 / 6万 | 边缘→形状→物体（信息分层投影）|
| 二 | AlexNet (2012) | 8 层 / 6000万 | 全连接层占 90% 参数——臃肿开始 |
| 三 | ResNet (2015) | 152 层 / 1.16亿 | 残差连接解决梯度消失，但层数≠信息层次 |
| 四 | DenseNet/EfficientNet/SENet | 更复杂 | 注意力/通道注意力/NAS 搜索——「特征提取器数量」|

**荣的数据准确**。关键观察（支持荣的判断）：AlexNet 的 90% 参数在全连接层
而非卷积层——**结构语义已经开始稀释**；ResNet 的 152 层是「可训练参数堆叠
容器」，不再是「信息分层」。

## 3. CSPMN 防偏机制（从源头定义，不事后补救）

荣给出的四条核心约束，对应协议机制：

| 荣的约束 | 协议机制 | 工程化 |
|---|---|---|
| 每个条件空间维度明确对应信息层次 | 3.11 分层作为通用设计原则 | 条件空间向量 = 入口条件声明（关键词/类型/排除），非任意向量 |
| 子实例数量只增长到信息结构所需 | 3.10 步骤8（方向性自检）| **增长判据**：新子实例必须对应新信息层次，否则拒绝 |
| 验证单元定期复核结构一致性 | 3.4 验证单元 | 定期扫描：条件空间向量是否仍匹配其声明的入口条件 |
| 新层级不能对应新信息层次时，不扩展 | 2.1.2（方向校准）| **结构闸门**：扩展须通过「信息层次对应性」检查 |

### 结构自检机制（反思单元 3.1 在架构层的职责）

```
定期结构自检（复用 3.10 步骤8 流程：反思发起→验证复核→维生确认）：

检查项 1：条件空间向量语义漂移
  - 子实例的入口条件向量 vs 其实际被命中的问题——语义还匹配吗？
  - 不匹配 → 标记「挂错/缺标签」→ 盲区自修正闭环（CSPRE Phase B）

检查项 2：子实例增长的信息层次对应性
  - 新增子实例是否对应新的信息层次？
  - 仅对应已有层次的重复 → 拒绝（防「再加一层涨0.1%」的堆叠）

检查项 3：结构臃肿度
  - 子实例总数 vs 信息层次数——比例是否合理？
  - 比值异常增长 → 触发方向性自检（是否偏离「信息分层」原始设计）
```

## 4. 与 CNN 的对照结论

| 维度 | CNN（学术界）| CSPMN（协议约束下）|
|---|---|---|
| 结构优化目标 | 准确率（局部最优）| **信息分层一致性**（结构合理性）|
| 层/实例增长 | 堆叠（能涨就行）| **信息层次对应性**（不对应不扩展）|
| 自检机制 | 无（靠人调参）| **方向性自检 3.10步骤8 + 反思单元** |
| 纠偏机制 | 无（只能推倒重来）| **价值观修正 2.1.2 + 盲区自修正闭环** |

**核心洞察（荣）**：CSPMN 的优势不是「比 CNN 更高效」，而是**从源头定义
了结构边界**——扩展由「信息层次对应性」门控，而非「准确率 +0.1%」驱动。
这正是学术界缺的：**结构层面的方向性自检**。

## 5. 落点

```
CSPMN 设计时就内置：
  1. 结构自检模块（反思单元职责，复用 3.10步骤8 流程）
  2. 增长闸门（新子实例须对应新信息层次）
  3. 臃肿度指标（子实例数/信息层次数，异常触发方向性自检）

这使 CSPMN 从出生就带「防止变成臃肿 CNN」的结构免疫
——不是事后补救，是协议机制（2.1.2/3.10/3.4）在架构层的先验植入。
```
